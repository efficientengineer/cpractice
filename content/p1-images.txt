## Why start here

Every procedural texture, heightmap, noise field and render target in the rest of this course is the same thing: a rectangle of numbers in one block of memory. Before noise or 3D, you build the tool that holds and shows them. This chapter is one project, a small image library, grown in ten steps. Chapters on vector math, noise and textures start from its finished code.

C has no canvas. Your programs here *print an image*: the site draws any output that starts with a PNM header as a picture. Keep run images at most 128×128; the tests never look at printed pictures, they call your functions and check pixel values.

## One allocation, flat, row-major

An image is width × height pixels. Store them in **one contiguous array**, row after row:

```text
index(x, y) = y * w + x          pixel (0,0) is top left, x grows right, y grows down
```

```c
typedef struct { float r, g, b; } Color;              // linear light, 0..1
typedef struct { int w, h; Color *px; } Image;         // px has w*h entries
```

`Color` is three floats, so `px` is also a flat `float` buffer `r g b r g b ...` of `3*w*h` values; you can hand `(float *)im.px` to anything that wants floats.

What not to do, and why:

| Layout | Problem |
|---|---|
| `Color **rows`, one `malloc` per row | h+1 allocations, rows scattered in memory, two dependent loads per pixel, can't `memcpy` or upload the image in one go |
| `Color *pixel[w*h]`, one `malloc` per pixel | catastrophic: millions of allocations, 16+ bytes of overhead each, no locality |
| `int` index `y*w+x` on huge images | `w*h*3` overflows `int` past ~27k×27k; compute offsets in `size_t` |

> **Performance:** walk images in memory order, `y` in the outer loop and `x` in the inner one. A row of a 1024-wide float RGB image is 12 KB; going down a column touches a new cache line for every pixel. Swapping the loops on a large image costs several times the run time with identical results.

Allocate once, at the size you need, and **reuse**: a blur needs a scratch image, a renderer needs a depth buffer. Create them once, pass them in, never `malloc` inside a per-pixel or per-frame loop.

## Writing PNM

PNM is the simplest image format there is: a text header and then numbers. `P2` is grayscale, `P3` is color:

```text
P3
3 2
255
255 0 0  0 255 0  0 0 255
255 255 0  255 255 255  0 0 0
```

`3 2` is width and height, `255` the maximum value. Here is a complete program that fills an image with a UV gradient (red follows x, green follows y) and prints it:

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct { float r, g, b; } Color;
typedef struct { int w, h; Color *px; } Image;

int main(void) {
    Image im = { 96, 64, calloc(96 * 64, sizeof(Color)) };
    if (!im.px) return 1;
    for (int y = 0; y < im.h; y++)
        for (int x = 0; x < im.w; x++) {
            Color *p = &im.px[(size_t)y * im.w + x];
            p->r = (x + 0.5f) / im.w;          // sample at the pixel center
            p->g = (y + 0.5f) / im.h;
            p->b = 0.2f;
        }
    printf("P3\n%d %d\n255\n", im.w, im.h);
    for (size_t i = 0; i < (size_t)im.w * im.h; i++)
        printf("%d %d %d\n", (int)(im.px[i].r * 255 + 0.5f), (int)(im.px[i].g * 255 + 0.5f),
               (int)(im.px[i].b * 255 + 0.5f));
    free(im.px);
    return 0;
}
```

`(x + 0.5f) / w` samples the **pixel center**. Using `x / w` shifts everything half a pixel and makes the last column never reach 1. Pixel centers at half-integers is the convention every rasterizer and GPU uses; you'll meet it again with triangles.

## Two ways to hold a color

| | `Color` (3 floats, 0..1) | packed `uint32_t` `0xAARRGGBB` |
|---|---|---|
| Size | 12 bytes | 4 bytes |
| Math (blend, blur, light) | direct, no precision loss, values above 1 allowed (HDR) | unpack, compute, repack, rounding at each step |
| Use for | everything you compute | storage, files, GPU upload, framebuffers |

Work in floats; convert to bytes **once**, at the very end. Converting a float to a byte needs a clamp (values outside 0..1 are normal after lighting or bloom) and rounding:

```c
uint8_t to_byte(float v) {
    if (!(v > 0.0f)) return 0;          // also catches NaN, which fails every comparison
    if (v >= 1.0f) return 255;
    return (uint8_t)(v * 255.0f + 0.5f);
}
```

Converting an out-of-range float straight to an integer type (`(uint8_t)(1.7f * 255)`) is undefined behavior, not a wrap-around. Clamp first.

Packing is shifts and ors:

```c
uint32_t pack = 0xFF000000u | (uint32_t)r8 << 16 | (uint32_t)g8 << 8 | b8;
uint8_t green = (pack >> 8) & 0xFF;
```

## Gamma: the bug in almost every first renderer

Monitors don't show byte value 128 as half the light of 255; they show about 22%. Image bytes are stored in **sRGB**, a nonlinear encoding that spends more of the 256 codes on dark tones, where eyes are sensitive. Light, on the other hand, adds linearly: two lamps give twice the photons. So:

- **Compute in linear light** (blending, blurring, lighting, averaging, anti-aliasing).
- **Encode to sRGB once, when writing bytes**; decode sRGB inputs (textures, color pickers) when reading them.

The exact sRGB transfer functions (IEC 61966-2-1) have a short linear toe:

```text
encode(l) = 12.92 l                      if l <= 0.0031308
            1.055 l^(1/2.4) - 0.055      otherwise
decode(s) = s / 12.92                    if s <= 0.04045
            ((s + 0.055) / 1.055)^2.4    otherwise
```

Linear 0.5 encodes to 0.7354, byte 188. The test below makes it visible: the top band is a fine black/white checkerboard, which from a distance is exactly 50% of the light. The middle band is linear 0.5 encoded properly (188) and matches it; the bottom band is the naive byte 128 and is visibly too dark.

```c
#include <math.h>
#include <stdio.h>

static float srgb_encode(float l) {
    return l <= 0.0031308f ? 12.92f * l : 1.055f * powf(l, 1.0f / 2.4f) - 0.055f;
}

int main(void) {
    int w = 96, h = 72;
    printf("P2\n%d %d\n255\n", w, h);
    for (int y = 0; y < h; y++) {
        for (int x = 0; x < w; x++) {
            int v;
            if (y < 24) v = ((x + y) & 1) ? 255 : 0;                    // 50% light, dithered
            else if (y < 48) v = (int)(srgb_encode(0.5f) * 255 + 0.5f);  // 188
            else v = 128;                                               // "half" the naive way
            printf("%d ", v);
        }
        printf("\n");
    }
    return 0;
}
```

(Zoom your browser to 100% for a fair comparison: a scaled checkerboard is resampled.) Gradients look different too: a linear ramp encoded to sRGB spends most of its width in light tones. For *designed* color ramps (palettes picked by an artist), interpolating in sRGB is sometimes what the artist wanted; for anything physical, use linear.

> **Performance:** `powf` per channel per pixel is the most expensive thing in a simple image writer. A 4096-entry lookup table from linear value to sRGB byte (index `v * 4095`) gives the same bytes for all practical purposes and costs one load. Precomputed tables for expensive pure functions of one small input are one of the oldest graphics tricks; you'll use them again for permutation tables in noise.

## Drawing shapes: only touch what can change

A filled disk of radius `r` at `(cx, cy)` covers pixel `(x, y)` when the pixel's *center* is inside: `(x+0.5-cx)² + (y+0.5-cy)² <= r²`. The beginner's loop tests every pixel of the image for every disk. A 3-pixel spark on a 1024×1024 image then costs a million tests. Loop over the disk's **bounding box, clipped to the image**, instead: the work becomes proportional to the disk's area.

```text
x0 = max(0, floor(cx - r))      x1 = min(w - 1, floor(cx + r))
y0 = max(0, floor(cy - r))      y1 = min(h - 1, floor(cy + r))
```

Clipping the box also makes out-of-range writes impossible, so the inner loop needs no bounds check. Compare squared distances; there is no need for `sqrtf` to decide inside or outside.

### Lines: Bresenham

Bresenham's algorithm (1962, for a pen plotter at IBM) draws a line with integer additions only. It steps one pixel along the major axis each iteration and keeps an *error term* that says when to step along the minor axis. Jack Bresenham's version handles one octant; this form (Alois Zingl's) handles all eight with one loop:

```c
int dx = abs(x1 - x0), sx = x0 < x1 ? 1 : -1;
int dy = -abs(y1 - y0), sy = y0 < y1 ? 1 : -1;
int err = dx + dy;
for (;;) {
    put_pixel(im, x0, y0, c);
    if (x0 == x1 && y0 == y1) break;
    int e2 = 2 * err;
    if (e2 >= dy) { err += dy; x0 += sx; }   // step in x
    if (e2 <= dx) { err += dx; y0 += sy; }   // step in y
}
```

A line from `(0,0)` to `(20,7)` sets exactly 21 pixels, one per column, each the nearest to the ideal line. The float version (`y = y0 + t * slope`, rounded) gets the same picture with a float multiply and a rounding per pixel, and gaps when written carelessly (stepping along the minor axis).

### Anti-aliasing by coverage

A hard disk has jagged edges because each pixel is all in or all out. The fix is **coverage**: how much of the pixel's square the shape covers, used as an opacity. For a disk, the signed distance from the pixel center to the edge, `d - r`, approximates it well:

```text
coverage = clamp(r + 0.5 - d, 0, 1)        d = distance from the pixel center to the disk center
```

Pixels whose center is half a pixel inside get full coverage, half a pixel outside get none, and in between it ramps linearly. This "distance to edge → coverage" idea is how signed distance fields render text and shapes, and it carries straight into shaders. A ring is the same with `|d - radius|` against half the thickness.

```c
#include <math.h>
#include <stdio.h>

int main(void) {
    int w = 64, h = 64;
    float cx = 32, cy = 32, r = 20;
    printf("P2\n%d %d\n255\n", w, h);
    for (int y = 0; y < h; y++) {
        for (int x = 0; x < w; x++) {
            float dx = x + 0.5f - cx, dy = y + 0.5f - cy, d = sqrtf(dx * dx + dy * dy);
            float hard = d <= r ? 1.0f : 0.0f;
            float soft = fminf(fmaxf(r + 0.5f - d, 0.0f), 1.0f);
            float v = x < 32 ? hard : soft;             // left half aliased, right half smooth
            float s = v <= 0.0031308f ? 12.92f * v : 1.055f * powf(v, 1 / 2.4f) - 0.055f;
            printf("%d ", (int)(s * 255 + 0.5f));
        }
        printf("\n");
    }
    return 0;
}
```

Notice that the coverage is encoded to sRGB on output. Coverage is a fraction of light, so it is linear; writing it raw makes anti-aliased edges look thin and ropey.

## Compositing

Drawing with opacity `a` over what is there is a linear interpolation:

```text
out = dst + (src - dst) * a          ("over" with straight alpha)
```

Additive blending (`out = dst + src * k`) is for light: glows, sparks, fire. It never darkens and order doesn't matter.

When the destination itself has alpha (layers, sprites, textures you will composite later), use **premultiplied alpha**: store `(r*a, g*a, b*a, a)`. Then "over" is

```text
out = src + dst * (1 - src.a)        for all four channels
```

which is associative (you can pre-merge layers), works for additive light (`a = 0` with nonzero color), and, importantly, filters correctly: blurring or downsampling a straight-alpha image bleeds the color of fully transparent pixels into the edges (the dark halo around badly resized sprites). Porter and Duff's 1984 paper "Compositing Digital Images" is the source of all of this.

## Gradients and palettes

Most procedural textures compute one number `t` per pixel (a noise value, a distance, a height) and then **map it to a color**. The tools:

- `lerp(a, b, t) = a + (b - a) t`
- `smoothstep(e0, e1, x)`: clamp `t = (x - e0)/(e1 - e0)` to 0..1, then `t*t*(3 - 2t)`. A soft threshold with zero slope at both ends.
- **Multi-stop ramps**: sorted `(position, color)` stops, find the segment containing `t`, lerp inside it. Terrain colors (water, sand, grass, rock, snow) are a ramp over height.
- **Cosine palettes** (Inigo Quilez, "palettes"): `color(t) = a + b * cos(2π (c t + d))` per channel, with four `Color` parameters. Four vectors give an endless family of smooth palettes and cost one `cosf` per channel.

```c
#include <math.h>
#include <stdio.h>

typedef struct { float r, g, b; } Color;

static Color cosine_palette(float t, Color a, Color b, Color c, Color d) {
    const float tau = 6.2831853f;
    return (Color){ a.r + b.r * cosf(tau * (c.r * t + d.r)),
                    a.g + b.g * cosf(tau * (c.g * t + d.g)),
                    a.b + b.b * cosf(tau * (c.b * t + d.b)) };
}
static int byte(float v) { return v <= 0 ? 0 : v >= 1 ? 255 : (int)(v * 255 + 0.5f); }

int main(void) {
    Color a = {0.5f, 0.5f, 0.5f}, b = {0.5f, 0.5f, 0.5f};
    Color cs[4] = {{1, 1, 1}, {1, 1, 1}, {1, 1, 0.5f}, {2, 1, 0}};
    Color ds[4] = {{0, 0.33f, 0.67f}, {0, 0.1f, 0.2f}, {0.8f, 0.9f, 0.3f}, {0.5f, 0.2f, 0.25f}};
    int w = 128, h = 64;
    printf("P3\n%d %d\n255\n", w, h);
    for (int y = 0; y < h; y++)
        for (int x = 0; x < w; x++) {
            Color c = cosine_palette((x + 0.5f) / w, a, b, cs[y / 16], ds[y / 16]);
            printf("%d %d %d\n", byte(c.r), byte(c.g), byte(c.b));
        }
    return 0;
}
```

> **Performance:** a ramp with many stops costs a search per pixel. Bake it once into a 256- or 1024-entry table and index it with `t`: the same trick as the sRGB table. For a handful of stops a linear scan is fine; measure before you bother.

## Blur: from O(r²) to O(1) per pixel

A box blur replaces each pixel with the mean of the `(2r+1)×(2r+1)` square around it. Done directly, that's `(2r+1)²` reads per pixel: radius 30 is 3721 reads, so a 1024² image needs almost 4 billion. Two observations fix it:

1. **Separability.** A box filter is a horizontal box followed by a vertical box. Two 1D passes cost `2(2r+1)` per pixel instead of `(2r+1)²`. You need a scratch image between the passes.
2. **Sliding window.** In one row, the window for `x+1` is the window for `x` with one pixel added on the right and one dropped on the left. Keep a running sum: each output costs two additions **no matter how big `r` is**.

```text
sum = px[-r] + ... + px[r]           (with the edge pixels repeated for indices outside the row)
for x = 0 .. w-1:
    out[x] = sum / (2r + 1)
    sum += px[clamp(x + r + 1)] - px[clamp(x - r)]
```

At the borders, indices are **clamped** to the image (the edge pixel repeats), so every output is still a mean of exactly `2r+1` samples. Three box blurs in a row are very close to a Gaussian blur (the central limit theorem at work), which is how fast "Gaussian" blurs and bloom are built in practice.

> **Performance:** this is the chapter's main lesson in *algorithmic* cost. No compiler flag turns `O(r²)` into `O(1)`; changing what you compute does. Blur, summed-area tables, prefix sums and running windows reappear in terrain smoothing, ambient occlusion and erosion.

typedef struct { float r, g, b; } Color;     // linear light, normally 0..1

Write:

=== exercise img_ppm
title: Images, step 2: bytes, packing and PPM
continues: img_new
--- prompt
Add output. All three functions convert *once*, at the edge of the program; everything inside stays float.

- `uint8_t to_byte(float v)`: clamp `v` to `0..1`, then `v * 255` rounded to nearest. NaN gives 0. (Write the lower clamp as `if (!(v > 0.0f)) return 0;`: a NaN fails every comparison, so this form catches it.) Never cast an out-of-range float straight to an integer type: that is undefined behavior, and UBSan here will say so.
- `uint32_t pack_rgb(Color c)`: `0xAARRGGBB` with alpha `0xFF`, each channel through `to_byte`.
- `Color unpack_rgb(uint32_t p)`: the reverse, each channel byte divided by `255.0f` (alpha ignored).
- `void image_write_ppm(const Image *im, FILE *f)`: a `P3` file: the header `P3\n<w> <h>\n255\n`, then **one line per image row**, each pixel as three numbers, all numbers on the row separated by single spaces, no trailing space. A 2×1 image of red and blue is

```text
P3
2 1
255
255 0 0 0 0 255
```

The tests write into a `tmpfile()` and read it back. From now on, the `main` used by **Run** calls `image_write_ppm(&im, stdout)`.

Color *image_at(Image *im, int x, int y) {

void image_fill(Image *im, Color c) {

uint8_t to_byte(float v) {
    if (!(v > 0.0f)) return 0;
    if (v >= 1.0f) return 255;
    return (uint8_t)(v * 255.0f + 0.5f);

=== exercise img_srgb
title: Images, step 3: sRGB and a lookup table
continues: img_ppm
--- prompt
Your pixels hold *linear* light. Bytes in image files are *sRGB*. Add the exact transfer functions (clamp the input to `0..1` first):

```text
srgb_encode(l) = 12.92 l                      if l <= 0.0031308
                 1.055 l^(1/2.4) - 0.055      otherwise
srgb_decode(s) = s / 12.92                    if s <= 0.04045
                 ((s + 0.055) / 1.055)^2.4    otherwise
```

- `float srgb_encode(float linear)`, `float srgb_decode(float srgb)`: use `powf`, float constants.
- `void srgb_lut_init(uint8_t lut[4096])`: `lut[i] = to_byte(srgb_encode(i / 4095.0f))`.
- `void image_write_ppm_srgb(const Image *im, FILE *f, const uint8_t lut[4096])`: the same text format as `image_write_ppm`, but each channel `v` becomes `lut[i]` with `i = (int)(v * 4095 + 0.5f)` after clamping `v` to `0..1` (NaN counts as 0).

The table is the point: `powf` for every channel of every pixel is the slowest part of writing an image. 4096 entries are fine enough that the byte almost never differs from the exact one, and cost 4 KB built once.

From here on, Run output goes through the sRGB writer, so what you see is what the light values mean.
--- solution

float srgb_encode(float l) {
    if (!(l > 0.0f)) return 0.0f;
    if (l >= 1.0f) return 1.0f;
    return l <= 0.0031308f ? 12.92f * l : 1.055f * powf(l, 1.0f / 2.4f) - 0.055f;
}

float srgb_decode(float s) {
    if (!(s > 0.0f)) return 0.0f;
    if (s >= 1.0f) return 1.0f;
    return s <= 0.04045f ? s / 12.92f : powf((s + 0.055f) / 1.055f, 2.4f);
}

}

    if (!(v > 0.0f)) return 0;
    if (v >= 1.0f) return 4095;
    return (int)(v * 4095.0f + 0.5f);
}

    }
}

=== exercise img_disk
title: Images, step 4: clipped disks
continues: img_srgb
--- prompt
Add two drawing functions.

- `void put_pixel(Image *im, int x, int y, Color c)`: set one pixel, **ignoring** coordinates outside the image. Lines and sprites that hang off the edge rely on it.
- `void draw_disk(Image *im, float cx, float cy, float r, Color c)`: fill every pixel whose **center** `(x + 0.5, y + 0.5)` is within distance `r` of `(cx, cy)` (`<=`, compared squared, no `sqrtf`).

`draw_disk` must loop only over the disk's bounding box clipped to the image:

```text
x0 = max(0, (int)floorf(cx - r))      x1 = min(w - 1, (int)floorf(cx + r))
```

and the same for `y`. The clipped box guarantees every write is in bounds, so the inner loop needs no `put_pixel` check. A disk entirely off the image does no work at all. You may assume `cx`, `cy` and `r` are within ±1,000,000, so the `(int)` conversions are safe.

The last test draws 100,000 small disks on a 1024×1024 image. Scanning the whole image per disk is 10¹¹ distance tests and times out; the bounding box makes it a few million.

Loop over the bounding box, which now extends half a pixel further (`cx - r - 0.5` to `cx + r + 0.5`; for the ring use `radius + thickness / 2` as the outer radius), clipped to the image.

> **Performance:** most pixels of a big disk are fully inside. Skip the `sqrtf` for them: with `d²` already computed, full coverage is `d² <= (r - 0.5)²` (when `r >= 0.5`), zero coverage is `d² >= (r + 0.5)²`, and only the one-pixel band in between needs the square root. Not required by the tests, but it's the kind of thinking that matters in per-pixel code.
--- solution

void draw_line(Image *im, int x0, int y0, int x1, int y1, Color c) {

void draw_disk_aa(Image *im, float cx, float cy, float r, Color c, float alpha) {
    float ro = r + 0.5f, ri = r - 0.5f;
    float ro2 = ro * ro, ri2 = ri > 0 ? ri * ri : -1.0f;
    int x0 = clampi((int)floorf(cx - ro), 0, im->w), x1 = clampi((int)floorf(cx + ro), -1, im->w - 1);
    int y0 = clampi((int)floorf(cy - ro), 0, im->h), y1 = clampi((int)floorf(cy + ro), -1, im->h - 1);
    for (int y = y0; y <= y1; y++) {
        float dy = y + 0.5f - cy;
        Color *row = im->px + (size_t)y * im->w;
        for (int x = x0; x <= x1; x++) {
            float dx = x + 0.5f - cx, d2 = dx * dx + dy * dy;

--- prompt
Procedural textures compute a number `t` per pixel and map it to a color. Add the mapping tools:

- `float lerpf(float a, float b, float t)`.
- `float smoothstepf(float e0, float e1, float x)`: `t = clamp((x - e0) / (e1 - e0), 0, 1)`, return `t * t * (3 - 2 * t)`.
- A color ramp. Put this type in your code:

```c
typedef struct { float pos; Color c; } Stop;
```

  `Color ramp_sample(const Stop *s, int n, float t)`: stops are sorted by `pos`. Below the first stop return the first color, above the last return the last. Otherwise find `i` with `s[i].pos <= t <= s[i+1].pos` and lerp between their colors. Two stops at the same position make a hard edge: don't divide by zero (take the later color).
- `void ramp_bake(const Stop *s, int n, Color *lut, int size)`: `lut[i] = ramp_sample(s, n, i / (float)(size - 1))`. Sample a baked ramp with one multiply and one load per pixel.
- `Color cosine_palette(float t, Color a, Color b, Color c, Color d)`: Quilez's palette, per channel `a + b * cosf(6.2831853f * (c * t + d))`.

The Run output shows a terrain-style ramp, its baked version and four cosine palettes.

title: Images, step 9: an O(1)-per-pixel box blur
continues: img_ramp
--- prompt
Add `void box_blur(Image *im, int r, Image *tmp)`: replace each pixel by the mean of the `(2r+1)×(2r+1)` square around it, with coordinates outside the image **clamped** to the nearest edge pixel (so each output is still a mean of exactly `(2r+1)²` samples, some repeated). `tmp` is a scratch image of the same size, supplied by the caller so that blurring every frame allocates nothing. `r = 0` leaves the image unchanged. `r` may be larger than the image.

Do it in two passes, each with a **sliding window**:

1. Horizontal: for each row, start `sum` with the window around `x = 0` (indices `-r..r`, clamped), then for each `x` write `sum / (2r+1)` to `tmp` and update `sum += row[clamp(x + r + 1)] - row[clamp(x - r)]`.
2. Vertical: the same down each column, from `tmp` back into `im`.

Each output pixel costs a constant amount of work regardless of `r`. The last test blurs a 1024×1024 image with radius 60: the direct 2D loop is 15 billion reads and times out; even two 1D passes that re-sum the window per pixel are much slower than they need to be.

Keep the three channel sums in `float`s (or `double`s if you prefer); the tests allow for the rounding drift a running sum accumulates.

/* One sliding-window pass over n samples spaced `stride` apart, from src into dst. */
static void blur_line(const Color *src, Color *dst, int n, size_t stride, int r) {
    float sr = 0, sg = 0, sb = 0, inv = 1.0f / (2 * r + 1);
    for (int k = -r; k <= r; k++) {
        const Color *p = src + (size_t)clampi(k, 0, n - 1) * stride;
        sr += p->r; sg += p->g; sb += p->b;
    }
    for (int i = 0; i < n; i++) {
        dst[(size_t)i * stride] = rgb(sr * inv, sg * inv, sb * inv);
        const Color *add = src + (size_t)clampi(i + r + 1, 0, n - 1) * stride;
        const Color *sub = src + (size_t)clampi(i - r, 0, n - 1) * stride;
        sr += add->r - sub->r; sg += add->g - sub->g; sb += add->b - sub->b;
    }
}

--- prompt
Finish the library with **bloom**, the glow around bright lights, built from what you have:

`void bloom(Image *im, float threshold, int r, int passes, float strength, Image *bright, Image *tmp)`

1. Bright pass: `bright` gets `max(c - threshold, 0)` for each channel of each pixel of `im`.
2. Blur `bright` `passes` times with `box_blur(bright, r, tmp)`. Three box passes approximate a Gaussian closely.
3. Add it back: each pixel of `im` becomes `blend_add(pixel, bright_pixel, strength)`.

`bright` and `tmp` are caller-owned scratch images the same size as `im`.

Bloom only works in linear light with values allowed above 1, which is why the library computes in floats and clamps only at output. Everything below the threshold is untouched, so a dark image comes out identical.

The Run program draws a neon scene, rings and lines in cosine-palette colors at intensities above 1, and blooms it. Experiment with the threshold, radius and passes.

void draw_disk(Image *im, float cx, float cy, float r, Color c) {
    int x0 = clampi((int)floorf(cx - r), 0, im->w), x1 = clampi((int)floorf(cx + r), -1, im->w - 1);
    int y0 = clampi((int)floorf(cy - r), 0, im->h), y1 = clampi((int)floorf(cy + r), -1, im->h - 1);

void draw_line(Image *im, int x0, int y0, int x1, int y1, Color c) {
    int dx = abs(x1 - x0), sx = x0 < x1 ? 1 : -1;
    int dy = -abs(y1 - y0), sy = y0 < y1 ? 1 : -1;
    int err = dx + dy;
    for (;;) {
        put_pixel(im, x0, y0, c);
        if (x0 == x1 && y0 == y1) break;

void draw_disk_aa(Image *im, float cx, float cy, float r, Color c, float alpha) {
    float ro = r + 0.5f, ri = r - 0.5f;
    float ro2 = ro * ro, ri2 = ri > 0 ? ri * ri : -1.0f;
    int x0 = clampi((int)floorf(cx - ro), 0, im->w), x1 = clampi((int)floorf(cx + ro), -1, im->w - 1);
    int y0 = clampi((int)floorf(cy - ro), 0, im->h), y1 = clampi((int)floorf(cy + ro), -1, im->h - 1);
    for (int y = y0; y <= y1; y++) {
        float dy = y + 0.5f - cy;
        Color *row = im->px + (size_t)y * im->w;
        for (int x = x0; x <= x1; x++) {
            float dx = x + 0.5f - cx, d2 = dx * dx + dy * dy;
            if (d2 >= ro2) continue;
            float cov = d2 <= ri2 ? 1.0f : clampf(ro - sqrtf(d2), 0.0f, 1.0f);
            row[x] = blend_over(row[x], c, cov * alpha);
        }
    }
}

void draw_ring_aa(Image *im, float cx, float cy, float radius, float thickness, Color c, float alpha) {
    float ro = radius + thickness * 0.5f + 0.5f, half = thickness * 0.5f + 0.5f;
    int x0 = clampi((int)floorf(cx - ro), 0, im->w), x1 = clampi((int)floorf(cx + ro), -1, im->w - 1);
    int y0 = clampi((int)floorf(cy - ro), 0, im->h), y1 = clampi((int)floorf(cy + ro), -1, im->h - 1);
    for (int y = y0; y <= y1; y++) {
        float dy = y + 0.5f - cy;
        Color *row = im->px + (size_t)y * im->w;
        for (int x = x0; x <= x1; x++) {
            float dx = x + 0.5f - cx;
            float cov = clampf(half - fabsf(sqrtf(dx * dx + dy * dy) - radius), 0.0f, 1.0f);
            if (cov > 0.0f) row[x] = blend_over(row[x], c, cov * alpha);
        }
    }
}

typedef struct { float pos; Color c; } Stop;

float lerpf(float a, float b, float t) {
    return a + (b - a) * t;
}

float smoothstepf(float e0, float e1, float x) {
    float t = clampf((x - e0) / (e1 - e0), 0.0f, 1.0f);
    return t * t * (3.0f - 2.0f * t);
}

Color ramp_sample(const Stop *s, int n, float t) {
    if (t <= s[0].pos) return s[0].c;
    if (t >= s[n - 1].pos) return s[n - 1].c;
    int i = 0;
    while (i < n - 2 && t > s[i + 1].pos) i++;
    float span = s[i + 1].pos - s[i].pos;
    if (span <= 0.0f) return s[i + 1].c;
    return color_lerp(s[i].c, s[i + 1].c, (t - s[i].pos) / span);
}

void ramp_bake(const Stop *s, int n, Color *lut, int size) {
    for (int i = 0; i < size; i++) lut[i] = ramp_sample(s, n, i / (float)(size - 1));
}

Color cosine_palette(float t, Color a, Color b, Color c, Color d) {
    const float tau = 6.2831853f;
    return rgb(a.r + b.r * cosf(tau * (c.r * t + d.r)), a.g + b.g * cosf(tau * (c.g * t + d.g)),
               a.b + b.b * cosf(tau * (c.b * t + d.b)));
}

static inline Color color_scale(Color c, float k) { return rgb(c.r * k, c.g * k, c.b * k); }

/* One sliding-window pass over n samples spaced `stride` apart, from src into dst. */
static void blur_line(const Color *src, Color *dst, int n, size_t stride, int r) {
    float sr = 0, sg = 0, sb = 0, inv = 1.0f / (2 * r + 1);
    for (int k = -r; k <= r; k++) {
        const Color *p = src + (size_t)clampi(k, 0, n - 1) * stride;
        sr += p->r; sg += p->g; sb += p->b;
    }
    for (int i = 0; i < n; i++) {
        dst[(size_t)i * stride] = rgb(sr * inv, sg * inv, sb * inv);
        const Color *add = src + (size_t)clampi(i + r + 1, 0, n - 1) * stride;
        const Color *sub = src + (size_t)clampi(i - r, 0, n - 1) * stride;
        sr += add->r - sub->r; sg += add->g - sub->g; sb += add->b - sub->b;
    }
}

void box_blur(Image *im, int r, Image *tmp) {
    if (r <= 0) return;
    for (int y = 0; y < im->h; y++)
        blur_line(im->px + (size_t)y * im->w, tmp->px + (size_t)y * im->w, im->w, 1, r);
    for (int x = 0; x < im->w; x++)
        blur_line(tmp->px + x, im->px + x, im->h, (size_t)im->w, r);
}

void bloom(Image *im, float threshold, int r, int passes, float strength, Image *bright, Image *tmp) {
    size_t n = (size_t)im->w * im->h;
    for (size_t i = 0; i < n; i++) {
        Color c = im->px[i];
        bright->px[i] = rgb(fmaxf(c.r - threshold, 0.0f), fmaxf(c.g - threshold, 0.0f), fmaxf(c.b - threshold, 0.0f));
    }
    for (int p = 0; p < passes; p++) box_blur(bright, r, tmp);
    for (size_t i = 0; i < n; i++) im->px[i] = blend_add(im->px[i], bright->px[i], strength);
}

Premultiplied images use more bits per channel.
--- choice
Premultiplied images are stored in sRGB, so filtering is perceptual.
--- answer
In premultiplied form a fully transparent pixel is `(0,0,0,0)` and contributes nothing to a filtered color; in straight alpha its (often black) RGB is averaged into neighboring visible pixels.
--- choice
Filtering skips pixels whose alpha is zero only in premultiplied form.
--- explain
Filtering a straight-alpha image averages colors that should have been weighted by their alpha. Premultiplying does the weighting up front, so plain averaging of all four channels is correct.
