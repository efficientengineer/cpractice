## Familiar syntax, fewer guard rails

C# took its operators and statements from C, so `if`, `while`, `for`, `switch`, `? :` and the arithmetic operators look the same. The differences are in what the compiler *lets through*. C# rejects `if (x = 5)` and `if (n)` for an `int n`, because conditions must be `bool`. C accepts both. Many C#-isms that are compile errors become silent bugs in C, so compile with `-Wall -Wextra` and treat warnings as errors in your head.

## Precedence, and where it bites

From tightest to loosest binding:

| Level | Operators | Associativity |
|---|---|---|
| 1 | `x()` `a[i]` `s.f` `p->f` `x++` `x--` | left to right |
| 2 | `++x` `--x` `+x` `-x` `!` `~` `*p` `&x` `(type)` `sizeof` | right to left |
| 3 | `*` `/` `%` | left to right |
| 4 | `+` `-` | left to right |
| 5 | `<<` `>>` | left to right |
| 6 | `<` `<=` `>` `>=` | left to right |
| 7 | `==` `!=` | left to right |
| 8 | `&` | left to right |
| 9 | `^` | left to right |
| 10 | `\|` | left to right |
| 11 | `&&` | left to right |
| 12 | `\|\|` | left to right |
| 13 | `? :` | right to left |
| 14 | `=` `+=` `-=` `*=` `/=` `%=` `<<=` `>>=` `&=` `^=` `\|=` | right to left |
| 15 | `,` | left to right |

The famous mistakes all come from levels 5 and 8-10 being in odd places (a historical accident: `&` and `|` once doubled as logical operators):

```c
#include <stdio.h>

int main(void) {
    int x = 4;
    if (x & 1 == 0) puts("even?");   // parsed as x & (1 == 0), i.e. x & 0: never true
    if ((x & 1) == 0) puts("even");  // what was meant
    printf("%d\n", 1 << 2 + 1);      // 8: parsed as 1 << (2 + 1)
    printf("%d\n", (1 << 2) + 1);    // 5
    int a = 5, b = 3, c = 1;
    printf("%d\n", a > b > c);       // 0: (5 > 3) is 1, then 1 > 1 is 0
    return 0;
}
```

In C# `x & 1 == 0` is a type error (`int & bool`), so you never learned this one. gcc's `-Wparentheses` (part of `-Wall`) warns about all three. The rule of thumb: **parenthesize whenever you mix bitwise operators, shifts, or comparisons**.

## Truth is an int

C has no boolean conditions. Any scalar works: zero (or a null pointer) is false, everything else is true. Comparison and logical operators produce an `int`, `0` or `1`.

```c
#include <stdio.h>
#include <stdbool.h>

int main(void) {
    int n = 42;
    if (n) puts("nonzero is true");
    printf("%d %d %d\n", 5 > 3, 5 < 3, !7);   // 1 0 0
    printf("%d\n", !!n);                       // 1: the normalize-to-0/1 idiom

    int big = 256;
    bool flag = big;             // any nonzero converts to exactly 1
    unsigned char byte = big;    // keeps the low 8 bits: 0
    printf("%d %d\n", flag, byte);             // 1 0

    const char *p = NULL;
    if (!p) puts("a null pointer is false");
    return 0;
}
```

C99 added `_Bool`, a 1-byte type that only holds 0 or 1. `<stdbool.h>` gives it the names `bool`, `true` and `false` (C23 makes them keywords). Use it for flags and predicate return types; it documents intent. But plenty of C code (including the standard library: `isdigit`, `strcmp`) still returns `int` and means "zero or not zero", so never write `if (isdigit(c) == true)`: `isdigit` may return 2048.

JavaScript habit to drop: `||` does not return an operand. `int port = cfg_port || 8080;` sets `port` to `1`. Write `cfg_port ? cfg_port : 8080`.

## = versus ==

`if (x = 0)` assigns 0 and tests it: always false, and `x` is now 0. It is legal C, because assignment is an expression whose value is the assigned value. gcc warns ("suggest parentheses around assignment used as truth value"). When you *do* mean it, the convention is to add parentheses and an explicit comparison, as in the most common loop in C:

```c
#include <stdio.h>

int main(void) {
    int c, lines = 0, chars = 0;
    while ((c = getchar()) != EOF) {   // assign, then compare
        chars++;
        if (c == '\n') lines++;
    }
    printf("%d lines, %d chars\n", lines, chars);
    return 0;
}
```

`c` must be an `int`, not a `char`: `getchar` returns every byte value 0..255 *plus* `EOF` (-1), 257 possibilities that do not fit in a `char`.

## Short-circuit and the ternary

`&&` and `||` evaluate left to right and stop as soon as the answer is known, exactly as in C# and JS. That makes guards like `if (p != NULL && p->count > 0)` and `if (d != 0 && n / d > 2)` safe. The bitwise `&` and `|` always evaluate both sides.

> **Performance:** short-circuiting is also a cheap filter. In a collision check, test the cheap condition that usually fails first: `if (e->alive && e->layer == layer && dist_sq(a, e) < r * r)`. Most entities are rejected by the first comparison, and the distance math only runs for the few that pass.

`cond ? a : b` evaluates only one of `a` and `b`. Both branches are converted to a common type, the usual arithmetic conversions again: `n > 0 ? 1 : 0.5` has type `double`. It nests right to left, so a chain reads like `else if`:

```c
#include <stdio.h>

const char *health_label(int hp, int max_hp) {
    return hp <= 0              ? "dead"
         : hp * 4 <= max_hp     ? "critical"
         : hp * 4 <= max_hp * 3 ? "hurt"
         :                        "healthy";
}

int main(void) {
    printf("%s %s %s %s\n", health_label(0, 100), health_label(20, 100),
           health_label(60, 100), health_label(90, 100));   // dead critical hurt healthy
    return 0;
}
```

## The comma operator

`a, b` evaluates `a`, throws its value away, then evaluates `b`; the result is `b`. Its only common use is packing two updates into a `for` header:

```c
#include <stdio.h>

int main(void) {
    char s[] = "stressed";
    int i, j;
    for (i = 0, j = 7; i < j; i++, j--) {   // comma operator, twice
        char t = s[i]; s[i] = s[j]; s[j] = t;
    }
    printf("%s\n", s);                      // desserts
    int x = (puts("side effect"), 42);      // x = 42
    printf("%d\n", x);
    return 0;
}
```

The commas separating function arguments and declarators (`int i, j;`) are *not* the comma operator, and do not guarantee left-to-right order.

## switch

`switch` works only on integer types (including `char` and `enum`). No strings, no patterns, no ranges (gcc has `case 1 ... 5:` as an extension). Case labels must be integer constant expressions. The big difference from C#: **control falls through** from one case into the next unless you `break`. C# makes implicit fallthrough a compile error; C makes it the default.

```c
#include <stdio.h>

const char *kind(int c) {
    switch (c) {
    case 'a': case 'e': case 'i': case 'o': case 'u':   // stacked labels share code
        return "vowel";
    case ' ':
    case '\t':
        return "space";
    default:
        if (c >= '0' && c <= '9') return "digit";
        return "other";
    }
}

int main(void) {
    const char *s = "hi 42";
    for (int i = 0; s[i] != '\0'; i++)
        printf("'%c' %s\n", s[i], kind(s[i]));
    return 0;
}
```

Deliberate fallthrough is occasionally neat. `-Wextra` enables `-Wimplicit-fallthrough`, which warns unless you mark it with a `/* fall through */` comment (or C23's `[[fallthrough]];`):

```c
#include <stdio.h>

int main(void) {
    for (int level = 0; level <= 3; level++) {
        printf("level %d:", level);
        switch (level) {
        case 3:
            printf(" debug");
            /* fall through */
        case 2:
            printf(" info");
            /* fall through */
        case 1:
            printf(" errors");
            break;
        default:
            printf(" nothing");
        }
        printf("\n");
    }
    return 0;
}
```

Two more rules: before C23 a label must be followed by a statement, so `case 1: int x = 5;` is an error; wrap the case body in braces `case 1: { int x = 5; ... break; }`. And `default` can go anywhere, but put it last.

> **Performance:** a `switch` over dense case values (0, 1, 2, ... like an enum) usually compiles to a *jump table*: one indexed jump, however many cases. Sparse values (1, 1000, 50000) become a chain or tree of comparisons. Either is cheap once. What costs is a `switch` on a value that changes unpredictably *per element in a hot loop*, such as switching on each entity's type while updating 10,000 mixed entities: the CPU cannot predict the jump and pays for a misprediction (around 15-20 cycles) again and again. Game engines often keep each kind of entity in its own array, so every loop body is one straight path. You will see that design in the structs chapter.

## Loops

`while`, `do ... while` and `for` behave as in C#. There is no `foreach`: you loop over indices or pointers. Since C99 you can declare the loop variable in the `for` header, scoped to the loop. `for (;;)` is the idiomatic infinite loop.

```c
#include <stdio.h>

int main(void) {
    int i = 10;
    while (i < 3) puts("never");
    do {
        printf("do-while runs at least once: %d\n", i);
    } while (i < 3);

    for (int a = 0, b = 10; a < b; a += 3, b -= 3)
        printf("%d %d\n", a, b);

    for (int row = 0; row < 10; row++) {
        if (row == 1) continue;   // skip to the next iteration (runs row++)
        if (row == 4) break;      // leave the innermost loop or switch
        printf("row %d\n", row);
    }
    return 0;
}
```

`break` inside a `switch` inside a loop leaves the `switch`, not the loop. There is no labeled `break` like Java's; to leave nested loops, use a flag, move the loops into a function and `return`, or use `goto`.

### Loops that run every frame

Two habits matter more than any micro-optimization in a loop that runs over every entity, every frame:

**Hoist work out of the loop.** Anything that does not change between iterations should be computed once before the loop. The compiler can do it for plain arithmetic, but not across a function call it cannot see into, and not at `-O0`:

```c
#include <stdio.h>

int main(void) {
    float x[4] = {0, 10, 20, 30};
    float speed = 120.0f, dt = 1.0f / 60, drag = 0.5f;

    // Slow habit: the same product computed on every iteration
    // for (int i = 0; i < n; i++) x[i] += speed * dt * (1.0f - drag * dt);

    float step = speed * dt * (1.0f - drag * dt);   // once, before the loop
    for (int i = 0; i < 4; i++)
        x[i] += step;
    printf("%.4f %.4f\n", x[0], x[3]);
    return 0;
}
```

**Keep branches predictable.** A modern CPU guesses which way each `if` goes and runs ahead speculatively. A branch that almost always goes the same way (`if (hp <= 0)` on mostly living enemies) is nearly free. A branch that is effectively random (50/50 on unsorted data) is mispredicted about half the time, and each miss throws away 15-20 cycles of work. For small decisions, a ternary that picks between two values (`v = v < lo ? lo : v;`) often compiles to a conditional move with no branch at all. Sorting or grouping data so that equal cases come together also makes branches predictable.

## goto

`goto label;` jumps to `label:` anywhere in the same function. Dijkstra was right that spaghetti `goto` is bad, but two uses are standard, idiomatic C, used all over the Linux kernel, SQLite and CPython:

```c
#include <stdio.h>

int main(void) {
    enum { FLOOR, WALL, DOOR };
    int map[3][4] = {
        {WALL, WALL, WALL, WALL},
        {WALL, FLOOR, FLOOR, DOOR},
        {WALL, WALL, WALL, WALL},
    };
    for (int y = 0; y < 3; y++)
        for (int x = 0; x < 4; x++)
            if (map[y][x] == DOOR) {
                printf("door at %d,%d\n", x, y);
                goto done;            // leave both loops at once
            }
    puts("no door");
done:
    return 0;
}
```

The second is **cleanup on error**. C has no `using`, `finally` or destructors. When a function acquires several resources and any step can fail, you jump forward to a single cleanup block instead of repeating `free`s in every error branch:

```c
#include <stdio.h>
#include <stdlib.h>

// Sum of i*i for i in 0..n-1, computed the long way with two scratch buffers.
// Returns -1 on failure.
long work(int n) {
    long result = -1;
    long *squares = NULL, *totals = NULL;

    if (n <= 0) goto cleanup;
    squares = malloc(n * sizeof *squares);
    if (squares == NULL) goto cleanup;
    totals = malloc(n * sizeof *totals);
    if (totals == NULL) goto cleanup;

    for (int i = 0; i < n; i++) {
        squares[i] = (long)i * i;
        totals[i] = squares[i] + (i > 0 ? totals[i - 1] : 0);
    }
    result = totals[n - 1];

cleanup:
    free(totals);     // free(NULL) does nothing, so this is safe on every path
    free(squares);
    return result;
}

int main(void) {
    printf("%ld %ld\n", work(4), work(0));   // 14 -1
    return 0;
}
```

Only jump *forward* and *out*, never into a block or backwards to emulate a loop.

## Bitwise versus logical

| Logical (on truth values) | Bitwise (on every bit) |
|---|---|
| `a && b`: 0 or 1, short-circuits | `a & b`: bit by bit AND, evaluates both |
| `a \|\| b`: 0 or 1, short-circuits | `a \| b`: bit by bit OR |
| `!a`: 0 or 1 | `~a`: flips every bit |
| | `a ^ b`: XOR; `a << n`, `a >> n`: shifts |

```c
#include <stdio.h>

int main(void) {
    int a = 6, b = 1;                     // binary 110 and 001
    printf("%d %d\n", a & b, a && b);     // 0 1
    printf("%d %d\n", a | b, a || b);     // 7 1
    printf("%d %d\n", ~a, !a);            // -7 0
    printf("%d\n", a ^ 3);                // 5: 110 ^ 011 = 101
    printf("%d %d\n", a << 2, a >> 1);    // 24 3

    enum { READ = 1, WRITE = 2, EXEC = 4 };
    int perms = READ | WRITE;
    if (perms & WRITE) puts("writable");
    if (!(perms & EXEC)) puts("not executable");
    return 0;
}
```

Shift `unsigned` values when you can. Left-shifting a negative number, or shifting by a negative count or by the width of the type or more, is undefined; right-shifting a negative number is implementation-defined (gcc does an arithmetic shift). The bits chapter goes deeper.

## Increment and sequencing

`i++` yields the old value, `++i` the new one; that part is the same as C#. The difference: C# and JavaScript guarantee left-to-right evaluation of everything. **C does not.** In `f() + g()` or `printf("%d %d", f(), g())`, either call may run first (the order is *unspecified*). And modifying a variable twice, or modifying it and also reading it for another purpose, without a *sequence point* in between is **undefined behavior**:

```c
#include <stdio.h>

int main(void) {
    int i = 5;
    int a = i++;          // a = 5, i = 6
    int b = ++i;          // i = 7, b = 7
    printf("%d %d %d\n", a, b, i);

    // All undefined behavior. gcc -Wall warns "operation on 'i' may be undefined":
    // i = i++ + 1;
    // arr[i] = i++;
    // printf("%d %d\n", i++, i++);

    int j = 0;
    int ok = (j++, j++, j);   // fine: the comma operator is a sequence point
    printf("%d\n", ok);       // 2
    return 0;
}
```

The sequence points you can rely on: the end of each full expression (`;`), after the left operand of `&&`, `||`, `?` and the comma operator, and before a function is called (after all its arguments are evaluated). The safe habit is boring: **one side effect per variable per statement**, and use `++` as a statement on its own line unless it is the standard `*p++` idiom.

bool is_leap(int year) {

=== exercise powtwo
title: Bits, not booleans
--- prompt
Write two functions using bitwise operators:

- `int popcount(unsigned x)`: the number of 1 bits in `x`.
- `int is_power_of_two(unsigned x)`: 1 if `x` is a power of two (1, 2, 4, ...), else 0. Do this in one expression with no loop.

Use the trick that `x & (x - 1)` clears the lowest set bit of `x`. (gcc has `__builtin_popcount`, but write it yourself here.)
--- starter
int popcount(unsigned x) {
    int count = 0;
    return count;
}

int is_power_of_two(unsigned x) {
    return 0;
}
--- solution
int popcount(unsigned x) {
    int count = 0;
    while (x) {
        x &= x - 1;
        count++;
    }
    return count;
}

int is_power_of_two(unsigned x) {
    return x != 0 && (x & (x - 1)) == 0;
}
--- harness
int main(void) {
    CHECK_INT(popcount(0), 0);
    CHECK_INT(popcount(1), 1);
    CHECK_INT(popcount(6), 2);
    CHECK_INT(popcount(255), 8);
    CHECK_INT(popcount(0xF0F0u), 8);
    CHECK_INT(popcount(0x80000000u), 1);
    CHECK_INT(popcount(0xFFFFFFFFu), 32);
    CHECK_INT(popcount(0xAAAAAAAAu), 16);
    CHECK_INT(is_power_of_two(0), 0);
    CHECK_INT(is_power_of_two(1), 1);
    CHECK_INT(is_power_of_two(2), 1);
    CHECK_INT(is_power_of_two(3), 0);
    CHECK_INT(is_power_of_two(64), 1);
    CHECK_INT(is_power_of_two(96), 0);
    CHECK_INT(is_power_of_two(0x80000000u), 1);
    CHECK_INT(is_power_of_two(0x80000001u), 0);
    CHECK_INT(is_power_of_two(0xFFFFFFFFu), 0);
    return TEST_END();
}
--- hint
`popcount`: each `x &= x - 1` removes exactly one 1 bit, so count how many times you can do it before `x` is 0.
--- hint
A power of two has exactly one bit set, so clearing its lowest set bit leaves 0. Mind the precedence: `(x & (x - 1)) == 0` needs the parentheses.
--- hint
Zero is not a power of two, but `0 & (0 - 1)` is 0. Guard it with `x != 0 &&`.

--- starter
#include <stdio.h>

int main(void) {

--- solution
#include <stdio.h>

int main(void) {
    int n;
    while (scanf("%d", &n) == 1) {
        if (n < 0) putchar('-');
        do {
            int d = n % 10;          // negative for negative n
            if (d < 0) d = -d;
            putchar('0' + d);
            n /= 10;
        } while (n != 0);
        putchar('\n');
    }
    return 0;
}
--- hint
`n % 10` is the last digit and `n / 10` drops it. Loop until `n` is 0, but run the body at least once.
--- hint
For negative `n`, `n % 10` is negative (`-45 % 10 == -5`) and `n / 10` truncates toward zero. So you never need to negate `n` itself, only each digit.

=== exercise primes
title: Primes up to n
--- prompt
Read one integer `n` and print every prime number from 2 to `n` inclusive on one line, separated by single spaces. If there are none (including for zero and negative `n`), print an empty line.

Use trial division: for each candidate `k`, try divisors `d` while `d * d <= k`; `break` out as soon as one divides, and `continue` to the next candidate.
--- starter
#include <stdio.h>

int main(void) {
    int n;
    if (scanf("%d", &n) != 1) return 1;
    for (int k = 2; k <= n; k++) {
        // test k
    }
    printf("\n");
    return 0;
}
--- solution
#include <stdio.h>

int main(void) {
    int n;
    if (scanf("%d", &n) != 1) return 1;
    int first = 1;
    for (int k = 2; k <= n; k++) {
        int prime = 1;
        for (int d = 2; d * d <= k; d++) {
            if (k % d == 0) {
                prime = 0;
                break;
            }
        }
        if (!prime) continue;
        if (!first) putchar(' ');
        printf("%d", k);
        first = 0;

=== exercise gridwalk
title: Walking on a grid
--- prompt
A character stands on a `W` by `H` grid of tiles, at column `x`, row `y` (row 0 is the top, so "up" decreases `y`). Read `W H x y` from stdin, then read the rest of the input one character at a time with `getchar` until `EOF`. Each character is a move:

- Anything else (spaces, newlines, other letters) is ignored.

A move that would leave the grid does not happen; count it as a **bump**. At the end print `x y bumps`.

For input `5 3 0 0` and moves `RRUDDDLL`: right twice to (2,0), up bumps, down twice to (2,2), down bumps, left twice to (0,2). Output `0 2 2`.

Use a `switch` with stacked `case` labels for the key mapping. This is the shape of real input handling: map raw keys to a direction once, then apply the direction with one bounds check.
--- starter
#include <stdio.h>

int main(void) {
    int w, h, x, y;
    if (scanf("%d %d %d %d", &w, &h, &x, &y) != 4) return 1;
    int bumps = 0;
    // read moves with getchar until EOF

--- solution
#include <stdio.h>

int main(void) {
    int w, h, x, y;
    if (scanf("%d %d %d %d", &w, &h, &x, &y) != 4) return 1;
    int bumps = 0, c;
    while ((c = getchar()) != EOF) {
        int dx = 0, dy = 0;
        switch (c) {
        case 'U': case 'u': dy = -1; break;
        case 'D': case 'd': dy = 1; break;
        case 'L': case 'l': dx = -1; break;
        case 'R': case 'r': dx = 1; break;
        default: continue;              // not a move: next character
        }
        int nx = x + dx, ny = y + dy;
        if (nx < 0 || nx >= w || ny < 0 || ny >= h) bumps++;
        else { x = nx; y = ny; }
    }
    printf("%d %d %d\n", x, y, bumps);
    return 0;
}
--- hint

--- hint

    if (roll == 1) return HIT_MISS;

int turns_to_kill(int hp, int damage, int attack, int defense, unsigned seed) {
    for (int turn = 1; turn <= 1000; turn++) {
        seed = seed * 1103515245u + 12345u;

title: Count spawns without simulating
--- prompt
An enemy spawner fires on tick `offset`, then every `period` ticks after that (`offset`, `offset + period`, `offset + 2 * period`, ...). Write `long long spawns_between(long long t0, long long t1, long long period, long long offset)`: how many spawn ticks `t` satisfy `t0 <= t < t1`?

The loop `for (t = t0; t < t1; t++) if (...) count++;` is correct, and on a range of 10^18 ticks it would run for decades. Some tests use ranges like that. Count with arithmetic instead: write a helper "how many spawns happen before tick `T`" (none if `T <= offset`, otherwise `(T - offset - 1) / period + 1`), and subtract.

> **Performance:** a game that fast-forwards (an idle game catching up on the hours you were away, a server replaying a long fight, an AI predicting when a timer fires) must not step tick by tick when a closed form exists. Simulate only what actually interacts.
--- starter
long long spawns_between(long long t0, long long t1, long long period, long long offset) {
    long long count = 0;
    for (long long t = t0; t < t1; t++)
        if (t >= offset && (t - offset) % period == 0) count++;
    return count;
}
--- solution
static long long spawns_before(long long T, long long period, long long offset) {
    if (T <= offset) return 0;
    return (T - offset - 1) / period + 1;
}

long long spawns_between(long long t0, long long t1, long long period, long long offset) {
    return spawns_before(t1, period, offset) - spawns_before(t0, period, offset);
}
--- hint
Spawns before tick `T`: the ticks `offset, offset + period, ...` that are `< T`. The last one is at most `T - 1`, so there are `(T - 1 - offset) / period + 1` of them when `T > offset`.
--- hint
Everything is non-negative, so `/` (truncation) is the same as floor here.
--- harness
static long long brute(long long t0, long long t1, long long p, long long o) {
    long long c = 0;
    for (long long t = t0; t < t1; t++) if (t >= o && (t - o) % p == 0) c++;
    return c;
}

    CHECK_INT(spawns_between(0, 10, 3, 1), 3);

    CHECK_INT(spawns_between(5, 5, 1, 0), 0);
    CHECK_INT(spawns_between(0, 100, 7, 200), 0);
