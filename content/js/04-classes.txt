## this is decided at the call site

In C#, `this` inside a method is always the instance. In JavaScript, `this` inside a regular `function` is a hidden parameter set by **how the function is called**, not where it was defined. Four rules, in priority order:

| Call form | `this` |
|---|---|
| `new Foo()` | the newly created object |
| `fn.call(obj, ...)`, `fn.apply(obj, [...])`, or a function from `fn.bind(obj)` | `obj` |
| `obj.method()` | `obj` (whatever is left of the dot at call time) |
| plain `fn()` | `undefined` in strict mode; the global object in sloppy mode |

Arrow functions ignore all four: they have no `this` of their own and use the `this` of the scope they were written in.

```js
function whoAmI() { return this?.label ?? String(this === globalThis ? 'global object' : this); }
const hero = { label: 'hero', whoAmI };
const villain = { label: 'villain' };

console.log(hero.whoAmI());              // method call: hero
console.log(whoAmI.call(villain));       // explicit: villain
const detached = hero.whoAmI;
console.log(detached());                 // plain call: global object (sloppy) / undefined (strict)
const bound = whoAmI.bind(villain);
console.log(bound(), bound.call(hero));  // bind wins over call
```

`call` and `apply` differ only in how arguments are passed (`apply` takes an array; with spread syntax you rarely need it). `bind` returns a new function with `this` (and optionally leading arguments) fixed permanently.

### Losing this in callbacks

The single most common `this` bug: passing a method as a callback. The callee calls it as a plain function, so `this` is gone. Class bodies are always strict, so inside a class method that means `this === undefined` and a `TypeError`.

```js
class Spawner {
  constructor() { this.count = 0; }
  spawn() { this.count++; return this.count; }
}
const s = new Spawner();
try {
  [1, 2].forEach(s.spawn);               // passes the function, not the binding
} catch (e) { console.log(e.name + ': ' + e.message); }

[1, 2].forEach(() => s.spawn());          // fix 1: wrap in an arrow
[1, 2].forEach(s.spawn.bind(s));          // fix 2: bind
[1, 2].forEach(s.spawn, s);               // fix 3: many array methods take a thisArg
console.log(s.count);
```

Fix 4 is to define the method as an arrow-valued class field (`spawn = () => {...}`), shown below, which has a cost.

### Arrows capture this

Arrows are the fix for the pre-2015 `var self = this` dance: a callback written inside a method sees the method's `this`.

```js
const enemy = {
  label: 'orc',
  hp: 10,
  poison(ticks) {
    // arrow: this is enemy, from poison's call
    Array.from({ length: ticks }).forEach(() => { this.hp -= 2; });
    return this.hp;
  },
  broken: () => typeof this,   // arrow at object level: this from the enclosing scope, not the object
};
console.log(enemy.poison(3), enemy.broken());
```

Don't use arrows as object methods (the `broken` case): an object literal doesn't create a scope, so `this` is whatever it was outside.

## Prototypes

Every object has a hidden link to another object, its **prototype** (`Object.getPrototypeOf(obj)`, historically `obj.__proto__`). Reading a property that isn't on the object itself walks up the chain: object, its prototype, the prototype's prototype, until `null`. Writing always goes to the object itself (shadowing, not modifying, the prototype's copy).

```js
const monsterProto = {
  describe() { return `${this.kind} with ${this.hp} hp`; },
  hp: 1,                                    // a shared default
};
const goblin = Object.create(monsterProto);
goblin.kind = 'goblin';
const rat = Object.create(monsterProto);
rat.kind = 'rat';
rat.hp = 3;                                 // own property shadows the prototype's

console.log(goblin.describe(), rat.describe());
console.log(Object.hasOwn(goblin, 'hp'), 'hp' in goblin, Object.keys(goblin));
console.log(Object.getPrototypeOf(goblin) === monsterProto, Object.getPrototypeOf(monsterProto) === Object.prototype);
```

That's the whole object model. Methods live once on a shared prototype; instances hold only their data. A C# class does the same thing internally (instance fields per object, methods in the type's method table); JavaScript makes the table an ordinary object you can see and modify.

**Never put mutable shared state on a prototype.** An array default on the prototype is one array shared by every instance, and `goblin.loot.push(...)` mutates it for all of them (reading `loot` finds the prototype's array; `push` mutates it rather than assigning).

### Constructor functions: what classes compile to

```js
function Vec(x, y) { this.x = x; this.y = y; }       // called with new
Vec.prototype.len = function () { return Math.hypot(this.x, this.y); };

const v = new Vec(3, 4);
console.log(v.len(), v instanceof Vec, Object.getPrototypeOf(v) === Vec.prototype, v.constructor === Vec);
```

`new Vec(3, 4)` does four things: create an object whose prototype is `Vec.prototype`; call `Vec` with `this` set to it; if `Vec` returns an object, use that instead; otherwise return the new object. `a instanceof B` walks `a`'s prototype chain looking for `B.prototype`. You'll implement both in the exercises.

## Classes

`class` is cleaner syntax for the same prototype machinery, with a few real additions: private fields, static blocks, and enforced `new` (calling a class without `new` throws). Class bodies are always strict mode.

```js
class Entity {
  static #nextId = 1;            // private static
  static count = 0;              // public static, lives on the class itself

  id = Entity.#nextId++;         // public instance field, initialized per instance
  #hp;                           // private instance field

  constructor(name, hp) {
    this.name = name;
    this.#hp = hp;
    this.maxHp = hp;
    Entity.count++;
  }

  get hp() { return this.#hp; }                 // accessor on the prototype
  get alive() { return this.#hp > 0; }

  damage(n) {                                   // method on the prototype
    this.#hp = Math.max(0, this.#hp - n);
    return this;                                // enables chaining
  }

  static compareHp(a, b) { return a.hp - b.hp; }
  toString() { return `${this.name}#${this.id} (${this.#hp}/${this.maxHp})`; }
}

const a = new Entity('slime', 5), b = new Entity('orc', 12);
a.damage(2).damage(1);
console.log(`${a}`, b.alive, a.hp, Entity.count);
console.log(a, Object.keys(a));                // #hp isn't a property: invisible to keys and JSON
console.log([b, a].toSorted(Entity.compareHp).map(String));
a.hp = 99;                       // getter only: ignored in sloppy code like this, a TypeError in strict code
console.log(a.hp);
try { Entity('x', 1); } catch (e) { console.log(e.message); }
```

Notes for C# eyes:

- **Fields** are per-instance and initialized in declaration order, before the constructor body runs (in a subclass: right after `super()` returns).
- **`#private`** is hard privacy, enforced by the engine: `obj.#hp` from outside the class is a syntax error, and there's no reflection to get around it. `#hp in obj` is a brand check ("was this object constructed by my class?"). The older convention `_hp` is just a name.
- **`static`** members live on the constructor function. Statics are inherited: `class Boss extends Entity` gets `Boss.compareHp`.
- **No overloading**, no `protected`, no interfaces, no abstract keyword. Duck typing fills the gap: anything with an `update(dt)` method is an updatable thing. Simulate `abstract` by throwing in the base method.
- Methods aren't `virtual` or non-virtual: every call is dynamic dispatch through the prototype chain.

### Getters, setters, and validation

```js
class Stat {
  #value = 0;
  constructor(min, max) { this.min = min; this.max = max; }
  get value() { return this.#value; }
  set value(v) { this.#value = Math.min(this.max, Math.max(this.min, v)); }   // clamp on write
  get ratio() { return (this.#value - this.min) / (this.max - this.min); }
}
const stamina = new Stat(0, 100);
stamina.value = 150;
stamina.value -= 30;
console.log(stamina.value, stamina.ratio);
```

### Arrow fields: auto-bound but per instance

```js
class Button {
  clicks = 0;
  onClick = () => { this.clicks++; };   // a new function per instance, this bound to it
  press() { this.clicks++; }            // one function on the prototype, shared
}
const btn = new Button();
const handler = btn.onClick;
handler(); handler();
console.log(btn.clicks, Object.keys(btn), new Button().onClick === btn.onClick, new Button().press === btn.press);
```

> **Performance:** an arrow field is a closure allocated for every instance and stored on it. For a UI with ten buttons, who cares. For 10,000 particles, that's 10,000 extra function objects per method, and bigger objects. Keep methods on the prototype for anything you create in bulk; bind only where a callback is actually needed. Equally, initialize **every** field in the constructor or as a field declaration, so all instances share one shape. Adding a property later to some instances (`if (boss) e.phase = 1`) splits them into different shapes and makes every `e.update()` call site slower.

## Inheritance and super

```js
class Unit {
  constructor(name, hp) { this.name = name; this.hp = hp; }
  takeHit(dmg) { this.hp -= dmg; return dmg; }
  describe() { return `${this.name} (${this.hp})`; }
}

class Knight extends Unit {
  constructor(name, hp, armor) {
    super(name, hp);               // must run before touching this
    this.armor = armor;
  }
  takeHit(dmg) {                   // override
    return super.takeHit(Math.max(1, dmg - this.armor));   // call the base version
  }
  describe() { return `${super.describe()} [armor ${this.armor}]`; }
}

const k = new Knight('Ser Ada', 20, 3);
console.log(k.takeHit(5), k.takeHit(2), k.describe());
console.log(k instanceof Knight, k instanceof Unit, Object.getPrototypeOf(Knight.prototype) === Unit.prototype);
```

- A derived constructor **must** call `super(...)` before using `this` (a `ReferenceError` otherwise), and if it has no constructor, one that forwards all arguments is generated.
- `super.method()` calls the parent's version, like C#'s `base.Method()`.
- There's one gotcha C# also has: a base constructor that calls an overridden method runs the derived override **before** the derived class's fields are initialized. Avoid calling overridable methods from constructors.
- You can extend built-ins: `class Stack extends Array`, `class GameError extends Error`. Custom errors should set `this.name`.

```js
class GameError extends Error {
  constructor(message, code) { super(message); this.name = 'GameError'; this.code = code; }
}
try { throw new GameError('save corrupt', 42); } catch (e) {
  console.log(e instanceof GameError, e instanceof Error, e.name, e.code, String(e));
}
```

### instanceof and its limits

`x instanceof C` checks whether `C.prototype` is on `x`'s chain. It fails across realms (an array from another iframe or worker isn't `instanceof` your `Array`; use `Array.isArray`), and it says nothing about objects that merely have the right shape. For duck typing, check for the method: `typeof thing.update === 'function'`.

## Composition and mixins

Deep inheritance hierarchies (`Entity > Actor > Enemy > FlyingEnemy > FlyingFireEnemy`) age badly in games; that's why engines moved to components. JavaScript has two lightweight options.

**Mixins**: a function from a class to a subclass. Since `extends` takes any expression, you can stack them:

```js
const Positioned = Base => class extends Base {
  x = 0; y = 0;
  moveBy(dx, dy) { this.x += dx; this.y += dy; return this; }
};
const Damageable = Base => class extends Base {
  hp = 10;
  hurt(n) { this.hp = Math.max(0, this.hp - n); return this; }
  get dead() { return this.hp === 0; }
};
class Thing {}
class Barrel extends Damageable(Positioned(Thing)) {
  explode() { return `boom at ${this.x},${this.y}`; }
}
const barrel = new Barrel().moveBy(3, 4).hurt(10);
console.log(barrel, barrel.dead, barrel.explode());
```

**Composition**: an entity *has* components (plain objects), and systems loop over entities that have the components they need. That's the start of an entity-component-system, and it's how the Game development track structures its engine.

```js
const entities = [
  { id: 1, pos: { x: 0, y: 0 }, vel: { x: 1, y: 0 } },
  { id: 2, pos: { x: 5, y: 5 } },                             // static: no vel
  { id: 3, pos: { x: 0, y: 0 }, vel: { x: 0, y: 2 }, hp: { value: 3 } },
];
function movementSystem(list, dt) {
  for (const e of list) if (e.vel) { e.pos.x += e.vel.x * dt; e.pos.y += e.vel.y * dt; }
}
movementSystem(entities, 0.5);
console.log(entities.map(e => e.pos));
```

## C# classes versus JavaScript classes

| C# | JavaScript |
|---|---|
| `private int hp;` | `#hp;` (hard private) or `_hp` (convention only) |
| `protected` | no equivalent (convention, or symbols) |
| `public int Hp { get; private set; }` | `#hp` plus `get hp()` |
| `static` | `static` (inherited by subclasses) |
| `base.M()` | `super.m()` |
| `abstract` / `interface` | duck typing; throw in a base method; TypeScript for checking |
| overloads | one function that inspects its arguments, or options objects |
| `virtual` / `override` | every method is overridable |
| `struct` value types | no equivalent; objects are always references |
| `sealed` | no equivalent (`Object.freeze` on the prototype, rarely) |
| extension methods | adding to a prototype: possible, but don't patch built-ins |
| `this` always bound | depends on the call: see the start of this chapter |

> **Performance:** there are no value-type structs, so `new Vec2(x, y)` per operation is a heap allocation. A math library where `a.add(b)` returns a new vector is pleasant and fine at setup time, but in a physics step it makes garbage proportional to entity count times frame rate. Real engines provide mutating variants (`a.addInPlace(b)`, or `Vec2.add(out, a, b)` writing into a preallocated `out`), reuse scratch vectors, and pool short-lived objects like bullets and particles instead of creating and dropping them.

=== exercise vec2
title: Vec2
--- prompt
Write a `class Vec2` for 2D game math.

- `constructor(x = 0, y = 0)` storing public fields `x`, `y`.
- `add(v)`, `sub(v)`, `scale(s)`: return **new** vectors.
- `get length()`: the Euclidean length.
- `normalized()`: a new unit vector in the same direction; the zero vector normalizes to `(0, 0)` (not `NaN`).
- `dot(v)`.
- `equals(v, eps = 1e-9)`: component-wise within `eps`.
- `static fromAngle(rad, len = 1)`: `(cos·len, sin·len)`.
- In-place variants for hot loops, which **mutate `this` and return `this`** (so they chain and allocate nothing): `addScaledInPlace(v, s)` (adds `v * s`, the classic `pos += vel * dt`) and `set(x, y)`.
- `toString()` returning `Vec2(x, y)`, e.g. `Vec2(1, -2.5)`.
--- starter
class Vec2 {
  constructor(x, y) {
    this.x = x;
    this.y = y;
  }
}
--- solution
class Vec2 {
  constructor(x = 0, y = 0) {
    this.x = x;
    this.y = y;
  }
  add(v) { return new Vec2(this.x + v.x, this.y + v.y); }
  sub(v) { return new Vec2(this.x - v.x, this.y - v.y); }
  scale(s) { return new Vec2(this.x * s, this.y * s); }
  get length() { return Math.hypot(this.x, this.y); }
  normalized() {
    const len = this.length;
    return len === 0 ? new Vec2(0, 0) : new Vec2(this.x / len, this.y / len);
  }
  dot(v) { return this.x * v.x + this.y * v.y; }
  equals(v, eps = 1e-9) { return Math.abs(this.x - v.x) <= eps && Math.abs(this.y - v.y) <= eps; }
  static fromAngle(rad, len = 1) { return new Vec2(Math.cos(rad) * len, Math.sin(rad) * len); }
  addScaledInPlace(v, s) { this.x += v.x * s; this.y += v.y * s; return this; }
  set(x, y) { this.x = x; this.y = y; return this; }
  toString() { return `Vec2(${this.x}, ${this.y})`; }
}
--- hint
`get length() { ... }` defines an accessor: callers write `v.length`, no parentheses.
--- hint
In-place methods end with `return this;`. `static fromAngle` is called as `Vec2.fromAngle(...)`.
--- harness
{
  const a = new Vec2(3, 4), b = new Vec2(1, -2);
  eq(a.add(b), new Vec2(4, 2));
  eq(a.sub(b), new Vec2(2, 6));
  eq(a.scale(2), new Vec2(6, 8));
  eq(a, new Vec2(3, 4), 'add/sub/scale do not mutate');
  check(a.add(b) instanceof Vec2, 'returns Vec2 instances');
  eq(a.length, 5);
  eq(new Vec2().length, 0);
  eq([new Vec2().x, new Vec2().y], [0, 0], 'defaults');
  check(a.normalized().equals(new Vec2(0.6, 0.8)), 'normalized');
  eq(new Vec2(0, 0).normalized(), new Vec2(0, 0), 'zero vector');
  eq(a.dot(b), -5);
  check(Vec2.fromAngle(Math.PI / 2, 2).equals(new Vec2(0, 2)), 'fromAngle');
  check(Vec2.fromAngle(0).equals(new Vec2(1, 0)), 'fromAngle default len');
  check(!a.equals(new Vec2(3, 4.001)), 'equals eps');
  check(a.equals(new Vec2(3, 4.001), 0.01), 'equals custom eps');
  const p = new Vec2(10, 10), vel = new Vec2(2, -4);
  const r = p.addScaledInPlace(vel, 0.5);
  check(r === p, 'in-place returns this');
  eq([p.x, p.y], [11, 8]);
  eq(p.set(1, 2).addScaledInPlace(new Vec2(1, 1), 3), new Vec2(4, 5), 'chaining');
  eq(String(new Vec2(1, -2.5)), 'Vec2(1, -2.5)');
  eq(`${new Vec2()}`, 'Vec2(0, 0)');
  check(!Object.hasOwn(a, 'add') && typeof Vec2.prototype.add === 'function', 'methods live on the prototype');
}

=== exercise emitter
title: Event emitter
--- prompt
Games are full of events: `'damage'`, `'death'`, `'levelup'`. Write `class Emitter` with:

- `on(event, handler)`: subscribe; returns a function that unsubscribes this handler.
- `off(event, handler)`: unsubscribe (removes one registration; no-op if absent).
- `once(event, handler)`: subscribe for a single emit. `off(event, handler)` with the original handler must also cancel a pending `once`.
- `emit(event, ...args)`: call the event's handlers in subscription order with the args, and return how many were called.

Edge cases that real emitters get wrong, all tested:

- A handler that unsubscribes itself (or another handler) during `emit` must not cause handlers to be skipped in that emit. Handlers added during an emit are not called until the next one.
- The same handler subscribed twice is called twice.
- Handlers are called with `this` set to the emitter.
- Different events and different emitters are independent.
--- starter
class Emitter {
  handlers = {};
  on(event, handler) {
    this.handlers[event] = handler;
  }
  emit(event, ...args) {
    this.handlers[event](...args);
  }
}
--- solution
class Emitter {
  #map = new Map();

  on(event, handler) {
    return this.#add(event, { handler, fn: handler });
  }

  once(event, handler) {
    const entry = { handler, fn: null };
    entry.fn = (...args) => {
      this.#remove(event, entry);
      return handler.apply(this, args);
    };
    return this.#add(event, entry);
  }

  off(event, handler) {
    const list = this.#map.get(event);
    if (!list) return;
    const i = list.findIndex(e => e.handler === handler);
    if (i >= 0) this.#remove(event, list[i]);
  }

  emit(event, ...args) {
    const list = this.#map.get(event);
    if (!list) return 0;
    const snapshot = list.slice();
    let called = 0;
    for (const entry of snapshot) {
      if (!entry.removed) {
        called++;
        entry.fn.apply(this, args);
      }
    }
    return called;
  }

  #add(event, entry) {
    if (!this.#map.has(event)) this.#map.set(event, []);
    this.#map.get(event).push(entry);
    return () => this.#remove(event, entry);
  }

  #remove(event, entry) {
    const list = this.#map.get(event);
    const i = list ? list.indexOf(entry) : -1;
    if (i >= 0) { list.splice(i, 1); entry.removed = true; }
  }
}
--- hint
Store an entry object per registration (`{ handler, fn }`) rather than bare functions, so `once` wrappers can be found by their original handler and duplicates stay distinct.
--- hint
In `emit`, iterate over a copy of the list so removals don't shift indexes under you. But a handler removed during the emit, before its turn, should not be called: mark entries as removed and skip them.
--- harness
{
  const em = new Emitter();
  const log = [];
  const a = (x) => log.push('a' + x), b = (x) => log.push('b' + x);
  const unA = em.on('hit', a);
  em.on('hit', b);
  eq(em.emit('hit', 1), 2);
  eq(log, ['a1', 'b1']);
  unA();
  eq(em.emit('hit', 2), 1);
  eq(log, ['a1', 'b1', 'b2']);
  em.off('hit', b);
  eq(em.emit('hit', 3), 0);
  eq(em.emit('nothing'), 0, 'unknown event');
  em.off('nothing', a);

  const em2 = new Emitter();
  let n = 0;
  em2.once('go', () => n++);
  eq([em2.emit('go'), em2.emit('go')], [1, 0]);
  eq(n, 1, 'once fires once');
  const h = () => n++;
  em2.once('go', h);
  em2.off('go', h);
  eq(em2.emit('go'), 0, 'off cancels once');

  const em3 = new Emitter(), order = [];
  const self = () => { order.push('self'); em3.off('t', self); };
  const next = () => order.push('next');
  em3.on('t', self); em3.on('t', next);
  eq(em3.emit('t'), 2, 'self-removal does not skip the next handler');
  eq(order, ['self', 'next']);
  eq(em3.emit('t'), 1);

  const em4 = new Emitter(), seen = [];
  const second = () => seen.push('second');
  em4.on('t', () => { seen.push('first'); em4.off('t', second); });
  em4.on('t', second);
  eq(em4.emit('t'), 1, 'handler removed before its turn is not called');
  eq(seen, ['first']);

  const em5 = new Emitter(), adds = [];
  em5.on('t', () => { adds.push('outer'); em5.on('t', () => adds.push('inner')); });
  em5.emit('t');
  eq(adds, ['outer'], 'added during emit not called yet');

  const em6 = new Emitter();
  let dup = 0;
  const d = () => dup++;
  em6.on('t', d); em6.on('t', d);
  em6.emit('t');
  eq(dup, 2, 'duplicates called twice');
  em6.off('t', d);
  em6.emit('t');
  eq(dup, 3, 'off removes one registration');

  const em7 = new Emitter();

  em7.on('t', function () { who = this; });
  em7.emit('t');
  check(who === em7, 'this is the emitter');
  let args = null;
  em7.once('u', function (...a) { args = [this === em7, ...a]; });
  em7.emit('u', 1, 2);
  eq(args, [true, 1, 2], 'once passes this and args');

  const x1 = new Emitter(), x2 = new Emitter();
  let c = 0;
  x1.on('t', () => c++);
  x2.emit('t');
  eq(c, 0, 'emitters independent');
}

=== exercise units
title: A unit hierarchy
--- prompt
Write three classes.

**`Unit`**: `constructor(name, hp)`. HP is **private** (`#hp`), exposed by a read-only getter `hp`. Also `get alive()` (hp > 0), and `takeDamage(n)`: reduces hp (never below 0), ignores negative `n` (treat as 0), and returns the damage actually dealt (so `5` damage on a unit with 3 hp returns `3`). A static `Unit.created` counts all units ever constructed, including subclasses.

**`Armored extends Unit`**: `constructor(name, hp, armor)`. `takeDamage(n)` subtracts `armor` from incoming damage first (minimum 0) and then applies the rest via the base implementation, returning damage dealt.

**`Boss extends Armored`**: `constructor(name, hp, armor)`. Has a public `phase` field starting at `1`. When a hit brings hp to half of the starting hp or below for the first time, `phase` becomes `2` and `armor` doubles. Returns damage dealt like the others.

`toString()` on all of them returns `name (hp/maxHp)`.
--- starter
class Unit {
  constructor(name, hp) {
    this.name = name;
    this.hp = hp;
  }
}
class Armored extends Unit {}
class Boss extends Armored {}
--- solution
class Unit {
  static created = 0;
  #hp;
  constructor(name, hp) {
    this.name = name;
    this.maxHp = hp;
    this.#hp = hp;
    Unit.created++;
  }
  get hp() { return this.#hp; }
  get alive() { return this.#hp > 0; }
  takeDamage(n) {
    const dealt = Math.min(this.#hp, Math.max(0, n));
    this.#hp -= dealt;
    return dealt;
  }
  toString() { return `${this.name} (${this.#hp}/${this.maxHp})`; }
}

class Armored extends Unit {
  constructor(name, hp, armor) {
    super(name, hp);
    this.armor = armor;
  }
  takeDamage(n) {
    return super.takeDamage(Math.max(0, n - this.armor));
  }
}

class Boss extends Armored {
  phase = 1;
  takeDamage(n) {
    const dealt = super.takeDamage(n);
    if (this.phase === 1 && this.hp <= this.maxHp / 2) {
      this.phase = 2;
      this.armor *= 2;
    }
    return dealt;
  }
}
--- hint
Subclasses can't touch `#hp`: it's private to `Unit`'s body. Route all damage through `super.takeDamage(...)` and read `this.hp` through the getter.
--- hint
`Unit.created++` in the base constructor counts subclasses too, since every subclass constructor calls `super`. Use `Unit.created`, not `this.constructor.created`, or each subclass would get its own copy of the counter.
--- harness

=== exercise pool
title: Object pool
--- prompt
Bullets and particles live for a fraction of a second. Creating and discarding thousands per second feeds the garbage collector; a pool recycles them instead. Write `class Pool`:

- `constructor(create, reset)`: `create()` makes a new object; `reset(obj)` prepares a recycled one.
- `acquire()`: returns a free object if there is one (after calling `reset` on it), otherwise a new one from `create()`.
- `release(obj)`: returns `obj` to the pool. Releasing an object that isn't currently in use (released twice, or never acquired from this pool) throws an `Error`.
- `get inUse()` and `get free()`: counts.
- `prewarm(n)`: creates objects until at least `n` are free.

`acquire` and `release` must be O(1) (tested with 200,000 objects, so no `indexOf`/`includes` scans over arrays). Hint: a `Set` gives O(1) membership.
--- starter
class Pool {
  constructor(create, reset) {
    this.create = create;
  }
  acquire() { return this.create(); }
  release(obj) {}
}
--- solution
class Pool {
  #create; #reset;
  #free = [];
  #used = new Set();

  constructor(create, reset) {
    this.#create = create;
    this.#reset = reset;
  }

  acquire() {
    let obj;
    if (this.#free.length) {
      obj = this.#free.pop();
      this.#reset(obj);
    } else {
      obj = this.#create();
    }
    this.#used.add(obj);
    return obj;
  }

  release(obj) {
    if (!this.#used.delete(obj)) throw new Error('object not in use');
    this.#free.push(obj);
  }

  prewarm(n) {
    while (this.#free.length < n) this.#free.push(this.#create());
  }

  get inUse() { return this.#used.size; }
  get free() { return this.#free.length; }
}
--- hint
Keep free objects in an array used as a stack (`push`/`pop` are O(1)) and the in-use ones in a `Set`.
--- hint
`set.delete(obj)` returns `false` when `obj` wasn't there: that's your double-release check in one O(1) call.
--- harness
{
  let made = 0, resets = 0;
  const pool = new Pool(() => ({ id: made++, x: 0, alive: true }), b => { resets++; b.x = 0; b.alive = true; });
  const a = pool.acquire(), b = pool.acquire();
  eq([made, pool.inUse, pool.free], [2, 2, 0]);
  a.x = 50; a.alive = false;
  pool.release(a);
  eq([pool.inUse, pool.free], [1, 1]);
  const c = pool.acquire();
  check(c === a, 'recycled the same object');
  eq([c.x, c.alive, resets, made], [0, true, 1, 2], 'reset was called, nothing new created');
  throws(() => { pool.release(b); pool.release(b); }, 'double release throws');
  throws(() => pool.release({}), 'foreign object throws');
  eq([pool.inUse, pool.free], [1, 1]);
  pool.prewarm(10);
  eq([pool.free, made], [10, 11]);
  pool.prewarm(5);
  eq(pool.free, 10, 'prewarm is "at least"');

  const big = new Pool(() => ({}), () => {});
  const N = 200000, objs = new Array(N);
  const t = performance.now();
  for (let i = 0; i < N; i++) objs[i] = big.acquire();
  for (let i = 0; i < N; i++) big.release(objs[i]);
  for (let i = 0; i < N; i++) objs[i] = big.acquire();
  const ms = performance.now() - t;
  eq([big.inUse, big.free], [N, 0]);
  check(ms < 500, `200k acquire/release took ${ms.toFixed(0)} ms (want < 500)`);
}

=== exercise protoMagic
title: new and instanceof by hand
--- prompt
Implement the two operators yourself, using only `Object.create`, `Object.getPrototypeOf` and function calls:

- `construct(Ctor, ...args)`: behaves like `new Ctor(...args)` for **constructor functions** (not classes, which refuse to be called without `new`). Create an object whose prototype is `Ctor.prototype`, call `Ctor` with it as `this`, and return the constructor's return value if that is an object (or function), otherwise the new object.
- `isInstance(obj, Ctor)`: like `obj instanceof Ctor`. Primitives (and `null`/`undefined`) are never instances. Walk the prototype chain of `obj` looking for `Ctor.prototype`.
--- starter
function construct(Ctor, ...args) {
  return Ctor(...args);
}

function isInstance(obj, Ctor) {
  return obj.constructor === Ctor;
}
--- solution
function construct(Ctor, ...args) {
  const obj = Object.create(Ctor.prototype);
  const result = Ctor.apply(obj, args);
  return (result !== null && typeof result === 'object') || typeof result === 'function' ? result : obj;
}

function isInstance(obj, Ctor) {
  if (obj === null || (typeof obj !== 'object' && typeof obj !== 'function')) return false;
  let p = Object.getPrototypeOf(obj);
  while (p !== null) {
    if (p === Ctor.prototype) return true;
    p = Object.getPrototypeOf(p);
  }
  return false;
}
--- hint
`Ctor.apply(obj, args)` calls the constructor with `this = obj`.
--- hint
`obj.constructor` can be overwritten and isn't how `instanceof` works. Loop `p = Object.getPrototypeOf(p)` until `null`.
--- harness
{
  function Monster(kind, hp) { this.kind = kind; this.hp = hp; }
  Monster.prototype.roar = function () { return this.kind + '!'; };
  function Dragon(hp) { Monster.call(this, 'dragon', hp); }
  Dragon.prototype = Object.create(Monster.prototype);
  Dragon.prototype.constructor = Dragon;

  const m = construct(Monster, 'orc', 5);
  eq([m.kind, m.hp, m.roar()], ['orc', 5, 'orc!']);
  check(Object.getPrototypeOf(m) === Monster.prototype, 'prototype set');
  const d = construct(Dragon, 50);
  eq(d.roar(), 'dragon!');
  check(isInstance(d, Dragon) && isInstance(d, Monster) && isInstance(d, Object), 'chain');
  check(!isInstance(m, Dragon), 'not a dragon');
  check(isInstance(m, Monster) === (m instanceof Monster), 'agrees with instanceof');

  function ReturnsObj() { this.a = 1; return { b: 2 }; }
  eq(construct(ReturnsObj), { b: 2 }, 'returned object wins');
  function ReturnsPrim() { this.a = 1; return 42; }
  eq(construct(ReturnsPrim).a, 1, 'returned primitive ignored');
  function ReturnsNull() { this.a = 1; return null; }
  eq(construct(ReturnsNull).a, 1, 'returned null ignored');
  const fn = () => 1;
  function ReturnsFn() { return fn; }
  check(construct(ReturnsFn) === fn, 'returned function wins');

  check(!isInstance(5, Number), 'primitives are not instances');
  check(!isInstance(null, Object) && !isInstance(undefined, Object), 'null/undefined');
  check(isInstance([], Array) && isInstance([], Object), 'arrays');
  check(isInstance(fn, Function), 'functions are objects');
  check(!isInstance(Object.create(null), Object), 'null prototype');
  const fake = { constructor: Monster };
  check(!isInstance(fake, Monster), 'constructor property is not proof');
  class Real {}
  check(isInstance(new Real(), Real), 'works with class instances');
}

=== exercise mixins
title: Mixins
--- prompt
Write two mixins, functions that take a base class and return a subclass:

- `Movable(Base)`: adds fields `x = 0`, `y = 0`, `vx = 0`, `vy = 0` and a method `step(dt)` that moves by velocity times `dt` and returns `this`.
- `Living(Base)`: adds a field `hp` initialized from a static `maxHp` on the **final** class (`this.constructor.maxHp`, default `10` if the class doesn't define one), and `heal(n)` (capped at max hp, returns `this`) and `hurt(n)` (floored at 0, returns `this`), plus `get dead()`.

Then define `class Player extends Living(Movable(Object))` with `static maxHp = 30` and a `name` set from its constructor's argument.

Mixins must not interfere with a base class's constructor arguments: `Living(Movable(Named))` where `Named`'s constructor takes `(name)` must still receive it.
--- starter
const Movable = Base => Base;
const Living = Base => Base;
class Player {}
--- solution
const Movable = Base => class extends Base {
  x = 0; y = 0; vx = 0; vy = 0;
  step(dt) { this.x += this.vx * dt; this.y += this.vy * dt; return this; }
};

const Living = Base => class extends Base {
  hp = this.constructor.maxHp ?? 10;
  get maxHp() { return this.constructor.maxHp ?? 10; }
  heal(n) { this.hp = Math.min(this.maxHp, this.hp + n); return this; }
  hurt(n) { this.hp = Math.max(0, this.hp - n); return this; }
  get dead() { return this.hp === 0; }
};

class Player extends Living(Movable(Object)) {
  static maxHp = 30;
  constructor(name) {
    super();
    this.name = name;
  }
}
--- hint
`const Movable = Base => class extends Base { ... }`. Without an explicit constructor, the generated one forwards all arguments to `Base`.
--- hint
A field initializer can read `this.constructor`: it runs during construction, after the base constructors, with `this` being the final object.
--- harness
{
  const p = new Player('ada');
  eq([p.name, p.hp, p.x, p.y], ['ada', 30, 0, 0]);
  p.vx = 2; p.vy = -1;
  check(p.step(0.5) === p, 'step returns this');
  eq([p.x, p.y], [1, -0.5]);
  p.hurt(50);
  eq([p.hp, p.dead], [0, true]);
  p.heal(100);
  eq(p.hp, 30, 'heal capped at maxHp');
  eq(p.hurt(5).heal(2).hp, 27, 'chaining');

  class Named { constructor(name) { this.name = name; } }
  class Crate extends Living(Movable(Named)) {}
  const c = new Crate('box');
  eq([c.name, c.hp], ['box', 10], 'base args forwarded, default max 10');
  c.heal(5);
  eq(c.hp, 10);
  check(c instanceof Named, 'instanceof base');
  class Tough extends Living(Object) { static maxHp = 99; }
  eq(new Tough().hp, 99);
  check(!Object.hasOwn(c, 'step') && !Object.hasOwn(c, 'heal'), 'methods on prototypes, not instances');
}
