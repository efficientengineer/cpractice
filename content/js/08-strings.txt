## The string API in one pass

Strings are immutable sequences of UTF-16 code units, the same representation as C#'s `string`. Every method returns a new string. Most of the API maps one to one onto C#:

```js
const s = '  Hello, World  ';
const t = s.trim();
console.log(t.length, t.at(0), t.at(-1), t[100]);          // at() takes negative indices
console.log(t.slice(7), t.slice(-5, -1), t.slice(3, 1));   // slice(start, end), negatives from end
console.log(t.substring(3, 1));                            // substring swaps arguments; avoid it
console.log(t.indexOf('o'), t.lastIndexOf('o'), t.indexOf('o', 5), t.indexOf('z'));
console.log(t.includes('World'), t.startsWith('Hell'), t.endsWith('!'));
console.log(t.toUpperCase(), t.toLowerCase(), 'ab'.repeat(3));
console.log('7'.padStart(3, '0'), 'id'.padEnd(6, '.') + '|', 'abc'.padStart(2));
console.log('a-b-c'.replace('-', '+'), 'a-b-c'.replaceAll('-', '+'));
console.log('a,b,,c'.split(','), 'a,b,c'.split(',', 2), [...'abc'].join('|'));
```

Things that differ from C#:

- There is no `char` type. `s[0]` is a string of length 1 (or `undefined` past the end, never an exception).
- `slice` is the method to use. `substring` silently swaps its arguments and clamps negatives to 0; the legacy `substr(start, length)` is deprecated.
- `replace` with a string pattern replaces only the **first** occurrence. Use `replaceAll` or a regex with the `g` flag.
- Comparison with `<` compares UTF-16 code units, which is ordinal: `'Z' < 'a'` is true. For human sorting use `localeCompare` or `Intl.Collator`.
- String concatenation in a loop is fine. Engines use ropes, so there is no need for a `StringBuilder`; building an array and calling `join` is also idiomatic.

> **Performance:** strings are immutable, so every `+`, template literal, `slice`, `split` and `toUpperCase` allocates a new string. That is fine at load time and a bad habit in per-frame, per-vertex or per-pixel code: an overlay that rebuilds `` `FPS: ${fps}` `` sixty times a second makes garbage for the collector even when the value did not change, and building a `` `${x},${y}` `` key per pixel to look something up in a `Map` is far slower than an integer index `y * width + x`. Rebuild text only when its value changes, and never `split` or regex-parse data in a hot loop: parse scene files, shader sources, presets and OBJ meshes once at load into numbers, arrays and typed arrays.

## UTF-16: code units, code points and graphemes

`length` counts **UTF-16 code units**. Characters outside the Basic Multilingual Plane (most emoji, many CJK extension characters, mathematical letters) take two code units, a *surrogate pair*. Indexing, `slice`, `length` and `charCodeAt` all work in code units and can cut a pair in half. The string iterator (`for...of`, spread, `Array.from`) works in **code points**:

```js
const s = 'a😀b';
console.log(s.length, [...s].length);
console.log(s[1], s[1] === '\uD83D', s.charCodeAt(1).toString(16));
console.log(s.codePointAt(1).toString(16), s.codePointAt(2).toString(16));
for (const ch of s) console.log(ch, ch.codePointAt(0));
console.log(String.fromCodePoint(0x1F600), '\u{1F600}' === '😀');
console.log(s.split('').reverse().join('') === [...s].reverse().join(''));
```

`codePointAt(i)` returns the full code point if `i` is the *start* of a pair, and the lone trailing surrogate if it is in the middle. `charCodeAt` always returns one code unit. `String.fromCodePoint` and the `\u{...}` escape build characters from code points.

Code points are still not what a user sees as "one character". A **grapheme cluster** can be several code points: a letter plus combining accents, a flag (two regional indicators), an emoji with a skin tone modifier, or a family joined by zero-width joiners. `Intl.Segmenter` splits by graphemes:

```js
const family = '👨‍👩‍👧';
console.log(family.length, [...family].length);
const seg = new Intl.Segmenter('en', { granularity: 'grapheme' });
console.log([...seg.segment(family)].length);
console.log([...seg.segment('e\u0301🇯🇵!')].map(x => x.segment));
```

> **Performance:** `[...s]` allocates an array plus one string per code point. To count or scan, iterate with `for...of` or step through with `codePointAt` instead of spreading.

Rule of thumb: count `length` for storage and protocol limits, code points when you have to process characters, graphemes when you truncate or display.

### Normalization

The same visible text can have several encodings. `é` is either U+00E9 (one code point, *composed*) or `e` followed by U+0301 COMBINING ACUTE ACCENT (*decomposed*). They render identically and compare unequal. `normalize()` converts to a canonical form: `'NFC'` (composed, the default and what you usually want for storage and comparison) or `'NFD'` (decomposed, handy for stripping accents). The `NFKC`/`NFKD` forms also fold compatibility characters like `ﬁ` into `fi`.

```js
const a = '\u00E9', b = 'e\u0301';
console.log(a, b, a === b, a.length, b.length);
console.log(a.normalize() === b.normalize(), b.normalize('NFC').length);
const stripAccents = s => s.normalize('NFD').replace(/\p{M}/gu, '');
console.log(stripAccents('Crème Brûlée à São Paulo'));
console.log('ﬁle'.normalize('NFKC'), 'ﬁle'.length, 'ﬁle'.normalize('NFKC').length);
```

## Intl in brief

The `Intl` namespace is the equivalent of .NET's `CultureInfo` formatting, built into the engine. Create a formatter once and reuse it; construction is the expensive part.

```js
const n = 1234567.891;
console.log(new Intl.NumberFormat('en-US').format(n));
console.log(new Intl.NumberFormat('de-DE', { style: 'currency', currency: 'EUR' }).format(n));
console.log(new Intl.NumberFormat('en', { notation: 'compact' }).format(n));
const d = new Date(Date.UTC(2024, 2, 5, 14, 30));
console.log(new Intl.DateTimeFormat('en-GB', { dateStyle: 'long', timeStyle: 'short', timeZone: 'UTC' }).format(d));
console.log(['item10', 'item9', 'Item1'].sort(new Intl.Collator('en', { numeric: true, sensitivity: 'base' }).compare));
const plural = new Intl.PluralRules('en', { type: 'ordinal' });
const suffix = { one: 'st', two: 'nd', few: 'rd', other: 'th' };
console.log([1, 2, 3, 4, 11, 22, 103].map(k => k + suffix[plural.select(k)]).join(' '));
console.log(new Intl.RelativeTimeFormat('en', { numeric: 'auto' }).format(-1, 'day'));
```

`toLocaleString` on numbers and dates and `localeCompare` on strings are shortcuts that create a formatter per call.

## Regular expressions

JavaScript regexes are close to .NET's: same character classes, quantifiers, groups and lookarounds. A literal `/ab+c/gi` is compiled once when the script loads; `new RegExp(pattern, flags)` builds one from a string at runtime (escape your backslashes twice, and escape user input before embedding it).

### Flags

| Flag | Name | Effect |
|---|---|---|
| `g` | global | find all matches; makes `exec`/`test` stateful via `lastIndex` |
| `i` | ignoreCase | case-insensitive |
| `m` | multiline | `^` and `$` match at line breaks, not just the ends of the input |
| `s` | dotAll | `.` also matches `\n` |
| `u` | unicode | code point semantics, `\u{...}`, `\p{...}` property escapes, strict syntax |
| `v` | unicodeSets | `u` plus set operations in classes like `[\p{L}--[a-z]]` |
| `y` | sticky | match only exactly at `lastIndex` (no scanning ahead) |
| `d` | hasIndices | adds `indices` (start and end of each group) to match results |

Always use `u` (or `v`) for text that may contain non-ASCII characters: without it `.` matches half a surrogate pair and `/^.$/.test('😀')` is false.

### The methods

| Call | Returns |
|---|---|
| `re.test(s)` | boolean |
| `re.exec(s)` | one match array (with `index`, `groups`) or `null`; with `g`/`y` it starts at `lastIndex` and advances it |
| `s.match(re)` | without `g`: like `exec`. With `g`: an array of all matched strings, no groups |
| `s.matchAll(re)` | iterator of full match arrays; `re` must have `g` |
| `s.replace(re, x)` / `replaceAll` | new string; `x` is a pattern string or a function |
| `s.split(re)` | array; capture groups in `re` are included in the output |
| `s.search(re)` | index of the first match or `-1` |

```js
const re = /(\d{4})-(\d{2})-(\d{2})/;
const m = re.exec('Due: 2024-03-15, paid 2024-04-01');
console.log(m[0], m[1], m.index, m.length);
console.log('Due: 2024-03-15, paid 2024-04-01'.match(/\d{4}-\d{2}-\d{2}/g));
for (const x of 'a1b22c333'.matchAll(/[a-z](\d+)/g)) console.log(x[0], x[1], x.index);
console.log('one  two   three'.split(/\s+/), 'a1b2c'.split(/(\d)/));
```

> **Performance:** a regex literal is compiled once and the compiled form is cached, but `new RegExp(...)` inside a function called per frame or per line of a big file recompiles every time: hoist it to the top level. `match`, `matchAll`, `exec` and `split` allocate result arrays; when you only need a yes/no, `test` allocates nothing.

The `g` flag makes a regex object stateful: `test` and `exec` start from `lastIndex` and store where they stopped. Reusing a global regex across different strings with `test` is a classic bug, so do not put `g` on a regex you only `test` with.

### Groups, names and backreferences

```js
const date = /(?<y>\d{4})-(?<m>\d{2})-(?<d>\d{2})/u;
const { y, m, d } = '2024-03-15'.match(date).groups;
console.log(y, m, d);
console.log('2024-03-15'.replace(date, '$<d>/$<m>/$<y>'), '2024-03-15'.replace(date, '$3.$2.$1'));
console.log(/(?:ab)+/.exec('ababx')[0]);                       // (?:...) does not capture
console.log(/(\w)\1/.exec('hello')[0], /(?<q>['"]).*?\k<q>/.exec(`say "hi" 'x'`)[0]);
console.log('<a><b>'.match(/<.+>/)[0], '<a><b>'.match(/<.+?>/)[0]);   // greedy vs lazy
```

In a replacement string, `$1` and `$<name>` insert groups, `$&` the whole match, `` $` `` and `$'` the text before and after, `$$` a literal dollar.

### Lookaround and boundaries

`(?=x)` and `(?!x)` assert what follows; `(?<=x)` and `(?<!x)` assert what precedes. None of them consume characters. `\b` is a word boundary (ASCII word characters only, even with `u`).

```js
console.log('1234567'.replace(/\B(?=(\d{3})+(?!\d))/g, ','), '1234.5678'.replace(/\B(?=(\d{3})+(?!\d))/g, ','));
console.log('price: $30, €40, $5'.match(/(?<=\$)\d+/g));
console.log('foo.js bar.ts baz.js'.match(/\b\w+(?=\.js\b)/g));
console.log(/^(?=.*\d)(?=.*[a-z])(?=.*[A-Z]).{8,}$/.test('Passw0rdX'));
console.log('naïve café'.match(/\p{L}+/gu), 'naïve café'.match(/\w+/g));
```

The first line shows lookaround's limits: it works for integers, but the decimals of `1234.5678` also get a comma (`678` is three digits followed by no digit). A correct version has to split on the decimal point first, or use `Intl.NumberFormat`.

### Replacing with a function

When the replacement needs logic, pass a function. It receives the match, each group, the offset, the whole string, and (if there are named groups) a groups object:

```js
const prices = 'apple 1.50, pear 0.75, melon 3.00';
console.log(prices.replace(/(\d+)\.(\d{2})/g, (all, units, cents) => `${Number(units) * 100 + Number(cents)}c`));
const tpl = 'Hi {name}, you have {count} new {what}.';
const data = { name: 'Ada', count: 3 };
console.log(tpl.replace(/\{(\w+)\}/g, (m, key) => key in data ? String(data[key]) : m));
const escapeRegExp = s => s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
console.log(new RegExp(escapeRegExp('1+1=2?')).test('is 1+1=2?'));
```

Catastrophic backtracking exists here too: a pattern like `/^(a+)+$/` on `'aaaaaaaaaaaaaaaaaaaaaaaaaa!'` takes exponential time. Avoid nested quantifiers over the same characters.

## Tagged templates

A template literal with a function in front calls the function with the literal pieces and the interpolated values *unconverted*. That lets a library escape, validate or even parse the values instead of blindly concatenating them:

```js
function show(strings, ...values) {
  console.log(strings, strings.raw, values);
}
show`a${1}b${{ x: 2 }}\n`;

const escapeHtml = s => String(s).replace(/[&<>"']/g, c => ({ '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' })[c]);
function html(strings, ...values) {
  return strings.reduce((out, str, i) => out + escapeHtml(values[i - 1]) + str);
}
const user = '<img src=x onerror=alert(1)>';
console.log(html`<p title="${user}">${user}</p>`);
console.log(String.raw`C:\new\table ${1 + 1}`);
```

`strings` always has exactly one more element than `values`. `strings.raw` holds the source text with escapes unprocessed, which is what `String.raw` returns. The `strings` array is frozen and is the *same object* every time a given call site runs, so tags can cache work per call site (lit-html does this).

## Rewriting strings: L-systems

An **L-system** grows structure by string rewriting: start from an *axiom*, and in each generation replace **every symbol at once** according to a rule table. Interpreted as drawing commands (`F` draw forward, `+`/`-` turn, `[`/`]` push and pop the turtle state), the strings become plants, trees and fractals; the procedural generation track draws them. Here we care about the string side:

```js
function step(s, rules) {
  let out = '';
  for (const ch of s) out += rules[ch] ?? ch;      // symbols without a rule are copied
  return out;
}
const algae = { A: 'AB', B: 'A' };
let s = 'A';
for (let i = 0; i < 6; i++) { console.log(i, s); s = step(s, algae); }

// The classic bug: applying the rules one after another instead of simultaneously.
const wrong = 'AB'.replaceAll('A', 'AB').replaceAll('B', 'A');
console.log(wrong, step('AB', algae));

const plant = { X: 'F+[[X]-X]-F[-FX]+X', F: 'FF' };
let p = 'X';
for (let i = 0; i < 6; i++) p = step(p, plant);
console.log(p.length, p.slice(-24));
```

The sequential version lets the `B` rule rewrite the `B`s that the `A` rule just produced. Rules must be applied in one pass over the *old* string.

> **Performance:** L-system strings grow exponentially (the plant above multiplies its length by about 4 per generation), so always cap generations or total length and check the cap *while* building, not after. For deep systems, do not materialize the final string at all: interpret it recursively (expand a symbol only when the turtle reaches it, with recursion depth equal to the generation count), which needs memory proportional to the depth instead of the length.

## Building a tokenizer with a sticky regex

A tokenizer turns text into a list of typed tokens. The cleanest JavaScript technique combines one regex of named alternatives with the `y` flag: each `exec` must match exactly at `lastIndex`, so unmatched junk cannot be skipped silently.

```js
const TOKEN = /(?<ws>\s+)|(?<num>\d+(?:\.\d+)?)|(?<id>[A-Za-z_]\w*)|(?<op>\*\*|[-+*\/()=])/y;

function tokenize(src) {
  const out = [];
  TOKEN.lastIndex = 0;
  while (TOKEN.lastIndex < src.length) {
    const start = TOKEN.lastIndex;
    const m = TOKEN.exec(src);
    if (!m) throw new SyntaxError(`Unexpected '${src[start]}' at ${start}`);
    const [type, text] = Object.entries(m.groups).find(([, v]) => v !== undefined);
    if (type !== 'ws') out.push({ type, text, pos: start });
  }
  return out;
}

console.log(tokenize('x = 2 ** (y + 3.5)').map(t => `${t.type}:${t.text}`).join(' '));
try { tokenize('a + #'); } catch (e) { console.log(e.message); }
```

> **Performance:** the sticky regex never copies the input. The common naive tokenizer does `src = src.slice(token.length)` and matches `^...` again, creating a new string per token; on a large file that is a lot of garbage, and in engines that copy on `slice` it turns tokenizing quadratic. Track a position instead.

Order matters in the alternation: `\*\*` must come before `*`, and keywords before general identifiers if they are separate types. When a token can be empty the loop would never advance, so make sure no alternative matches the empty string. The capstone chapter builds a parser on top of this.

=== exercise kv
title: Parsing key=value pairs
--- prompt
A scene description format declares materials with lines like `material name="Rusty metal" roughness=0.8 tint=#aa5533`. Write `parseKV(s)` that parses the `key=value` pairs of such a line into an object, using `matchAll` and named groups.

- Keys are `[A-Za-z_][\w.-]*` and must start at the beginning of the line or after whitespace.
- A value is either double-quoted (may contain spaces and `\"` or `\\` escapes, which you unescape), single-quoted (no escapes; anything up to the next `'`), or bare (a run of non-whitespace characters, possibly empty).
- Pairs are separated by whitespace. Anything that is not a well-formed pair is ignored.
- If a key repeats, the last value wins.
- The result object must have no prototype (`Object.create(null)`), so a key like `__proto__` is just a key.

```js
parseKV(`a=1 b="hello \\"world\\"" c='x y' d= e.f-g=ok`)
// { a: '1', b: 'hello "world"', c: 'x y', d: '', 'e.f-g': 'ok' }
```
--- starter
function parseKV(s) {
  const out = {};
  for (const part of s.split(' ')) {
    const [k, v] = part.split('=');
    out[k] = v;
  }
  return out;
}
--- solution
function parseKV(s) {
  const re = /(?<=^|\s)(?<key>[A-Za-z_][\w.-]*)=(?:"(?<dq>(?:[^"\\]|\\.)*)"|'(?<sq>[^']*)'|(?<bare>[^\s"']*))(?=\s|$)/g;
  const out = Object.create(null);
  for (const { groups: g } of s.matchAll(re)) {
    out[g.key] = g.dq !== undefined ? g.dq.replace(/\\(.)/g, '$1')
      : g.sq !== undefined ? g.sq
      : g.bare;
  }
  return out;
}
--- hint
One regex with three alternatives for the value, each in its own named group: `"(?<dq>(?:[^"\\]|\\.)*)"`, `'(?<sq>[^']*)'` and `(?<bare>\S*)`. Only the group that matched is not `undefined`.
--- hint
Unescape the double-quoted value with `.replace(/\\(.)/g, '$1')`. Add a lookahead `(?=\s|$)` so a pair must end at whitespace or the end of the line.

| type | matches | value |
|---|---|---|
| `'num'` | `12`, `3.5`, `.5`, `1e9`, `2.5e-3` | the number (`Number`) |
| `'str'` | double-quoted, with escapes `\n` `\t` `\"` `\\` | the unescaped string |
| `'kw'` | `let`, `if`, `else`, `uniform`, `return`, `fn` | the word |
| `'id'` | a letter or `_` (any Unicode letter, use `\p{L}`) then letters, digits, `_` | the word |
| `'op'` | `== != <= >= && \|\| => + - * / % = < > ! ( ) { } , ;` | the operator |

Throw a `SyntaxError` whose message contains `line:col` (for example `'Unexpected "#" at 2:5'`) on any character that starts no token, and on an unterminated string (a string may not contain a raw newline).
--- starter

--- solution
function tokenize(src) {
  const re = /(?<nl>\n)|(?<ws>[ \t\r]+)|(?<comment>\/\/[^\n]*)|(?<num>(?:\d+\.?\d*|\.\d+)(?:[eE][+-]?\d+)?)|(?<str>"(?:[^"\\\n]|\\.)*")|(?<word>[\p{L}_][\p{L}\p{N}_]*)|(?<op>==|!=|<=|>=|&&|\|\||=>|[-+*\/%=<>!(){},;])/uy;
  const KW = new Set(['let', 'if', 'else', 'uniform', 'return', 'fn']);
  const ESC = { n: '\n', t: '\t', '"': '"', '\\': '\\' };
  const out = [];
  let line = 1, lineStart = 0;
  re.lastIndex = 0;
  while (re.lastIndex < src.length) {
    const start = re.lastIndex;
    const m = re.exec(src);
    const where = `${line}:${start - lineStart + 1}`;
    if (!m) throw new SyntaxError(src[start] === '"' ? `Unterminated string at ${where}` : `Unexpected "${src[start]}" at ${where}`);
    const g = m.groups, col = start - lineStart + 1;
    if (g.nl) { line++; lineStart = re.lastIndex; }
    else if (g.ws || g.comment) {}
    else if (g.num) out.push({ type: 'num', value: Number(g.num), line, col });
    else if (g.str) out.push({ type: 'str', value: g.str.slice(1, -1).replace(/\\(.)/g, (_, c) => ESC[c] ?? c), line, col });
    else if (g.word) out.push({ type: KW.has(g.word) ? 'kw' : 'id', value: g.word, line, col });
    else out.push({ type: 'op', value: g.op, line, col });
  }
  return out;
}
--- hint

--- hint
Track `line` and the index where the current line starts. On a newline token, increment `line` and set `lineStart = re.lastIndex`. The column is `start - lineStart + 1`.
--- hint
Match keywords as identifiers, then check them against a `Set`. Put the two-character operators before the single-character class in the alternation.

title: L-system expansion
--- prompt
Write `expand(axiom, rules, n, options)` that applies L-system `rules` to `axiom` for `n` generations, rewriting every symbol simultaneously, and returns the resulting string. Symbols are single characters; a symbol with no rule is copied unchanged.

A rule's value is either a replacement string, or (for a *stochastic* rule) an array of `[weight, replacement]` choices. For a stochastic symbol, draw `r = rng() * totalWeight` and pick the first choice whose cumulative weight is greater than `r`. `options` is `{ maxLength = 1e6, rng }`:

- If a stochastic rule is used and no `rng` function was given, throw a `TypeError`.
- If any generation would exceed `maxLength` characters, throw a `RangeError`, and do it **while building** that generation: `expand('A', { A: 'AAAA' }, 30)` must fail fast, not after trying to build a 4^30 string.
- Only own properties of `rules` count (a symbol `'c'` must not pick up anything inherited).

```js
expand('A', { A: 'AB', B: 'A' }, 5)            // 'ABAABABAABAAB'
expand('F', { F: [[1, 'F+F'], [1, 'F-F']] }, 1, { rng: () => 0.7 })   // 'F-F'
```
--- starter

  let s = axiom;

    for (const [k, v] of Object.entries(rules)) s = s.replaceAll(k, v);
  }
  return s;
}
--- solution
function expand(axiom, rules, n, { maxLength = 1e6, rng } = {}) {
  let s = axiom;
  for (let gen = 0; gen < n; gen++) {
    const parts = [];
    let len = 0;
    for (const ch of s) {
      let out = ch;
      if (Object.hasOwn(rules, ch)) {
        const r = rules[ch];
        if (typeof r === 'string') out = r;
        else {
          if (typeof rng !== 'function') throw new TypeError('stochastic rule needs an rng');
          const total = r.reduce((t, [w]) => t + w, 0);
          const x = rng() * total;
          let acc = 0;
          out = r[r.length - 1][1];
          for (const [w, rep] of r) { acc += w; if (x < acc) { out = rep; break; } }
        }
      }
      len += out.length;
      if (len > maxLength) throw new RangeError(`L-system exceeded ${maxLength} characters`);
      parts.push(out);
    }
    s = parts.join('');
  }
  return s;
}
--- hint
Build each generation from the previous one in a single pass: loop over the old string's characters and collect each replacement into an array, then `join('')` once.
--- hint
Keep a running length while you collect the pieces and throw as soon as it passes `maxLength`. For a stochastic rule, sum the weights, scale `rng()` by the sum, and walk the cumulative weights.
