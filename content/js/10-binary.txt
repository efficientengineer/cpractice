## Why graphics code cares about bytes

Regular JavaScript arrays and objects are flexible and slow in exactly the ways that matter for graphics and procedural generation: each object is a separate heap allocation with a hidden class, an array of objects is an array of pointers, and the garbage collector has to trace all of it. **Typed arrays** are the escape hatch: a contiguous block of raw memory with a fixed element type, just like `float[]` in C# or an array in C. They are how you hold a 2048 by 2048 height field or a million vertices without GC pressure, how you read binary file formats (PNG chunks, glTF buffers, mesh caches), and the *only* way to hand data to the GPU: every WebGPU vertex buffer, uniform buffer and texture upload is an `ArrayBuffer` you filled byte by byte. The WebGPU course on this site assumes this chapter.

## ArrayBuffer and typed arrays

An `ArrayBuffer` is a fixed-length block of bytes. You cannot read it directly; you look at it through a *view*. A typed array is a view that interprets the bytes as elements of one numeric type:

| Type | Element | Bytes | C# equivalent |
|---|---|---|---|
| `Int8Array` / `Uint8Array` | 8-bit integer | 1 | `sbyte` / `byte` |
| `Uint8ClampedArray` | 8-bit, clamps instead of wrapping | 1 | |
| `Int16Array` / `Uint16Array` | 16-bit integer | 2 | `short` / `ushort` |
| `Int32Array` / `Uint32Array` | 32-bit integer | 4 | `int` / `uint` |
| `Float32Array` | 32-bit float | 4 | `float` |
| `Float64Array` | 64-bit float | 8 | `double` |
| `BigInt64Array` / `BigUint64Array` | 64-bit integer, as bigint | 8 | `long` / `ulong` |

```js
const a = new Float32Array(4);                 // 4 zeros, 16 bytes
const b = Uint8Array.from([1, 2, 300, -1]);    // values are converted: 300 wraps to 44, -1 to 255
const c = new Int16Array([1, 2, 3]);
console.log(a, b, c);
console.log(a.length, a.byteLength, Float32Array.BYTES_PER_ELEMENT, a.buffer.byteLength);
a[0] = 0.1; a[7] = 5;                          // out of range writes are silently ignored
console.log(a[0], a[7], a.length);
console.log(c.map(x => x * 1000), Array.from(c, x => x * 100000));
```

Typed arrays have most array methods (`map`, `filter`, `reduce`, `sort`, `indexOf`, `fill`, `set`, `subarray`, `slice`), but a fixed length: no `push`, `pop` or `splice`. Values are converted on write: integer types wrap modulo 2^n (like C# `unchecked`), floats are rounded to the element precision, and `map` returns the *same* typed array type, so results wrap too. `Float32Array` stores single precision, so `0.1` reads back as `0.10000000149011612`; `Math.fround(x)` does the same rounding on a plain number.

Single precision matters in 3D. A float32 has a 24-bit mantissa, so the gap between neighbouring representable values grows with magnitude: near 1 it is about 1e-7, near 100,000 it is about 0.008, and at 10 million it is a whole unit. A vertex far from the origin snaps to that grid, which shows up as jittering geometry and z-fighting when the camera travels far. The standard fix is to keep world positions in doubles on the CPU and upload positions *relative to the camera* (a floating origin).

```js
for (const x of [1, 1000, 100000, 1e7]) {
  console.log(x, Math.fround(x + 0.001) - x);       // what is left of a 1 mm offset in float32
}
```

## Views share memory

Several views can look at the same buffer. Writing through one is visible through the others, which is how you see the bytes of a float, or fill one buffer with mixed types:

```js
const buf = new ArrayBuffer(8);
const f32 = new Float32Array(buf);
const u8 = new Uint8Array(buf);
const u32 = new Uint32Array(buf, 4, 1);         // byteOffset 4, length 1
f32[0] = 1.0;
u32[0] = 0xDEADBEEF;
console.log(u8);                                // 1.0 is 0x3F800000, stored little-endian
console.log(u32[0].toString(16), f32[1]);

const whole = new Uint8Array([10, 20, 30, 40, 50]);
const view = whole.subarray(1, 4);              // shares memory
const copy = whole.slice(1, 4);                 // new buffer
view[0] = 99; copy[1] = 77;
console.log(whole, view, copy);
try { new Float32Array(buf, 2); } catch (e) { console.log(e.name, e.message); }
```

- `subarray` returns a view over the same memory (no copy). `slice` copies. This is the opposite of what the names suggest to many people, so remember it.
- A typed array's `byteOffset` must be a multiple of its element size: a `Float32Array` cannot start at byte 2. Use `DataView` for unaligned access.
- `target.set(source, offset)` copies a whole array in one native call (a `memcpy`), far faster than a loop.

## DataView and endianness

Typed arrays use the **platform's byte order**, which is little-endian on every machine you will meet. File formats and network protocols specify their own order, often big-endian ("network order"). `DataView` reads and writes any type at any byte offset with an explicit endianness, and **defaults to big-endian** when you omit the flag, which is a classic bug:

```js
const dv = new DataView(new ArrayBuffer(12));
dv.setUint32(0, 0x11223344);                  // big-endian (default)
dv.setUint32(4, 0x11223344, true);            // little-endian
dv.setFloat32(8, -2.5, true);
console.log(new Uint8Array(dv.buffer));
console.log(dv.getUint32(4, true).toString(16), dv.getUint32(4).toString(16));
console.log(dv.getUint16(1), dv.getInt8(8 + 3), dv.getFloat32(8, true));
```

`DataView` is the right tool for parsing headers and mixed records. For bulk homogeneous data (a million floats), typed arrays are faster.

## Bitwise operators: 32-bit integer semantics

The bitwise operators convert their operands with **ToInt32**: truncate toward zero, then wrap to a signed 32-bit integer. The result is signed, except for `>>>`, which produces an unsigned 32-bit value.

```js
console.log(5 & 3, 5 | 3, 5 ^ 3, ~5);
console.log(1 << 31, (1 << 31) >>> 0, 1 << 32, 1 << 33);   // shift counts are taken mod 32
console.log(-16 >> 2, -16 >>> 2, -1 >>> 0);
console.log(7.9 | 0, -7.9 | 0, 2 ** 32 + 5 | 0, 3e9 | 0);
console.log(0xFFFFFFFF * 0xFFFFFFFF % 2 ** 32, Math.imul(0xFFFFFFFF, 0xFFFFFFFF));
console.log((255).toString(2).padStart(16, '0'), parseInt('1010', 2), 0b1010, 0xff);
```

- `x | 0` truncates to a signed int32 (only safe for values within ±2^31); `x >>> 0` gives the unsigned 32-bit view of the same bits.
- `>>` is the arithmetic shift (copies the sign bit); `>>>` is the logical shift (fills with zeros). C# has the same pair (`>>` on `int` versus `uint`, or `>>>` since C# 11).
- Multiplying two large 32-bit values with `*` loses low bits (the product exceeds 2^53). `Math.imul` does a true 32-bit multiply; use it in hashes and RNGs.

Bit flags and packed values are the classic use. A mesh's vertex format, the features a shader permutation needs and the "dirty" parts of a scene each fit in one integer, and tests are a single AND. Colours are usually packed too: one 32-bit integer per RGBA pixel.

```js
const ATTR = { POSITION: 1 << 0, NORMAL: 1 << 1, UV: 1 << 2, COLOR: 1 << 3, TANGENT: 1 << 4 };
const meshFormat = ATTR.POSITION | ATTR.NORMAL | ATTR.UV;
const shaderNeeds = ATTR.POSITION | ATTR.UV;
console.log((meshFormat & shaderNeeds) === shaderNeeds, (meshFormat & ATTR.TANGENT) !== 0);

const TEXTURES = 1, MESHES = 2, LIGHTS = 4;
let dirty = 0;
dirty |= TEXTURES | LIGHTS;   // mark
dirty &= ~TEXTURES;           // clear after re-uploading textures
dirty ^= MESHES;              // toggle
console.log(dirty.toString(2), (dirty & LIGHTS) !== 0);

// Packed colour: R in the low byte, so a Uint32Array store writes R, G, B, A bytes in order (little-endian).
const rgba = (r, g, b, a) => (r | g << 8 | b << 16 | a << 24) >>> 0;
const orange = rgba(255, 128, 0, 255);
console.log(orange.toString(16), orange & 255, orange >>> 8 & 255, orange >>> 24);
const pixels = new Uint8ClampedArray(4 * 4);
new Uint32Array(pixels.buffer).fill(orange);          // four pixels in one call
console.log(pixels.subarray(0, 8));
```

> **Performance:** a bitmask test is one instruction and allocates nothing, versus a `Set` of strings (`features.has('normal')`) which hashes a string. Writing a pixel as one `Uint32Array` store is cheaper than four byte stores, and filling an image with `fill` is a native loop. The same goes for packing grid coordinates into one integer key (`y * width + x`) instead of building `` `${x},${y}` `` strings for a `Map`.

### Seeded random numbers

`Math.random()` cannot be seeded, so it cannot reproduce a texture, a terrain or a bug report. Procedural generators use small integer generators instead, seeded from the user's seed and often re-seeded per tile or per chunk from a hash of its coordinates, so any tile can be generated independently and identically. Here is **mulberry32**, a fast, decent-quality 32-bit generator built entirely from the operators above:

```js
function mulberry32(seed) {
  let a = seed >>> 0;
  return function () {
    a = (a + 0x6D2B79F5) | 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;     // [0, 1)
  };
}
const rng = mulberry32(42);
console.log(rng(), rng());
const again = mulberry32(42);
console.log(again(), Math.floor(again() * 6) + 1);     // same sequence: 0.60..., then a die roll
```

## Packing structs into bytes

A GPU vertex buffer, a binary mesh file and a network packet are all arrays of *structs*: fixed-size records laid out at known byte offsets. Say a vertex is a position (3 x `f32`) plus an RGBA colour (4 x `u8`): 12 + 4 = 16 bytes, the **stride**. Two views on one buffer let you write both parts without `DataView` overhead:

```js
const STRIDE = 16;
const verts = [
  { pos: [0, 0.5, 0], rgba: [255, 0, 0, 255] },
  { pos: [-0.5, -0.5, 0], rgba: [0, 255, 0, 255] },
  { pos: [0.5, -0.5, 0], rgba: [0, 0, 255, 128] },
];
const buffer = new ArrayBuffer(verts.length * STRIDE);
const f = new Float32Array(buffer), b = new Uint8Array(buffer);
verts.forEach((v, i) => {
  f.set(v.pos, i * STRIDE / 4);          // float index = byte offset / 4
  b.set(v.rgba, i * STRIDE + 12);        // colour starts at byte 12 of each vertex
});
console.log(buffer.byteLength, Array.from(b.subarray(16, 32)));
```

In WebGPU this layout is described as `arrayStride: 16` with attributes `float32x3` at offset 0 and `unorm8x4` at offset 12, and the whole `buffer` is uploaded with one `device.queue.writeBuffer` call. Uniform buffers add alignment rules (a `vec3<f32>` takes 16 bytes, for example), so you will often see padding fields; the WebGPU course covers them.

## Struct of arrays

For simulation the better layout is often the transpose: instead of an array of particle objects (*array of structs*), keep one typed array per field (*struct of arrays*). A loop that updates positions then streams through contiguous memory, touches only the fields it needs, and allocates nothing:

```js
const MAX = 10000;
const P = {
  count: 0,
  x: new Float32Array(MAX), y: new Float32Array(MAX),
  vx: new Float32Array(MAX), vy: new Float32Array(MAX),
  life: new Float32Array(MAX),
};
function spawn(x, y, vx, vy, life) {
  if (P.count === MAX) return;                 // full: drop it, never grow mid-frame
  const i = P.count++;
  P.x[i] = x; P.y[i] = y; P.vx[i] = vx; P.vy[i] = vy; P.life[i] = life;
}
function update(dt) {
  for (let i = 0; i < P.count; ) {
    P.life[i] -= dt;
    if (P.life[i] <= 0) {                      // swap-remove: move the last particle here
      const last = --P.count;
      P.x[i] = P.x[last]; P.y[i] = P.y[last]; P.vx[i] = P.vx[last]; P.vy[i] = P.vy[last]; P.life[i] = P.life[last];
      continue;                                // re-check index i, it holds a new particle
    }
    P.vy[i] += 9.8 * dt;
    P.x[i] += P.vx[i] * dt;
    P.y[i] += P.vy[i] * dt;
    i++;
  }
}
let seed = 7;
const rand = () => (seed = seed * 16807 % 2147483647) / 2147483647;   // tiny Lehmer RNG
for (let k = 0; k < 5000; k++) spawn(0, 0, rand() * 10 - 5, -rand() * 10, rand() * 4);
const t0 = performance.now();
for (let frame = 0; frame < 120; frame++) update(1 / 60);
console.log('alive after 2s:', P.count, 'time ok:', performance.now() - t0 < 1000);
```

> **Performance:** this is the single most important pattern in this chapter. Bad habits it replaces: `particles.push({ x, y, vx, vy })` per spawn and `particles = particles.filter(p => p.life > 0)` per frame, which allocate an object per particle and a new array per frame and make the collector run constantly. Rules for per-frame code: preallocate at a maximum size, reuse buffers, remove by swapping with the last element (order rarely matters), and keep loops over plain indices. The packed array is also exactly what you upload to the GPU, with no conversion.

## Hex and base64 by hand

Binary data often has to travel as text: hashes as hex, embedded buffers in glTF files and data URLs as base64. Doing it by hand is a good bit-manipulation exercise:

```js
const toHex = bytes => Array.from(bytes, b => b.toString(16).padStart(2, '0')).join('');
console.log(toHex(new Uint8Array([0, 15, 16, 255])));

// base64: every 3 bytes (24 bits) become 4 characters of 6 bits each.
const ALPHA = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/';
function base64Of3(b0, b1, b2) {
  const n = (b0 << 16) | (b1 << 8) | b2;
  return ALPHA[n >> 18 & 63] + ALPHA[n >> 12 & 63] + ALPHA[n >> 6 & 63] + ALPHA[n & 63];
}
console.log(base64Of3(77, 97, 110), btoa('Man'));
```

When the input length is not a multiple of 3, the last group is padded with zero bits and the missing characters are written as `=`. The built-in `btoa`/`atob` work on *strings of Latin-1 characters* (one char per byte), not on bytes or Unicode text, so `btoa('é😀')` throws. Very recent engines add `Uint8Array.prototype.toBase64()` and `Uint8Array.fromBase64()`; until they are everywhere, the hand-written version (or `btoa(String.fromCharCode(...bytes))` for small inputs) is what you use.

## TextEncoder and TextDecoder

Strings are UTF-16 in memory, but files and networks use UTF-8. `TextEncoder` converts a string to UTF-8 bytes; `TextDecoder` goes back (and supports other encodings for decoding):

```js
const enc = new TextEncoder(), dec = new TextDecoder();
const bytes = enc.encode('Hi é 😀');
console.log(bytes.length, 'Hi é 😀'.length, bytes);
console.log(dec.decode(bytes), dec.decode(bytes.subarray(0, 4)));
const scratch = new Uint8Array(64);
const { read, written } = enc.encodeInto('mesh rock_01', scratch);   // no allocation
console.log(read, written, dec.decode(scratch.subarray(0, written)));
try { new TextDecoder('utf-8', { fatal: true }).decode(new Uint8Array([0xFF])); } catch (e) { console.log(e.name); }
console.log(dec.decode(new Uint8Array([0xFF, 0x41])));
```

By default invalid bytes decode to U+FFFD; pass `{ fatal: true }` to throw instead when validating input. `encodeInto` writes into an existing buffer, which is how you write strings into a preallocated network or save buffer without allocating.

## Uint8ClampedArray

`Uint8ClampedArray` stores bytes but **clamps** out-of-range values to 0 or 255 and rounds to nearest (ties to even) instead of wrapping and truncating. It exists for pixels: `ImageData.data` is a `Uint8ClampedArray` of RGBA values, so brightening a pixel by adding 40 saturates at white instead of wrapping to black.

```js
const px = new Uint8ClampedArray([250, 128, 3, 255]);
for (let i = 0; i < 3; i++) px[i] += 40;
console.log(px, new Uint8Array([250 + 40]), Uint8ClampedArray.from([-5, 0.5, 1.5, 2.5, 254.6]));
```

=== exercise bits
title: Bit tricks and packed colours
--- prompt
Write these 32-bit helpers using bitwise operators (no string conversion, no `Math.clz32` for `popcount`):

- `popcount(n)`: the number of set bits in the 32-bit representation of `n` (`popcount(-1)` is 32).
- `lowestBit(n)`: the index (0 to 31) of the lowest set bit, or `-1` if `n` is 0. (`Math.clz32` is allowed here, or a loop.)
- `bitIndices(n)`: an array of the indices of all set bits, ascending (`bitIndices(0b1010)` is `[1, 3]`).
- `rotl(x, k)`: rotate the 32 bits of `x` left by `k` (any `k`, taken mod 32), returning an **unsigned** result.
- `packRGBA(r, g, b, a)`: packs four bytes (0 to 255) into one **unsigned** 32-bit integer with `r` in the lowest byte and `a` in the highest, so storing it into a `Uint32Array` lays the bytes out as R, G, B, A in memory (little-endian).
- `unpackRGBA(c)`: the inverse, returning `[r, g, b, a]`.

}

  return 0;
}

  return [];
}

  return x << k;
}

--- solution
function popcount(n) {
  n = n - ((n >>> 1) & 0x55555555);
  n = (n & 0x33333333) + ((n >>> 2) & 0x33333333);
  n = (n + (n >>> 4)) & 0x0F0F0F0F;
  return Math.imul(n, 0x01010101) >>> 24;
}

function lowestBit(n) {
  n |= 0;
  if (n === 0) return -1;
  return 31 - Math.clz32(n & -n);
}

function bitIndices(n) {
  const out = [];
  n |= 0;
  while (n !== 0) {
    out.push(lowestBit(n));
    n &= n - 1;                 // clear the lowest set bit
  }
  return out;
}

function rotl(x, k) {
  k &= 31;
  return ((x << k) | (x >>> (32 - k))) >>> 0;
}

function packRGBA(r, g, b, a) {
  return (r | (g << 8) | (b << 16) | (a << 24)) >>> 0;
}

function unpackRGBA(c) {
  return [c & 255, (c >>> 8) & 255, (c >>> 16) & 255, c >>> 24];
}
--- hint
`n & -n` isolates the lowest set bit, and `n &= n - 1` clears it. A loop of the second is the simple `popcount` (the solution shows the branch-free SWAR version).
--- hint
For `rotl`, the bits shifted out on the left come back on the right: `(x << k) | (x >>> (32 - k))`. When `k` is 0, `x >>> 32` is `x >>> 0`, which still works because OR-ing `x` with itself is `x`. Finish with `>>> 0`.

=== exercise hashrng
title: A hash and a seeded RNG
--- prompt
Write two classic 32-bit building blocks for procedural generation:

- `fnv1a(str)`: the 32-bit FNV-1a hash of the **UTF-8 bytes** of `str`, as an unsigned integer. Start with `h = 0x811c9dc5`; for each byte, `h ^= byte` then `h *= 0x01000193` (32-bit multiply). Known values: `fnv1a('')` is `2166136261`, `fnv1a('a')` is `3826002220`, `fnv1a('foobar')` is `3214735720`.
- `xorshift32(seed)`: returns a generator function. Each call updates a 32-bit state with `s ^= s << 13; s ^= s >>> 17; s ^= s << 5` and returns the state as an **unsigned** integer. Seed `1` yields `270369, 67634689, 2647435461, 307599695`. A seed of `0` would get stuck at 0, so treat seed 0 as 1. The generator also needs two methods:
  - `.float()`: next value divided by 2^32, in `[0, 1)`;
  - `.int(lo, hi)`: an integer in `[lo, hi]` inclusive, using `Math.floor(float * (hi - lo + 1)) + lo`.

Then `seedFromString(str)` is just `xorshift32(fnv1a(str))`: the same world name always generates the same world.
--- starter
function fnv1a(str) {
  let h = 0x811c9dc5;
  for (let i = 0; i < str.length; i++) {
    h ^= str.charCodeAt(i);
    h *= 0x01000193;
  }
  return h;
}

function xorshift32(seed) {
  const next = () => Math.floor(Math.random() * 2 ** 32);
  next.float = Math.random;
  next.int = (lo, hi) => lo;
  return next;
}

function seedFromString(str) {
  return xorshift32(fnv1a(str));
}
--- solution
const utf8_ = new TextEncoder();

function fnv1a(str) {
  let h = 0x811c9dc5;
  for (const b of utf8_.encode(str)) {
    h ^= b;
    h = Math.imul(h, 0x01000193);
  }
  return h >>> 0;
}

function xorshift32(seed) {
  let s = (seed >>> 0) || 1;
  const next = () => {
    s ^= s << 13;
    s ^= s >>> 17;
    s ^= s << 5;
    return s >>> 0;
  };
  next.float = () => next() / 4294967296;
  next.int = (lo, hi) => Math.floor(next.float() * (hi - lo + 1)) + lo;
  return next;
}

function seedFromString(str) {
  return xorshift32(fnv1a(str));
}
--- hint
Plain `*` on two 32-bit values loses the low bits because the product is beyond 2^53. Use `Math.imul(h, 0x01000193)` and finish with `>>> 0`.
--- hint
Hash UTF-8 bytes, not UTF-16 code units: `new TextEncoder().encode(str)`. Create the encoder once outside the function.

const B64_REV_ = new Int16Array(128).fill(-1);
for (let i = 0; i < 64; i++) B64_REV_[B64_.charCodeAt(i)] = i;

function toHex(bytes) {
  let s = '';
  for (let i = 0; i < bytes.length; i++) s += HEX_[bytes[i]];
  return s;
}

function fromHex(str) {
  if (str.length % 2 || !/^[0-9a-fA-F]*$/.test(str)) throw new SyntaxError('bad hex');
  const out = new Uint8Array(str.length / 2);
  for (let i = 0; i < out.length; i++) out[i] = parseInt(str.substr(i * 2, 2), 16);
  return out;
}

function toBase64(bytes) {
  const parts = [];
  let i = 0;
  for (; i + 2 < bytes.length; i += 3) {
    const n = (bytes[i] << 16) | (bytes[i + 1] << 8) | bytes[i + 2];
    parts.push(B64_[n >> 18 & 63] + B64_[n >> 12 & 63] + B64_[n >> 6 & 63] + B64_[n & 63]);
  }
  const rest = bytes.length - i;
  if (rest === 1) {
    const n = bytes[i] << 16;
    parts.push(B64_[n >> 18 & 63] + B64_[n >> 12 & 63] + '==');
  } else if (rest === 2) {
    const n = (bytes[i] << 16) | (bytes[i + 1] << 8);
    parts.push(B64_[n >> 18 & 63] + B64_[n >> 12 & 63] + B64_[n >> 6 & 63] + '=');
  }
  return parts.join('');
}

function fromBase64(str) {
  if (str.length % 4) throw new SyntaxError('bad base64 length');
  const pad = str.endsWith('==') ? 2 : str.endsWith('=') ? 1 : 0;
  const out = new Uint8Array(str.length / 4 * 3 - pad);
  const val = j => {
    const c = str.charCodeAt(j), v = c < 128 ? B64_REV_[c] : -1;
    if (v < 0) throw new SyntaxError('bad base64 character');
    return v;
  };
  let o = 0;
  for (let i = 0; i < str.length; i += 4) {
    const last = i + 4 === str.length;
    const p = last ? pad : 0;
    const n = (val(i) << 18) | (val(i + 1) << 12) | (p < 2 ? val(i + 2) << 6 : 0) | (p < 1 ? val(i + 3) : 0);
    out[o++] = n >> 16 & 255;
    if (p < 2) out[o++] = n >> 8 & 255;
    if (p < 1) out[o++] = n & 255;
  }
  return out;
}
--- hint
Encoding: take 3 bytes into one 24-bit number `n`, then emit `n >> 18 & 63`, `n >> 12 & 63`, `n >> 6 & 63`, `n & 63` as alphabet characters. Handle the 1 or 2 leftover bytes separately with `=` padding.
--- hint
Decoding: build a reverse lookup table (character code to 6-bit value, `-1` for invalid) once. The output length is `len / 4 * 3` minus the number of `=`. A `=` anywhere but the last one or two positions hits the "invalid character" path naturally.

=== exercise meshfile
title: A binary mesh file
--- prompt
Text formats like OBJ are slow to parse; tools cache meshes in binary. Write `encodeMesh(mesh)` and `decodeMesh(bytes)` for this layout (all values **little-endian**):

| offset | type | field |
|---|---|---|
| 0 | 4 bytes ASCII | magic `'MESH'` |
| 4 | u32 | `n`, the vertex count |
| 8 | u32 | `m`, the index count |
| 12 | `n * 3` x f32 | positions `x, y, z` per vertex |
| 12 + 12n | `m` x u16 **or** u32 | indices: u16 if `n <= 65536`, otherwise u32 |
| end - 4 | u32 | checksum: FNV-1a (as in the hash exercise) of all preceding bytes |

`mesh` is `{ positions, indices }`: `positions` a `Float32Array` (or array) of length `3n`, `indices` any array-like of length `m`. Throw a `RangeError` if `positions.length` or `indices.length` is not a multiple of 3, or if any index is not an integer in `[0, n)`.

`decodeMesh` returns `{ positions: Float32Array, indices: Uint16Array | Uint32Array }` (the index type matching the file) and throws an `Error` if the data is shorter than 16 bytes, the magic is wrong, the length does not match the header, or the checksum fails.

Two things the harness checks: `bytes` may be a `subarray` at an **odd** byte offset of a larger buffer (a `Float32Array` view cannot start there, so copy the bytes first, for example with `slice`), and a 300,000-vertex mesh must encode and decode quickly, so copy the float data in bulk (`Uint8Array.prototype.set` over a byte view of the positions, or `Float32Array.prototype.set`) instead of one `DataView` call per float.
--- starter

--- solution
function fnv1aBytes(bytes) {
  let h = 0x811c9dc5;
  for (let i = 0; i < bytes.length; i++) h = Math.imul(h ^ bytes[i], 0x01000193);
  return h >>> 0;
}

function encodeMesh({ positions, indices }) {
  if (positions.length % 3 || indices.length % 3) throw new RangeError('lengths must be multiples of 3');
  const n = positions.length / 3, m = indices.length;
  for (let i = 0; i < m; i++) {
    const k = indices[i];
    if (!Number.isInteger(k) || k < 0 || k >= n) throw new RangeError(`bad index ${k}`);
  }
  const wide = n > 65536, isz = wide ? 4 : 2;
  const end = 12 + 12 * n + isz * m;
  const out = new Uint8Array(end + 4);
  const dv = new DataView(out.buffer);
  out.set([77, 69, 83, 72], 0);                        // 'MESH'
  dv.setUint32(4, n, true);
  dv.setUint32(8, m, true);
  const pos = positions instanceof Float32Array ? positions : Float32Array.from(positions);
  out.set(new Uint8Array(pos.buffer, pos.byteOffset, n * 12), 12);   // bulk copy (little-endian platform)
  const idx = wide ? Uint32Array.from(indices) : Uint16Array.from(indices);
  out.set(new Uint8Array(idx.buffer, 0, isz * m), 12 + 12 * n);
  dv.setUint32(end, fnv1aBytes(out.subarray(0, end)), true);
  return out;
}

function decodeMesh(bytes) {
  if (bytes.length < 16) throw new Error('too short');
  const b = bytes.slice();                              // aligned private copy
  const dv = new DataView(b.buffer);
  if (b[0] !== 77 || b[1] !== 69 || b[2] !== 83 || b[3] !== 72) throw new Error('bad magic');
  const n = dv.getUint32(4, true), m = dv.getUint32(8, true);
  const wide = n > 65536, isz = wide ? 4 : 2;
  const end = 12 + 12 * n + isz * m;
  if (b.length !== end + 4) throw new Error('bad length');
  if (dv.getUint32(end, true) !== fnv1aBytes(b.subarray(0, end))) throw new Error('bad checksum');
  const positions = new Float32Array(b.buffer, 12, n * 3);
  const ib = b.slice(12 + 12 * n, end).buffer;          // indices may not be 4-aligned in b
  const indices = wide ? new Uint32Array(ib) : new Uint16Array(ib);
  return { positions, indices };
}
--- hint

--- hint
Decode: `bytes.slice()` gives a fresh buffer starting at offset 0, so `new Float32Array(copy.buffer, 12, n * 3)` is aligned. With u32 indices the index block starts at `12 + 12n`, which is a multiple of 4; with u16 indices just use a `slice` of that range.

--- solution
function createParticles(capacity) {
  return {
    capacity, count: 0,
    x: new Float32Array(capacity), y: new Float32Array(capacity),
    vx: new Float32Array(capacity), vy: new Float32Array(capacity),
    life: new Float32Array(capacity),
  };
}

function spawn(p, x, y, vx, vy, life) {
  if (p.count >= p.capacity) return -1;
  const i = p.count++;
  p.x[i] = x; p.y[i] = y; p.vx[i] = vx; p.vy[i] = vy; p.life[i] = life;
  return i;
}

function update(p, dt, gravity) {
  const { x, y, vx, vy, life } = p;
  let i = 0;
  while (i < p.count) {
    life[i] -= dt;
    if (life[i] <= 0) {
      const last = --p.count;
      x[i] = x[last]; y[i] = y[last]; vx[i] = vx[last]; vy[i] = vy[last]; life[i] = life[last];
      continue;
    }
    vy[i] += gravity * dt;
    x[i] += vx[i] * dt;
    y[i] += vy[i] * dt;
    i++;
  }
}

function bounds(p) {
  if (p.count === 0) return null;
  let minX = Infinity, minY = Infinity, maxX = -Infinity, maxY = -Infinity;
  for (let i = 0; i < p.count; i++) {
    const px = p.x[i], py = p.y[i];
    if (px < minX) minX = px;
    if (px > maxX) maxX = px;
    if (py < minY) minY = py;
    if (py > maxY) maxY = py;
  }
  return [minX, minY, maxX, maxY];
}
