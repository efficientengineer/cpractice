title: Types, coercion and errors
blurb: ToPrimitive, + and ==, floating point and BigInt, number parsing traps, Error subclasses, finally, defensive validation.

## Why this chapter exists

C# rejects `"3" * "4"` at compile time. JavaScript evaluates it to `12`, and evaluates `"3" + 4` to `"34"`. None of this is random: the spec has a small number of conversion operations (*ToPrimitive*, *ToNumber*, *ToString*, *ToBoolean*) and every operator is defined in terms of them. Once you know those few rules, the famous "wat" examples become predictable, and more usefully, you can tell at a glance which of your own expressions are safe.

## Seven primitives and one object type

| Type | `typeof` | Notes |
|---|---|---|
| undefined | `'undefined'` | also what `typeof` returns for an undeclared name, without throwing |
| null | `'object'` | a bug from 1995 that can never be fixed |
| boolean | `'boolean'` | |
| number | `'number'` | IEEE 754 double, including `NaN`, `Infinity`, `-0` |
| bigint | `'bigint'` | arbitrary precision integers, `10n` |
| string | `'string'` | immutable UTF-16 sequence |
| symbol | `'symbol'` | unique keys (chapter 11) |
| object | `'object'` or `'function'` | everything else: arrays, dates, maps, class instances |

Primitives have no identity and are compared by value. Objects are compared by reference, exactly like C# reference types. There is no struct-like user type: an object is always a reference.

`typeof` is only good for primitives and "is it callable". For objects use:

```js
const values = [[], {}, new Date(0), /x/, null, new Map()];
for (const v of values) {
  console.log(Array.isArray(v), v instanceof Object, Object.prototype.toString.call(v));
}
```

- `Array.isArray(v)` is the only reliable array test. `v instanceof Array` fails for arrays created in another realm (an iframe or a worker's message is structurally cloned, so that one is fine, but iframes are not).
- `x instanceof C` walks `x`'s prototype chain looking for `C.prototype`. It says nothing about the shape of `x`, and it can be customized with `Symbol.hasInstance`.
- `Object.prototype.toString.call(v)` returns `[object Array]`, `[object Date]`, `[object Null]` and so on; classes can customize it with `Symbol.toStringTag`.

## ToPrimitive: how objects become primitives

When an operator needs a primitive and gets an object, it calls **ToPrimitive(obj, hint)**. The hint is `'number'`, `'string'` or `'default'`:

1. If the object has a `[Symbol.toPrimitive]` method, call it with the hint. Done.
2. Otherwise, for hint `'string'`, try `toString()` then `valueOf()`; for `'number'` and `'default'`, try `valueOf()` then `toString()`. The first one that returns a primitive wins. If neither does, throw a `TypeError`.

Plain objects inherit a `valueOf` that returns the object itself (not a primitive, so it is skipped) and a `toString` that returns `'[object Object]'`. Arrays inherit `toString`, which is `join(',')`. Which hint is used:

| Context | Hint |
|---|---|
| `` `${x}` ``, `String(x)`, property keys `o[x]` | string |
| `-x`, `x * y`, `x < y`, `Number(x)`, `Math.*` | number |
| `x + y`, `x == y` | default (only `Date` treats default as string) |

```js
const price = {
  valueOf() { return 42; },
  toString() { return 'price'; },
};
console.log(price * 2);       // number hint: valueOf
console.log(`${price}`);      // string hint: toString
console.log(price + '!');     // default hint: valueOf, then string concat
console.log(String([1, [2, 3]]), Number([]), Number([7]), Number([1, 2]));
```

## The + operator

`a + b` does ToPrimitive on both sides with the default hint. Then, **if either result is a string, it concatenates** (ToString on both). Otherwise it adds numerically (ToNumber on both, or BigInt addition if both are bigints). Every other arithmetic operator (`- * / % **`) is always numeric.

```js
console.log(1 + 2 + '3');     // (1 + 2) + '3'
console.log('1' + 2 + 3);     // ('1' + 2) + 3
console.log('5' - 2, '5' * '2', true + 1, null + 1, undefined + 1);
console.log([] + [], [1, 2] + [3], {} + []);
console.log(+'', +' 12 ', +'1e3', +'0x1f', +'12px', +[], +null);
```

ToNumber of a string trims whitespace, then accepts decimal, `0x`/`0o`/`0b` literals, `Infinity`, or the empty string (which becomes `0`, a frequent source of bugs with empty form fields). Anything else is `NaN`. `null` becomes `0` but `undefined` becomes `NaN`. Symbols throw. Mixing a bigint and a number in arithmetic throws a `TypeError` rather than silently losing precision.

## == and why you mostly avoid it

`===` compares type and value with no conversion (`NaN !== NaN`, `0 === -0`). `Object.is` is the same except it says `NaN` is `NaN` and `0` is not `-0`; Map and Set keys use that rule (with `-0` normalized to `0`).

`==` (*loose equality*) is this algorithm, in order:

1. Same type: behave like `===`.
2. `null == undefined` is true, and **null and undefined equal nothing else**.
3. Number and string: convert the string with ToNumber.
4. A boolean on either side: convert it to a number (`true` is `1`) and start over. So `'1' == true` is true but `'2' == true` is false.
5. Object and primitive: ToPrimitive (default hint) on the object and start over.
6. Bigint and number or string: compare mathematical values.
7. Otherwise false.

```js
console.log('' == 0, '0' == 0, '' == '0');   // not transitive
console.log(null == 0, null >= 0);           // == has its own null rule; >= uses ToNumber
console.log([] == false, [] ? 'truthy' : 'falsy');
console.log([1, 2] == '1,2', NaN == NaN, 1n == 1);
```

The one idiomatic use: `x == null` is true exactly for `null` and `undefined`. Otherwise use `===`.

## Truthiness, || and ??

The falsy values are `false`, `0`, `-0`, `0n`, `NaN`, `''`, `null` and `undefined`. Everything else is truthy, including `'0'`, `'false'`, `[]` and `{}`. `a || b` returns `a` if it is truthy, so `count || 10` replaces a legitimate `0`. `a ?? b` only replaces `null` and `undefined`, which is almost always what you mean for defaults. `??=`, `||=` and `&&=` assign with the same rules.

```js
const opts = { retries: 0, name: '' };
console.log(opts.retries || 3, opts.retries ?? 3, opts.name || 'anon', opts.name ?? 'anon');
```

## Floating point

`number` is a C# `double`. All the usual IEEE 754 consequences apply, plus a few JavaScript-specific ones:

```js
console.log(0.1 + 0.2, 0.1 + 0.2 === 0.3);
console.log(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON);
console.log((1.005).toFixed(2), (0.5).toFixed(0), (2.5).toFixed(0), Math.round(-2.5));
console.log(Number.MAX_SAFE_INTEGER, 2 ** 53 === 2 ** 53 + 1);
console.log(Number.isSafeInteger(2 ** 53), Number.isInteger(5.0), 1 / 0, -1 / 0, 0 / 0);
console.log(Object.is(-0, 0), -0 === 0, 1 / -0);
```

- `Number.EPSILON` is the gap between `1` and the next double (about `2.2e-16`). It is only a sensible absolute tolerance for values near 1. For general comparisons use a relative tolerance: `Math.abs(a - b) <= rel * Math.max(Math.abs(a), Math.abs(b))`.
- `toFixed` rounds the *actual* binary value: `1.005` is really `1.00499999999999989...`, so it rounds down.
- `Math.round` rounds half toward `+Infinity` (`-2.5` gives `-2`), unlike C#'s banker's rounding default.
- Integers are exact up to `Number.MAX_SAFE_INTEGER` (2^53 - 1). Beyond that, consecutive integers collide. IDs from a database `bigint` column must not pass through `JSON.parse` as numbers.
- For money, store integer cents (or use bigint), and only format with a decimal point at the edges.

## BigInt

```js
const big = 2n ** 64n - 1n;
console.log(big, typeof big, big.toString(16));
console.log(7n / 2n, -7n / 2n, 7n % -2n);          // truncates toward zero
console.log(BigInt(Number.MAX_SAFE_INTEGER) + 2n);
console.log(BigInt.asUintN(8, 257n), BigInt.asIntN(8, 255n));
console.log(1n < 2, 2n > 1.5, 1n === 1);
try { console.log(1n + 1); } catch (e) { console.log(e.name); }
```

Bigints cannot mix with numbers in arithmetic, have no fractional part, are not supported by `Math`, cannot go through `JSON.stringify` (it throws), and are much slower than numbers. Use them for exact integer math (64-bit IDs, factorials, money in cents beyond 2^53) and convert at the boundary with `BigInt(n)` and `Number(b)`. `BigInt(1.5)` throws; `BigInt('0x10')` works.

## Parsing numbers

There are four ways to turn a string into a number and they all disagree:

| Input | `Number(s)` / `+s` | `parseInt(s, 10)` | `parseFloat(s)` |
|---|---|---|---|
| `''` | `0` | `NaN` | `NaN` |
| `'  42  '` | `42` | `42` | `42` |
| `'42px'` | `NaN` | `42` | `42` |
| `'3.9'` | `3.9` | `3` | `3.9` |
| `'0x1A'` | `26` | `0` | `0` |
| `'1e3'` | `1000` | `1` | `1000` |
| `'1_000'` | `NaN` | `1` | `1` |

`parseInt` and `parseFloat` read the longest valid prefix and ignore the rest. `parseInt` first converts its argument to a string, so `parseInt(0.0000005)` is `5` (the string is `'5e-7'`). Always pass the radix: `parseInt(s, 16)`. And never pass `parseInt` straight to `map`, which calls it with `(value, index)`:

```js
console.log(['10', '10', '10'].map(parseInt));
console.log(['10', '10', '10'].map(s => parseInt(s, 10)));
console.log(isNaN('abc'), Number.isNaN('abc'), Number.isFinite('5'), isFinite('5'));
```

The global `isNaN` and `isFinite` coerce first; the `Number.` versions do not and are the ones to use. For user input, the robust approach is to validate the *format* with a regular expression first and only then convert with `Number`.

## Exceptions: throw anything

You can `throw` any value: a string, a number, `undefined`. Library code should only throw `Error` objects, because only they carry a `stack`, and `catch` blocks commonly read `.message`. But your catch blocks must still cope with anything, because other people's code may not follow that rule.

```js
try {
  throw { code: 42 };
} catch (e) {
  console.log(e instanceof Error, e.code);
}
try {
  null.x;
} catch {                         // the binding is optional
  console.log('caught without a name');
}
```

There is only one `catch` per `try`: no `catch (IOException e)` filters. You test inside it and rethrow what you do not handle.

### Error subclasses and cause

```js
class AppError extends Error {
  constructor(message, options) {
    super(message, options);      // options.cause is stored as this.cause
    this.name = new.target.name;  // so String(e) and stacks show the subclass
  }
}
class NotFoundError extends AppError {
  constructor(what, options) {
    super(`${what} not found`, options);
    this.what = what;
  }
}

function loadUser(id) {
  try {
    throw new TypeError('db connection reset');
  } catch (err) {
    throw new NotFoundError(`user ${id}`, { cause: err });
  }
}

try {
  loadUser(7);
} catch (e) {
  if (!(e instanceof AppError)) throw e;
  console.log(String(e));
  console.log(e.what, e instanceof NotFoundError, e instanceof Error);
  console.log('caused by', e.cause.message);
}
```

Without `this.name = ...` the subclass's `name` is inherited from `Error.prototype` and prints as plain `Error`. `cause` (ES2022) is the equivalent of C#'s `InnerException`: always attach it when you wrap. The built-in types worth knowing are `TypeError` (wrong type, calling a non-function), `RangeError` (value out of range), `SyntaxError` (thrown by `JSON.parse`), `ReferenceError` and `AggregateError` (several errors, used by `Promise.any`).

### try/catch/finally

`finally` runs whether the block returned, threw, `break`ed or `continue`d. The surprising part is that **a `return` or `throw` inside `finally` replaces whatever was in flight**, including an exception, which silently disappears. C# forbids `return` in `finally` for exactly this reason; in JavaScript it is legal and a linter rule.

```js
function order() {
  const log = [];
  try {
    log.push('try');
    return log;                   // the value is computed now...
  } finally {
    log.push('finally');          // ...but finally still runs, and mutates it
  }
}
console.log(order());

function swallow() {
  try {
    throw new Error('lost');
  } finally {
    return 'finally wins';        // the exception is discarded
  }
}
console.log(swallow());

function count() {
  let n = 0;
  try { return n; } finally { n = 99; }   // the primitive was already captured
}
console.log(count());
```

## Defensive validation

Coercion means a wrong-typed value rarely crashes where it entered. It travels, gets concatenated or turns into `NaN`, and fails three modules later. The defence is to validate at the boundary (user input, JSON, function arguments of public APIs) and fail fast with a specific error:

```js
function assert(cond, message, ErrorType = TypeError) {
  if (!cond) throw new ErrorType(message);
}
function createRect(w, h) {
  assert(typeof w === 'number' && Number.isFinite(w), `width must be a finite number, got ${typeof w}`);
  assert(Number.isFinite(h), `height must be a finite number`);
  assert(w >= 0 && h >= 0, 'negative size', RangeError);
  return { w, h, area: w * h };
}
console.log(createRect(2, 3));
for (const args of [['2', 3], [2, NaN], [-1, 1]]) {
  try { createRect(...args); } catch (e) { console.log(`${e.name}: ${e.message}`); }
}
```

Inside your own code, trust your types and do not re-check everything everywhere; that is noise. At the edges, check precisely: `Number.isFinite` rather than `typeof x === 'number'` (which accepts `NaN`), `Array.isArray`, `typeof s === 'string'`, and explicit format checks rather than "does it coerce".

=== exercise looseeq
title: Implement ==
--- prompt
Write `looseEquals(a, b)` that returns exactly what `a == b` returns, **without using `==` or `!=`**. You only need to handle `undefined`, `null`, booleans, numbers, strings and objects (arrays, plain objects, objects with custom `valueOf`/`toString`). No bigints or symbols.

The algorithm from the chapter:

1. Same `typeof` (treating `null` separately from objects): use `===`.
2. `null` and `undefined` equal each other and nothing else.
3. A boolean on either side: replace it with its number and repeat.
4. Number and string: convert the string with `Number` and compare.
5. Object and primitive: convert the object with ToPrimitive, default hint (`valueOf` first, then `toString`; the first that returns a primitive wins; otherwise throw `TypeError`), and repeat.
6. Two objects are compared by reference (step 1 covers that).

The harness compares your function to the real `==` over a big matrix of values.
--- starter
function looseEquals(a, b) {
  return a === b;
}
--- solution
function toPrimitive(o) {
  for (const m of ['valueOf', 'toString']) {
    if (typeof o[m] === 'function') {
      const v = o[m]();
      if (v === null || (typeof v !== 'object' && typeof v !== 'function')) return v;
    }
  }
  throw new TypeError('Cannot convert object to primitive value');
}

function looseEquals(a, b) {
  const isObj = x => x !== null && (typeof x === 'object' || typeof x === 'function');
  const isNullish = x => x === null || x === undefined;
  if (isNullish(a) || isNullish(b)) return isNullish(a) && isNullish(b);
  if (typeof a === typeof b) return a === b;
  if (typeof a === 'boolean') return looseEquals(Number(a), b);
  if (typeof b === 'boolean') return looseEquals(a, Number(b));
  if (typeof a === 'number' && typeof b === 'string') return a === Number(b);
  if (typeof a === 'string' && typeof b === 'number') return Number(a) === b;
  if (isObj(a) && !isObj(b)) return looseEquals(toPrimitive(a), b);
  if (isObj(b) && !isObj(a)) return looseEquals(a, toPrimitive(b));
  return false;
}
--- hint
Handle `null`/`undefined` first: if either side is nullish, the answer is "are both nullish". After that, `typeof` never reports `'object'` for `null`, so `typeof a === typeof b` is a safe "same type" test.
--- hint
Write a small `toPrimitive(o)` helper that tries `o.valueOf()` then `o.toString()`, returning the first result that is not an object. Then each remaining rule is one `if` that converts one side and recurses.

Write `approxEqual(a, b, opts)` where `opts` is optional `{ abs, rel }` with defaults `abs = 1e-12` and `rel = 1e-9`. It returns true when:

- both are finite and `|a - b| <= max(abs, rel * max(|a|, |b|))`.

Then write `sumPrices(prices)` that adds an array of prices given as numbers with at most 2 decimal places, and returns the total **rounded to exactly the nearest cent** as a number, so `sumPrices([0.1, 0.2])` is `0.3` and `sumPrices(Array(10).fill(0.1))` is `1`. Do it in integer cents.
--- starter
function approxEqual(a, b, opts) {
  return Math.abs(a - b) < Number.EPSILON;

  return prices.reduce((s, p) => s + p, 0);

--- solution
function approxEqual(a, b, { abs = 1e-12, rel = 1e-9 } = {}) {
  if (a === b) return true;
  if (!Number.isFinite(a) || !Number.isFinite(b)) return false;
  return Math.abs(a - b) <= Math.max(abs, rel * Math.max(Math.abs(a), Math.abs(b)));
}

function sumPrices(prices) {
  const cents = prices.reduce((s, p) => s + Math.round(p * 100), 0);
  return cents / 100;
}

=== exercise decimals
title: Exact decimal sums with BigInt
--- prompt
Floats cannot add `0.1` and `0.2` exactly, and integer cents stop being exact past 2^53. Write `addDecimals(list)` that takes an array of decimal **strings** and returns their exact sum as a string with **exactly two decimal places**.

Each input has an optional leading `-`, at least one digit before the point, and optionally a `.` followed by one or two digits (`'7'`, `'0.1'`, `'-3.25'`). Inputs can be arbitrarily large. Throw a `SyntaxError` for anything else.

```js
addDecimals(['0.1', '0.2'])                     // '0.30'
addDecimals(['90071992547409919.99', '0.01'])   // '90071992547409920.00'
addDecimals(['-5', '1.5'])                      // '-3.50'
addDecimals([])                                 // '0.00'
```

A result of zero is `'0.00'`, never `'-0.00'`. Values between -1 and 0 print as `'-0.50'`.
--- starter
function addDecimals(list) {
  return list.reduce((s, x) => s + Number(x), 0).toFixed(2);
}
--- solution
function addDecimals(list) {
  let total = 0n;
  for (const s of list) {
    const m = typeof s === 'string' && /^(-?)(\d+)(?:\.(\d{1,2}))?$/.exec(s);
    if (!m) throw new SyntaxError(`bad decimal: ${s}`);
    const cents = BigInt(m[2]) * 100n + BigInt((m[3] || '0').padEnd(2, '0'));
    total += m[1] ? -cents : cents;
  }
  const neg = total < 0n;
  const abs = neg ? -total : total;
  const frac = String(abs % 100n).padStart(2, '0');
  return `${neg ? '-' : ''}${abs / 100n}.${frac}`;
}
--- hint
Convert each string to a bigint number of cents: whole part times `100n` plus the fraction padded to two digits (`'5'` means 50 cents, not 5).
--- hint
To format, work with the absolute value: `abs / 100n` is the whole part (bigint division truncates), `abs % 100n` the cents, padded with `padStart(2, '0')`. Add the sign separately so `-0.50` comes out right.

title: An error hierarchy
--- prompt
Build a small error hierarchy and a config loader that uses it.

   - if the result is not a plain object (null, array, number...), throw `ConfigError('config must be an object')`.
   - requires a `port` key (else `MissingKeyError('port')`) that must be an integer from 1 to 65535 (else a `RangeError` with any message), and an optional `host` that defaults to `'localhost'` and must be a non-empty string if present (else a `TypeError`).
   - returns `{ host, port }`.
--- starter
class ConfigError extends Error {}

class MissingKeyError extends ConfigError {}

  return JSON.parse(text);
}
--- solution
class ConfigError extends Error {
  constructor(message, options) {
    super(message, options);
    this.name = new.target.name;
  }
}

class MissingKeyError extends ConfigError {
  constructor(key) {
    super(`missing key: ${key}`);
    this.key = key;
  }
}

function loadConfig(text) {
  let data;
  try {
    data = JSON.parse(text);
  } catch (err) {
    throw new ConfigError('invalid JSON', { cause: err });
  }
  if (data === null || typeof data !== 'object' || Array.isArray(data)) {
    throw new ConfigError('config must be an object');
  }
  if (!('port' in data)) throw new MissingKeyError('port');
  const { port, host = 'localhost' } = data;
  if (!Number.isInteger(port) || port < 1 || port > 65535) throw new RangeError(`bad port: ${port}`);
  if (typeof host !== 'string' || host === '') throw new TypeError('host must be a non-empty string');
  return { host, port };
}
--- hint
`this.name = new.target.name` in the base constructor names every subclass correctly. `super(message, options)` is how `cause` gets stored.
--- hint
Wrap only the `JSON.parse` call in try/catch. Validation errors thrown afterwards must not be caught and re-wrapped as "invalid JSON".

=== exercise cleanups
title: Run every cleanup
--- prompt
Write `runCleanups(fns)`. It calls every function in `fns` in order, **even if some of them throw**. Afterwards:

- if none threw, it returns the number of functions called;
- if exactly one threw, it rethrows that exact value (whatever it was: an `Error`, a string, `undefined`...);
- if several threw, it throws an `AggregateError` whose `errors` array holds the thrown values in order and whose message is `` `${n} cleanups failed` ``.

Then write `withResource(open, use)`: it calls `open()` to get a resource object with a `close()` method, calls `use(resource)` and returns its result, and **always** closes the resource, including when `use` throws. If `use` throws and `close` also throws, the error from `use` must win (it is the interesting one) and the close error is dropped. If `use` succeeds and `close` throws, throw the close error. If `open` throws, there is nothing to close.

Keep an eye on `finally`: a `throw` inside it would replace the error from `use`.
--- starter
function runCleanups(fns) {
  fns.forEach(f => f());
  return fns.length;
}

function withResource(open, use) {
  const r = open();
  const result = use(r);
  r.close();
  return result;
}
--- solution
function runCleanups(fns) {
  const errors = [];
  for (const f of fns) {
    try {
      f();
    } catch (e) {
      errors.push(e);
    }
  }
  if (errors.length === 1) throw errors[0];
  if (errors.length > 1) throw new AggregateError(errors, `${errors.length} cleanups failed`);
  return fns.length;
}

function withResource(open, use) {
  const r = open();
  let result;
  try {
    result = use(r);
  } catch (e) {
    try { r.close(); } catch {}
    throw e;
  }
  r.close();
  return result;
}
--- hint
For `runCleanups`, collect errors in an array inside a loop with try/catch around each call. Decide what to throw only after the loop.
--- hint
For `withResource`, a plain `finally { r.close(); }` is wrong: if `use` threw and `close` throws too, the close error replaces the use error. Handle the two paths separately.
--- harness

  const catchErr = f => { try { f(); } catch (e) { return { e }; } return null; };
  const log = [];
  eq(runCleanups([() => log.push(1), () => log.push(2)]), 2);
  eq(log, [1, 2]);
  eq(runCleanups([]), 0);

  const boom = new Error('boom');
  const calls = [];
  let r = catchErr(() => runCleanups([() => calls.push('a'), () => { throw boom; }, () => calls.push('c')]));
  check(r && r.e === boom, 'single error rethrown as is');
  eq(calls, ['a', 'c'], 'all functions still run');

  r = catchErr(() => runCleanups([() => { throw undefined; }]));
  check(r !== null && r.e === undefined, 'can rethrow undefined');
  r = catchErr(() => runCleanups([() => { throw 'str'; }, () => {}]));
  check(r && r.e === 'str', 'can rethrow a string');

  r = catchErr(() => runCleanups([() => { throw 1; }, () => {}, () => { throw boom; }, () => { throw 3; }]));
  check(r && r.e instanceof AggregateError, 'several errors give AggregateError');

  eq(r && r.e.message, '3 cleanups failed');
