## Changing how the language treats your objects

C# gives you operator overloading, `IEnumerable`, attributes and reflection. JavaScript's equivalents are **symbols** (hooks the language calls on your objects), **property descriptors** (fine control over each property), and **Proxy** (intercepting every operation on an object). They power `for...of` over your own types, reactive UI frameworks, ORMs and test mocks. This chapter covers them, plus modules and the event emitter, the backbone of most game architectures.

## Symbols

A symbol is a unique, immutable primitive used as a property key. Two symbols are never equal, even with the same description, so a symbol key can never clash with anyone else's string keys:

```js
const HP = Symbol('hp');
const enemy = { name: 'orc', [HP]: 30 };
console.log(enemy[HP], HP.toString(), HP.description, Symbol('hp') === HP);
console.log(Object.keys(enemy), JSON.stringify(enemy), Object.getOwnPropertySymbols(enemy));
console.log(Reflect.ownKeys(enemy));
console.log(Symbol.for('app.id') === Symbol.for('app.id'));    // global registry: same symbol
```

Symbol keys are skipped by `Object.keys`, `for...in` and `JSON.stringify`, which makes them good for metadata you want to attach without it showing up in serialized saves. They are *not* private: `Object.getOwnPropertySymbols` and `Reflect.ownKeys` find them.

### Well-known symbols

The language looks up specific symbols on your objects. Implementing them is how you plug into syntax:

| Symbol | Used by |
|---|---|
| `Symbol.iterator` | `for...of`, spread, destructuring, `Array.from`, `new Map(x)` |
| `Symbol.asyncIterator` | `for await...of` |
| `Symbol.toPrimitive` | every conversion to a primitive (chapter 07's ToPrimitive) |
| `Symbol.toStringTag` | `Object.prototype.toString` output |
| `Symbol.hasInstance` | `instanceof` |

```js
class Inventory {
  #items = [];
  add(name, qty) { this.#items.push({ name, qty }); return this; }
  *[Symbol.iterator]() {                         // a generator method
    for (const it of this.#items) if (it.qty > 0) yield it.name;
  }
  get [Symbol.toStringTag]() { return 'Inventory'; }
}
const inv = new Inventory().add('sword', 1).add('potion', 0).add('rope', 3);
console.log([...inv], Object.prototype.toString.call(inv));
for (const name of inv) console.log('has', name);

class Gold {
  constructor(amount) { this.amount = amount; }
  [Symbol.toPrimitive](hint) {
    if (hint === 'number') return this.amount;
    return `${this.amount}g`;                   // 'string' and 'default'
  }
}
const purse = new Gold(250);
console.log(`${purse}`, +purse, purse * 2, purse + '!', purse > 100);
```

`Symbol.asyncIterator` does the same for asynchronous sequences: network messages, streamed level chunks, a queue of input events. An `async *` generator method implements it:

```js
class WaveSpawner {
  constructor(waves, delayMs) { this.waves = waves; this.delayMs = delayMs; }
  async *[Symbol.asyncIterator]() {
    for (const [i, count] of this.waves.entries()) {
      await new Promise(r => setTimeout(r, this.delayMs));
      yield { wave: i + 1, enemies: count };
    }
  }
}
for await (const w of new WaveSpawner([3, 5, 8], 10)) console.log(w);
```

## Property descriptors

Every property is either a **data property** (`value`, `writable`) or an **accessor property** (`get`, `set`), and both kinds have `enumerable` (shows up in `Object.keys`, `for...in`, spread and JSON) and `configurable` (can be deleted or redefined). Properties created by assignment have every flag `true`; properties created by `Object.defineProperty` default every flag to **`false`**:

```js
const cfg = { gravity: 9.8 };
Object.defineProperty(cfg, 'VERSION', { value: 3 });               // read-only, hidden, permanent
Object.defineProperty(cfg, 'gravityFt', {
  get() { return this.gravity * 3.281; },
  enumerable: true,
});
cfg.VERSION = 4;                                                    // ignored (throws in strict mode)
console.log(cfg, cfg.VERSION, cfg.gravityFt.toFixed(2), JSON.stringify(cfg));
console.log(Object.getOwnPropertyDescriptor(cfg, 'VERSION'));
console.log(Object.getOwnPropertyDescriptor(cfg, 'gravity'));
```

`Object.preventExtensions` stops new properties, `Object.seal` also makes all properties non-configurable, and `Object.freeze` also makes them non-writable. All three are shallow.

### Getters on prototypes

A `get` in a class body defines an accessor on the **prototype**, shared by all instances, not an own property. That is why such properties do not appear in `Object.keys`, spread or JSON, a common surprise when serializing class instances:

```js
class Unit {
  constructor(hp, maxHp) { this.hp = hp; this.maxHp = maxHp; }
  get alive() { return this.hp > 0; }
  get ratio() { return this.hp / this.maxHp; }
}
const u = new Unit(15, 60);
console.log(u.alive, u.ratio, Object.keys(u), { ...u }, 'ratio' in u, Object.hasOwn(u, 'ratio'));
console.log(Object.getOwnPropertyNames(Unit.prototype));
```

A **lazy getter** computes an expensive value on first access and then replaces itself with a plain data property on the instance, so later reads cost nothing:

```js
class Level {
  constructor(tiles) { this.tiles = tiles; }
  get walkable() {
    console.log('computing walkable tiles');
    const value = this.tiles.filter(t => t !== '#').length;
    Object.defineProperty(this, 'walkable', { value, enumerable: true });
    return value;
  }
}
const lvl = new Level([...'..#..##.']);
console.log(lvl.walkable, lvl.walkable, Object.keys(lvl));
```

> **Performance:** engines optimize property access by giving objects with the same keys, added in the same order, a shared hidden class (a *shape*). Code that sees one shape at a property access site is fast; code that sees many is slow. So in hot paths: initialize every field in the constructor (even to `null` or `0`) instead of adding fields later, never `delete` a property from an object you keep using (set it to `undefined` or `null`), and avoid `defineProperty` on per-frame objects. The lazy getter above changes the instance's shape once, which is fine for a level, not for a bullet.

## Proxy and Reflect

`new Proxy(target, handler)` creates an object whose fundamental operations are routed to *traps* on the handler: `get`, `set`, `has` (`in`), `deleteProperty`, `ownKeys` (`Object.keys`, `for...in`), `getOwnPropertyDescriptor`, `defineProperty`, `apply` and `construct` (for function targets), and a few more. Any trap you omit forwards to the target. `Reflect` has one function per trap with the same signature, which is the correct way to do "the default behaviour" inside a trap:

```js
const log = [];
const target = { hp: 10 };
const traced = new Proxy(target, {
  get(t, key, receiver) { log.push(`get ${String(key)}`); return Reflect.get(t, key, receiver); },
  set(t, key, value, receiver) { log.push(`set ${String(key)}=${value}`); return Reflect.set(t, key, value, receiver); },
  has(t, key) { log.push(`has ${String(key)}`); return Reflect.has(t, key); },
});
traced.hp -= 3;
console.log('mp' in traced, target.hp, log);
```

A `set` trap must return `true` for success; returning `false` makes the assignment throw a `TypeError` in strict mode (and silently fail in sloppy mode). Traps must also respect *invariants*: for example, `get` cannot report a different value for a non-writable, non-configurable property of the target.

### Defaults and negative indices

```js
const withDefault = (obj, fallback) => new Proxy(obj, {
  get: (t, k, r) => (k in t ? Reflect.get(t, k, r) : fallback),
});
const keyBindings = withDefault({ jump: 'Space', fire: 'KeyJ' }, 'Unbound');
console.log(keyBindings.jump, keyBindings.dash);

const wrapAround = arr => new Proxy(arr, {
  get(t, k, r) {
    if (typeof k === 'string' && /^-\d+$/.test(k)) k = String(t.length + Number(k));
    return Reflect.get(t, k, r);
  },
});
const path = wrapAround(['start', 'bridge', 'cave', 'boss']);
console.log(path[-1], path[-2], path[0], path.length, path.slice(1, 2));
```

Property keys reaching a trap are always strings or symbols: `path[-1]` arrives as the string `'-1'`. Note that `arr.at(-1)` exists now, so this particular proxy is a demonstration rather than a need.

### Validation and observation

A proxy can enforce rules on every write, or report every change. This is the core of Vue's reactivity system and of many UI state stores:

```js
function observe(target, onChange) {
  return new Proxy(target, {
    set(t, key, value, r) {
      const old = t[key];
      const ok = Reflect.set(t, key, value, r);
      if (ok && !Object.is(old, value)) onChange(key, value, old);
      return ok;
    },
    deleteProperty(t, key) {
      const had = key in t, old = t[key];
      const ok = Reflect.deleteProperty(t, key);
      if (ok && had) onChange(key, undefined, old);
      return ok;
    },
  });
}
const hud = observe({ hp: 100, ammo: 12 }, (k, v, old) => console.log(`redraw ${k}: ${old} -> ${v}`));
hud.hp -= 25;
hud.ammo = 12;            // same value: no redraw
hud.ammo--;
delete hud.ammo;
```

> **Performance:** every operation on a proxy is a function call into your trap, plus a `Reflect` call, and engines cannot inline-cache through a proxy the way they do for plain objects. Proxy property access is commonly 10 to 100 times slower. Never put a proxy in a per-frame hot path (entity positions, particle data, the physics loop). Use them where operations are rare and the convenience is high: UI and HUD state, settings, editor tooling, debug instrumentation, validation of data at load time. The observable HUD above is fine because it fires on a handful of changes per second, and it lets you redraw only what changed instead of everything every frame.

## WeakMap for private data

Before `#private` fields (chapter 04), the standard way to keep per-instance private state was a module-level `WeakMap` keyed by the instance. It is still the right tool when you need to attach data to objects **you do not own** (DOM nodes, other libraries' objects, entities from another system) without modifying them and without leaking memory:

```js
const physics = new WeakMap();             // entity -> body; entries die with their entity
function attachBody(entity, mass) { physics.set(entity, { mass, vx: 0, vy: 0 }); }
function push(entity, fx) { const b = physics.get(entity); b.vx += fx / b.mass; }

let crate = { name: 'crate' };
attachBody(crate, 4);
push(crate, 10);
console.log(crate, physics.get(crate), physics.has({ name: 'crate' }));
crate = null;                              // the body becomes garbage too: no leak
```

A `Map` here would keep every entity alive forever. `WeakMap` keys must be objects (or non-registered symbols), the map is not iterable and has no `size`: you can only look up by a key you already hold. `WeakRef` and `FinalizationRegistry` exist for caches that should not keep values alive, but their timing is unpredictable; avoid building game logic on them.

> **Performance:** a `WeakMap` lookup is a hash lookup, noticeably slower than reading a field. For your own classes prefer `#private` fields, which are as fast as normal properties. Keep `WeakMap` side tables for cold paths and for objects you cannot add fields to.

## Modules: ESM and CommonJS

The examples on this site run as the body of one function, so they cannot use `import` or `export` statements. You will use modules everywhere else, so here is the model. Listings in this section are plain text, not runnable.

**ES modules** (ESM, the standard, `<script type="module">`, `.mjs`, or `"type": "module"` in `package.json`):

```text
// vec.js
export const ZERO = Object.freeze({ x: 0, y: 0 });
export let created = 0;
export function vec(x, y) { created++; return { x, y }; }
export default class Vec2 { /* ... */ }

// main.js
import Vec2, { vec, created, ZERO as origin } from './vec.js';
vec(1, 2);
console.log(created);        // 1: a live binding, not a copy
created = 5;                 // TypeError: imports are read-only views
```

- Imports and exports are **static** declarations, resolved before any code runs. That is what lets bundlers tree-shake unused exports and lets the browser fetch the whole dependency graph in parallel.
- An imported name is a **live binding** to the exporting module's variable: when `vec.js` increments `created`, every importer sees the new value. Importers cannot assign to it.
- Each module is evaluated **once** and is a singleton; every importer shares the same instance. Modules are always strict mode, have their own top-level scope (no accidental globals), and support top-level `await`.
- `import()` is the **dynamic** form: an expression returning a promise of the module namespace. Use it to lazy-load code: `const { loadBoss } = await import('./levels/boss.js')` only when the player reaches the boss. It also works in the runner here, for URLs it can fetch.

**CommonJS** (Node's original system: `require`, `module.exports`):

```text
// counter.js
let count = 0;
module.exports = { count, inc() { count++; } };

// main.js
const { count, inc } = require('./counter');
inc();
console.log(count);          // 0: destructuring copied the value at require time
```

- `require` is an ordinary synchronous function call that runs the file (once, then caches it) and returns its `module.exports` object. Exports are **values**, not bindings: copying a primitive out of the object freezes it at that moment.
- Because `require` is dynamic and synchronous, tools cannot reliably analyze it, browsers cannot load it without a bundler, and it cannot `await` at the top level.
- Modern Node supports both. ESM can import CommonJS (you get `module.exports` as the default export); CommonJS can `require` ESM only in recent Node versions. New code should be ESM.

Circular imports work in both systems but differently: in ESM, a binding that has not been initialized yet throws a `ReferenceError` (temporal dead zone) if used too early; in CommonJS you silently get a partially filled `exports` object.

## structuredClone

`structuredClone(value)` makes a deep copy using the same algorithm as `postMessage` to a worker. It handles cycles and shared references, `Map`, `Set`, `Date`, `RegExp`, typed arrays and `ArrayBuffer`, and errors. It does **not** copy functions (it throws a `DataCloneError`), symbols-as-keys, getters (they are read and stored as values), or prototypes: a class instance comes back as a plain object.

```js
class Hero { constructor() { this.hp = 30; this.bag = new Map([['gold', 12]]); } heal() { this.hp = 30; } }
const save = { hero: new Hero(), seen: new Set([1, 4]), at: new Date(0), grid: new Uint8Array([1, 0, 1]) };
save.self = save;
const snap = structuredClone(save);
snap.hero.bag.set('gold', 0);
console.log(save.hero.bag.get('gold'), snap.self === snap, snap.at instanceof Date, snap.grid);
console.log(snap.hero instanceof Hero, typeof snap.hero.heal);
console.log(JSON.parse(JSON.stringify({ m: new Map([[1, 2]]), d: new Date(0), u: undefined })));
try { structuredClone({ onHit() {} }); } catch (e) { console.log(e.name); }
```

`JSON.parse(JSON.stringify(x))` is the old trick, and it is worse: it loses `Map`, `Set` and `undefined`, turns dates into strings, and throws on cycles. For save games, a better design is an explicit `toJSON`/`fromJSON` pair per class, so the format is stable across versions; `structuredClone` is great for snapshots in memory (undo, rewind, "restart level").

> **Performance:** a deep clone is proportional to the size of what you clone. Cloning the whole world state each frame for rewind is a lot of garbage; record the *changes* (commands, chapter 12) or copy into preallocated typed arrays instead.

## The event emitter pattern

An event emitter decouples the code that notices something (the player died, a coin was collected) from the code that reacts (play a sound, update the HUD, unlock an achievement). It is the observer pattern, like C# `event`s, but keyed by name:

```js
class Emitter {
  #handlers = new Map();               // event name -> array of listeners
  on(event, fn) {
    if (!this.#handlers.has(event)) this.#handlers.set(event, []);
    this.#handlers.get(event).push(fn);
    return () => this.off(event, fn);  // return an unsubscribe function
  }
  off(event, fn) {
    const list = this.#handlers.get(event);
    if (list) this.#handlers.set(event, list.filter(f => f !== fn));
  }
  emit(event, ...args) {
    for (const fn of this.#handlers.get(event) ?? []) fn(...args);
  }
}
const events = new Emitter();
const stopSound = events.on('coin', n => console.log('play coin.wav x' + n));
events.on('coin', n => console.log('score +' + n * 10));
events.emit('coin', 2);
stopSound();
events.emit('coin', 1);
events.emit('nobody-listens');
```

Details that separate a robust emitter from a buggy one, which you will handle in the exercise: a listener that removes itself (or adds another) during `emit` must not break the loop, which is why `off` above replaces the array instead of splicing it; `once` listeners; and one throwing listener should not stop the others. Browsers also have a built-in `EventTarget` class (with `addEventListener`, `dispatchEvent` and `CustomEvent`) you can extend; a hand-written emitter is simpler and faster for game events.

> **Performance:** emitting allocates nothing in the loop above, but `emit(event, ...args)` creates a rest array per call, and `on` in a frame loop leaks listeners. Subscribe once at setup, keep a handle to unsubscribe, and do not emit per entity per frame (thousands of events); emit on *changes* (a death, a pickup), and let systems poll or iterate arrays for continuous state.

=== exercise tilemap
title: An iterable tile map
--- prompt
Write a `TileMap` class that plugs into the language through well-known symbols.

- `new TileMap(width, height, fill = '.')` creates the map; `get(x, y)` returns the tile or `undefined` out of bounds; `set(x, y, tile)` sets it (ignore out of bounds) and returns `this`. Store tiles in one flat array, index `y * width + x`.
- `[Symbol.iterator]` yields `[x, y, tile]` for every cell in row-major order (row 0 left to right, then row 1...).
- `*cells(tile)` is a generator yielding `[x, y]` for each cell equal to `tile`.
- `[Symbol.toPrimitive](hint)`: for `'number'`, the count of cells that differ from the fill tile; otherwise (string and default) the rows joined with `'\n'`.
- `[Symbol.toStringTag]` is `'TileMap'`, so `Object.prototype.toString.call(map)` is `'[object TileMap]'`.
- `static [Symbol.hasInstance](x)`: anything with numeric `width` and `height` and a `get` function counts as a `TileMap` for `instanceof` (duck typing).
--- starter
class TileMap {
  constructor(width, height, fill = '.') {
    this.width = width;
    this.height = height;
  }
  get(x, y) {}
  set(x, y, tile) { return this; }
}
--- solution
class TileMap {
  constructor(width, height, fill = '.') {
    this.width = width;
    this.height = height;
    this.fill = fill;
    this.tiles = new Array(width * height).fill(fill);
  }
  inBounds(x, y) { return x >= 0 && y >= 0 && x < this.width && y < this.height; }
  get(x, y) { return this.inBounds(x, y) ? this.tiles[y * this.width + x] : undefined; }
  set(x, y, tile) {
    if (this.inBounds(x, y)) this.tiles[y * this.width + x] = tile;
    return this;
  }
  *[Symbol.iterator]() {
    for (let y = 0; y < this.height; y++)
      for (let x = 0; x < this.width; x++) yield [x, y, this.tiles[y * this.width + x]];
  }
  *cells(tile) {
    for (const [x, y, t] of this) if (t === tile) yield [x, y];
  }
  [Symbol.toPrimitive](hint) {
    if (hint === 'number') return this.tiles.filter(t => t !== this.fill).length;
    const rows = [];
    for (let y = 0; y < this.height; y++) rows.push(this.tiles.slice(y * this.width, (y + 1) * this.width).join(''));
    return rows.join('\n');
  }
  get [Symbol.toStringTag]() { return 'TileMap'; }
  static [Symbol.hasInstance](x) {
    return x != null && typeof x.width === 'number' && typeof x.height === 'number' && typeof x.get === 'function';
  }
}
--- hint
Generator methods are written `*[Symbol.iterator]() { ... }` in a class body. `cells` can iterate `this` with `for...of`, reusing the iterator you just wrote.
--- hint
`static [Symbol.hasInstance](x)` replaces the normal prototype check for `x instanceof TileMap`, so real instances must also pass your duck-typing test.
--- harness
{
  const m = new TileMap(4, 3);
  eq(m.get(0, 0), '.'); eq(m.get(4, 0), undefined); eq(m.get(-1, 0), undefined); eq(m.get(0, 3), undefined);
  check(m.set(1, 0, '#').set(3, 2, '@').set(9, 9, 'X') === m, 'set chains');
  eq(m.get(1, 0), '#'); eq(m.get(3, 2), '@');
  const all = [...m];
  eq(all.length, 12);
  eq(all[0], [0, 0, '.']); eq(all[1], [1, 0, '#']); eq(all[4], [0, 1, '.']); eq(all[11], [3, 2, '@']);
  eq([...m.cells('#')], [[1, 0]]);
  eq([...m.cells('.')].length, 10);
  eq([...m.cells('Z')], []);
  eq(`${m}`, '.#..\n....\n...@');
  eq(String(m), '.#..\n....\n...@');
  eq(m + '', '.#..\n....\n...@', 'default hint is the string form');
  eq(+m, 2); eq(m * 10, 20);
  eq(Object.prototype.toString.call(m), '[object TileMap]');

  check(!({ width: 1 } instanceof TileMap), 'missing members');

=== exercise stats
title: Validated stats with a Proxy
--- prompt
Write `createStats(schema)` which returns a proxy-backed object for a character's stats. `schema` maps each stat name to `{ min, max, int }` (`int` optional, default `false`).

- Every stat starts at its `min`.
- Setting a stat to a value that is not a finite number throws a `TypeError`. If `int` is true and the value is not an integer, also `TypeError`.
- Values outside `[min, max]` are **clamped** (not rejected): `hp = 150` with max 100 stores 100.
- Setting a key that is not in the schema throws a `TypeError` (catches typos like `stats.hpp = 3`).
- Deleting any property throws a `TypeError`.
- Reading an unknown key throws a `ReferenceError` (string keys only; symbol reads such as `Symbol.toPrimitive` must pass through quietly, returning `undefined` if absent).
- `Object.keys(stats)`, `JSON.stringify(stats)` and `'hp' in stats` work normally.

The `set` and `deleteProperty` traps must **throw** themselves, not return `false`, so the errors happen in sloppy mode too.
--- starter
function createStats(schema) {
  const data = {};
  for (const k of Object.keys(schema)) data[k] = schema[k].min;
  return data;
}
--- solution
function createStats(schema) {
  const data = {};
  for (const k of Object.keys(schema)) data[k] = schema[k].min;
  return new Proxy(data, {
    get(t, k, r) {
      if (typeof k === 'string' && !(k in schema) && !(k in t) && k !== 'toJSON') {
        throw new ReferenceError(`unknown stat: ${k}`);
      }
      return Reflect.get(t, k, r);
    },
    set(t, k, v) {
      if (!Object.hasOwn(schema, k)) throw new TypeError(`unknown stat: ${String(k)}`);
      const { min, max, int = false } = schema[k];
      if (typeof v !== 'number' || !Number.isFinite(v)) throw new TypeError(`${k} must be a finite number`);
      if (int && !Number.isInteger(v)) throw new TypeError(`${k} must be an integer`);
      t[k] = Math.min(max, Math.max(min, v));
      return true;
    },
    deleteProperty(t, k) {
      throw new TypeError(`cannot delete ${String(k)}`);
    },
  });
}
--- hint
The `get` trap must allow inherited names that the runtime or other code look up: `k in t` is true for `toString`, `hasOwnProperty` and so on, because `t` inherits them. `JSON.stringify` also looks up `toJSON`, which must not throw.
--- hint
Check the schema with `Object.hasOwn(schema, k)` in `set`, so a key like `toString` or `__proto__` is not accepted as a stat.
--- harness
{
  const s = createStats({ hp: { min: 0, max: 100, int: true }, speed: { min: 0.5, max: 5 }, level: { min: 1, max: 99, int: true } });
  eq(s.hp, 0); eq(s.speed, 0.5); eq(s.level, 1);
  s.hp = 40; eq(s.hp, 40);
  s.hp += 100; eq(s.hp, 100, 'clamped to max');
  s.hp -= 500; eq(s.hp, 0, 'clamped to min');
  s.speed = 2.25; eq(s.speed, 2.25, 'non-int stat accepts fractions');
  throws(() => { s.hp = 1.5; }, 'int stat rejects fraction');
  throws(() => { s.hp = '50'; }, 'string rejected');
  throws(() => { s.speed = NaN; }, 'NaN rejected');
  throws(() => { s.speed = Infinity; }, 'Infinity rejected');
  throws(() => { s.hpp = 3; }, 'unknown key rejected');
  throws(() => { s.toString = 3; }, 'inherited name is not a stat');
  throws(() => { delete s.hp; }, 'delete rejected');
  throws(() => s.mana, 'unknown read');
  const errOf = f => { try { f(); } catch (e) { return e; } };
  check(errOf(() => s.mana) instanceof ReferenceError, 'ReferenceError for unknown read');
  check(errOf(() => { s.hp = 'x'; }) instanceof TypeError, 'TypeError for bad value');

title: A deep observable store for the HUD
--- prompt
Write `observable(target, onChange)` that returns a proxy which reports every change anywhere inside `target`, including nested objects and arrays. `onChange(path, value, oldValue)` receives the path as an array of keys (array indices as strings, like proxies see them), for example `['player', 'inventory', '0']`.

- `delete` notifies with `value` `undefined`, only if the key existed.
- Array methods work and notify: `push` reports the new index and then `length`; assigning `length` reports `length`.
- If you assign a proxy you got from this store, store the **raw** object underneath, not the proxy (keep a second `WeakMap` from proxy to raw).
- A nested object that is shared at two paths reports the path it was read through.
--- starter

    },

--- solution
function observable(target, onChange) {
  const toRaw = new WeakMap();                      // proxy -> raw
  const cache = new WeakMap();                      // raw -> Map(pathKey -> proxy)
  function wrap(obj, path) {
    const key = path.join('\u0000');
    let byPath = cache.get(obj);
    if (!byPath) cache.set(obj, byPath = new Map());
    if (byPath.has(key)) return byPath.get(key);
    const p = new Proxy(obj, {
      get(t, k, r) {
        const v = Reflect.get(t, k, r);
        return v !== null && typeof v === 'object' && typeof k === 'string' ? wrap(v, [...path, k]) : v;
      },
      set(t, k, v, r) {
        if (toRaw.has(v)) v = toRaw.get(v);
        const had = Object.hasOwn(t, k), old = t[k];
        const ok = Reflect.set(t, k, v);
        if (ok && (!had || !Object.is(old, v))) onChange([...path, k], v, old);
        return ok;
      },
      deleteProperty(t, k) {
        const had = Object.hasOwn(t, k), old = t[k];
        const ok = Reflect.deleteProperty(t, k);
        if (ok && had) onChange([...path, k], undefined, old);
        return ok;
      },
    });
    toRaw.set(p, obj);
    byPath.set(key, p);
    return p;
  }
  return wrap(target, []);
}

When `length` is set to its current value (which happens inside `push` after the element is added), `Object.is` says nothing changed, so check the old length carefully: compare against the value before *your* `Reflect.set`.

title: Lazy and hidden properties
--- prompt
Write three helpers with `Object.defineProperty`:

- `hidden(obj, name, value)`: adds a property that is writable but **not enumerable** and not configurable (it will not show up in `Object.keys`, spread or JSON, so it will not end up in a save file). Returns `obj`.

  return obj;

function constant(obj, name, value) {
  obj[name] = value;
  return obj;

  return obj;

--- solution
function hidden(obj, name, value) {
  return Object.defineProperty(obj, name, { value, writable: true, enumerable: false, configurable: false });
}

function constant(obj, name, value) {
  return Object.defineProperty(obj, name, { value, writable: false, enumerable: true, configurable: false });
}

function lazy(obj, name, compute) {
  return Object.defineProperty(obj, name, {
    get() {
      const value = compute.call(this);
      Object.defineProperty(this, name, { value, writable: false, enumerable: true, configurable: false });
      return value;
    },
    enumerable: true,
    configurable: true,
  });
}

  Object.defineProperty(Class.prototype, name, {
    get() {
      const value = compute.call(this);
      Object.defineProperty(this, name, { value, writable: false, enumerable: true, configurable: false });
      return value;
    },
    enumerable: false,
    configurable: true,
  });
}

=== exercise emitter
title: A robust event emitter
--- prompt
Write a `class Emitter` for game events with:

- `on(event, fn)`: subscribe; returns an unsubscribe function. The same function may be subscribed twice and is then called twice.
- `once(event, fn)`: like `on`, but the listener is removed before it is called the first time. Its unsubscribe function works before it fires. `off(event, fn)` with the original `fn` also removes a `once` listener.
- `off(event, fn)`: removes **one** subscription of `fn` (the earliest).
- `emit(event, ...args)`: calls the listeners in subscription order with `args` and `this` set to the emitter, and returns `true` if there were any listeners, else `false`. Listeners added during an emit are **not** called in that emit; listeners removed during an emit (and not yet called) are **not** called. If a listener throws, the others still run, and afterwards `emit` rethrows the first error.
- `listenerCount(event)`.

Store listeners in a private field or a `WeakMap`: `Object.keys(new Emitter())` must be `[]`.
--- starter
class Emitter {
  constructor() { this.handlers = {}; }
  on(event, fn) { (this.handlers[event] ||= []).push(fn); }
  off(event, fn) {}
  once(event, fn) {}
  emit(event, ...args) { for (const f of this.handlers[event] || []) f(...args); }
  listenerCount(event) { return 0; }
}
--- solution
class Emitter {
  #map = new Map();                       // event -> array of { fn, once, active }

  #add(event, fn, once) {
    if (typeof fn !== 'function') throw new TypeError('listener must be a function');
    const entry = { fn, once, active: true };
    const list = this.#map.get(event) ?? [];
    this.#map.set(event, [...list, entry]);
    return () => this.#remove(event, entry);
  }
  #remove(event, entry) {
    const list = this.#map.get(event);
    if (!list || !list.includes(entry)) return;
    entry.active = false;
    const next = list.filter(e => e !== entry);
    if (next.length) this.#map.set(event, next); else this.#map.delete(event);
  }

  on(event, fn) { return this.#add(event, fn, false); }
  once(event, fn) { return this.#add(event, fn, true); }
  off(event, fn) {
    const entry = (this.#map.get(event) ?? []).find(e => e.fn === fn);
    if (entry) this.#remove(event, entry);
  }
  emit(event, ...args) {
    const list = this.#map.get(event);
    if (!list) return false;
    let error = null, failed = false;
    for (const entry of list) {               // a snapshot: on/off replace the array
      if (!entry.active) continue;
      if (entry.once) this.#remove(event, entry);
      try { entry.fn.apply(this, args); }
      catch (e) { if (!failed) { failed = true; error = e; } }
    }
    if (failed) throw error;
    return true;
  }
  listenerCount(event) { return this.#map.get(event)?.length ?? 0; }
}
--- hint
Wrap each subscription in a small entry object `{ fn, once, active }`. Unsubscribing marks it inactive and removes it, so the identity of the entry (not of `fn`) is what the unsubscribe function closes over.
--- hint
Never mutate the array while emitting: `on`/`off` build a new array. `emit` iterates the old array and skips entries whose `active` flag became false during the loop.
--- harness

=== exercise asyncqueue
title: An async event queue
--- prompt
Network messages and input events arrive whenever they like; game systems want to consume them in order. Write a class `AsyncQueue` that is **async iterable**:

- `push(item)` adds an item. If a consumer is waiting, it receives the item immediately.
- `close()` ends the stream: consumers finish their `for await` loop once the buffered items are drained. Pushing after `close` throws an `Error`.
- `[Symbol.asyncIterator]()` returns an iterator whose `next()` resolves to `{ value, done }`. Several `next()` calls may be pending at once (several consumers); they receive items in the order they asked.
- `size` (a getter) is the number of buffered, unconsumed items.
- Breaking out of a `for await` loop (which calls the iterator's `return()`) must not close the queue for other consumers.

Do not poll with timers: resolve waiting consumers directly from `push` and `close`.
--- starter
class AsyncQueue {
  constructor() { this.items = []; }
  push(item) { this.items.push(item); }
  close() {}
  get size() { return this.items.length; }
  [Symbol.asyncIterator]() {
    return { next: async () => ({ value: undefined, done: true }) };
  }
}
--- solution
class AsyncQueue {
  #items = [];
  #waiting = [];
  #closed = false;

  push(item) {
    if (this.#closed) throw new Error('queue is closed');
    const w = this.#waiting.shift();
    if (w) w({ value: item, done: false });
    else this.#items.push(item);
  }
  close() {
    this.#closed = true;
    for (const w of this.#waiting.splice(0)) w({ value: undefined, done: true });
  }
  get size() { return this.#items.length; }

  [Symbol.asyncIterator]() {
    return {
      next: () => {
        if (this.#items.length) return Promise.resolve({ value: this.#items.shift(), done: false });
        if (this.#closed) return Promise.resolve({ value: undefined, done: true });
        return new Promise(resolve => this.#waiting.push(resolve));
      },
      return: () => Promise.resolve({ value: undefined, done: true }),
      [Symbol.asyncIterator]() { return this; },
    };
  }
}
--- hint
Keep two arrays: buffered items, and `resolve` functions of consumers waiting for an item. `push` hands the item to the first waiter if there is one, else buffers it.
--- hint
`next()` returns `Promise.resolve(...)` when an item is buffered or the queue is closed, and otherwise a new promise whose `resolve` is stored in the waiters list. `close()` resolves every waiter with `{ done: true }`.

A class getter lives on the prototype. Assigning to an accessor without a setter does nothing in sloppy mode (it throws in strict mode); it does not create an own property. Spread and `Object.keys` only see own enumerable properties.
