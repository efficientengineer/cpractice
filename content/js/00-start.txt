## What you are walking back into

You have written JavaScript before, and you know C#. This course assumes both and goes for depth: the parts of JavaScript that a C# brain gets subtly wrong, and the modern features (ES2015 to ES2025) that changed how idiomatic code looks.

The examples lean towards graphics and procedural generation: pixels and colors, vectors, seeded random numbers, hash functions, meshes, height fields. **Performance** notes point out habits that matter when code runs once per pixel (a 1024x1024 texture is a million calls) or once per frame (16.7 ms at 60 fps), where every allocation is future work for the garbage collector. The point is to learn the cheap way first rather than unlearn the expensive way later.

The headline differences from C#:

| | C# | JavaScript |
|---|---|---|
| Typing | static, nominal | dynamic; values have types, variables don't |
| Numbers | `int`, `long`, `double`, `decimal`... | one `number` type (a 64-bit double), plus `bigint` |
| Objects | instances of classes | bags of properties linked to a *prototype* |
| Functions | methods, delegates, lambdas | first-class objects; closures everywhere |
| `this` | always the instance | decided by *how a function is called* |
| Concurrency | threads, `Task`, `async/await` | one thread, an event loop, promises, `async/await` |
| Null | `null` (and `Nullable<T>`) | both `null` and `undefined` |
| Equality | `==` is usually what you want | `===`; `==` does type coercion |

## How this site runs your code

Your code runs in your own browser, inside a **Web Worker**. There is no DOM (`document`, `window`) and no Node APIs (`require`, `fs`, `process`). What you do get:

- `console.log` output appears in the output pane, formatted like Node's: strings inside arrays and objects are single quoted, objects print as `{ a: 1 }`, maps as `Map(1) { 'k' => 1 }`.
- Your whole program is the body of an **`async` function**. That means top-level `await` works, and `return` at the top level is legal (it ends the program).
- `import`/`export` statements are not allowed (it is not a module). Dynamic `import('https://...')` works in principle but no course code needs it.
- The *result* of a run (what tests and quizzes compare) is the output printed before that async body finishes. The worker stays alive afterwards, so timers and `requestAnimationFrame` loops keep running and their output streams in late, until you press Run again. In test runs, anything after the body ends doesn't count: `await` what you want checked.
- Code that mentions `canvas` gets a 512x512 `OffscreenCanvas`: `canvas.getContext('2d')` and `ctx.putImageData(...)` show a procedural texture you computed into a pixel array. There are also input globals (`keys`, a `Set` of held key codes, and `mouse`, `{ x, y, down }`) for interactive demos. This course mostly sticks to logic and tests; the graphics tracks use the canvas heavily.
- The body runs in *sloppy mode* (not strict), like an old-fashioned script. Real modules and class bodies are always strict. Where the difference shows, the course says so; put `'use strict';` as the very first line to get strict semantics.
- There is a 5 second timeout, so infinite loops die instead of hanging the tab.

```js
console.log('hello', 42, [1, 'two', { three: 3 }]);
console.log(new Map([['k', 1]]), new Set([1, 2]));

// top-level await works because the program is an async function body
await new Promise(resolve => setTimeout(resolve, 100));
console.log('100 ms later');

setTimeout(() => console.log('printed late, after the run "finished"'), 1000);
// the body ends here; the worker lives on and the timer still fires
```

There are two kinds of exercise:

- **Function** exercises: write one or more functions. Hidden test code (you can view it) is appended after yours in the same scope and calls them with `eq(got, want)` (deep equality), `check(cond)`, `near(a, b)`, `throws(fn)`. Don't name your own things `eq`, `check` and so on.
- **Program** exercises: whatever your program logs must match the expected output exactly.

**Ctrl+Enter** runs, **Ctrl+Shift+Enter** checks against the tests.

## let, const, var

Use `const` by default, `let` when you reassign, and `var` never (but you must be able to read it).

| | scope | hoisted? | redeclare | before declaration |
|---|---|---|---|---|
| `var` | function | yes, initialized to `undefined` | allowed | reads `undefined` |
| `let` | block | yes, but uninitialized | error | `ReferenceError` (TDZ) |
| `const` | block | yes, but uninitialized | error | `ReferenceError` (TDZ) |

`const` means the *binding* can't be reassigned, not that the value is immutable. A `const` array can still be pushed to; it's like a C# `readonly` field holding a reference, not like an immutable type.

```js
const list = [1, 2];
list.push(3);          // fine: mutating the object
console.log(list);
try { list = []; } catch (e) { console.log(e.name, '-', e.message); }

if (true) {
  var leaky = 'var ignores blocks';
  let tight = 'let respects blocks';
}
console.log(leaky);
console.log(typeof tight);   // 'undefined': not in scope here
```

### The temporal dead zone

`let` and `const` declarations *are* hoisted to the top of their block, but the variable stays uninitialized until execution reaches the declaration. Touching it in between, the *temporal dead zone*, throws. This is better than `var`'s silent `undefined`, and it can bite in a way `var` never did: an inner declaration shadows an outer one for the *whole* block, including lines above it.

```js
console.log(v);   // undefined: var is hoisted and initialized
var v = 1;

try {
  console.log(t);
  let t = 2;
} catch (e) { console.log(e.name); }

const x = 'outer';
{
  try {
    console.log(x);       // which x? the inner one, still in its TDZ
  } catch (e) { console.log('TDZ:', e.message); }
  const x = 'inner';
}
```

Even `typeof`, normally safe on undeclared names, throws inside a TDZ.

## Values and types

JavaScript has seven **primitive** types and one non-primitive:

| `typeof` | type | notes |
|---|---|---|
| `'undefined'` | `undefined` | missing value: unassigned variable, absent property, no `return` |
| `'object'` | `null` | "intentionally empty". `typeof null` is a 1995 bug kept forever |
| `'boolean'` | `true`, `false` | |
| `'number'` | 64-bit IEEE 754 double | `42`, `3.14`, `NaN`, `Infinity`, `-0` |
| `'bigint'` | arbitrary-precision integer | `42n` |
| `'string'` | immutable UTF-16 sequence | `'a'`, `"a"`, `` `a` `` |
| `'symbol'` | unique identity token | `Symbol('id')` |
| `'object'` / `'function'` | everything else | objects, arrays, functions, dates, maps... |

Primitives are immutable and compared by value. Objects are mutable and compared by reference (like C# reference types: two arrays with the same contents are not `===`).

```js
console.log(typeof undefined, typeof null, typeof 1, typeof 1n, typeof 'x');
console.log(typeof Symbol(), typeof {}, typeof [], typeof (() => 1));
console.log(Array.isArray([]), [1] === [1], 'ab' === 'a' + 'b');

const s = 'hello';
s[0] = 'J';        // silently ignored (throws in strict mode): strings are immutable
console.log(s, s.toUpperCase(), s);
```

Methods on primitives work because the engine temporarily wraps the primitive (`'x'.length` uses a `String` wrapper). Never write `new String('x')` or `new Number(1)` yourself: wrapper objects are objects, so `new Number(0)` is truthy and `new String('a') !== 'a'`.

## == vs ===

`===` (strict equality) compares type and value with no conversion. `==` (loose equality) converts operands first, with rules few people remember: `'' == 0`, `'0' == 0`, but `'' != '0'`; `[] == false`; `null == undefined` but `null != 0`.

**Use `===` and `!==` always.** The one widely accepted exception is `x == null`, which is true exactly when `x` is `null` or `undefined`.

```js
console.log('' == 0, '0' == 0, '' == '0');
console.log([] == false, [0] == false, null == undefined, null == 0);
console.log(NaN === NaN, Object.is(NaN, NaN), 0 === -0, Object.is(0, -0));
```

`Object.is` is "same value": like `===` except that `NaN` equals itself and `+0` differs from `-0`. `Map`, `Set` and `includes` use a variant (SameValueZero) where `NaN` matches `NaN` but `0` matches `-0`.

## Truthiness

Exactly these values are **falsy**: `false`, `0`, `-0`, `0n`, `NaN`, `''`, `null`, `undefined`. Everything else is truthy, including `'0'`, `'false'`, `[]`, `{}`, and `new Boolean(false)`.

C# makes you write `if (list.Count > 0)`. JavaScript lets you write `if (list.length)`, which is fine; but `if (count)` when `count` can legitimately be `0` is a classic bug.

`&&` and `||` don't return booleans; they return one of their operands:

```js
console.log(0 || 'default', '' || 'default', 'x' || 'default');
console.log(1 && 'second', 0 && 'second', null && x.boom);
console.log(!!'0', !![], !!'', Boolean(NaN));
```

## Numbers

Every `number` is a double. There is no integer type, so integer arithmetic is exact only up to 2^53 (`Number.MAX_SAFE_INTEGER`, 9007199254740991). Beyond that, consecutive integers can't all be represented.

```js
console.log(7 / 2, Math.trunc(7 / 2), Math.floor(-7 / 2), -7 % 2);
console.log(0.1 + 0.2, 0.1 + 0.2 === 0.3, Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON);
console.log(Number.MAX_SAFE_INTEGER, 2 ** 53 === 2 ** 53 + 1);
console.log(2n ** 64n, 7n / 2n, typeof 10n);
console.log(1 / 0, -1 / 0, 0 / 0);
```

- Division is always floating point. Use `Math.trunc` for C#-style integer division (`Math.floor` differs for negatives).
- `%` is remainder with the sign of the left operand, as in C#.
- `bigint` is exact for any size but can't mix with `number` (`1n + 1` throws) and has no fractional part.
- Bitwise operators (`|`, `&`, `<<`, `>>`, `~`) convert to **32-bit signed integers**. `x | 0` truncates to int32, and `>>> 0` reinterprets as unsigned. Values above 2^31 wrap.

> **Performance:** engines don't really store every number as a double. Small integers (31-bit on V8, "Smis") live unboxed in the value itself and integer arithmetic stays on fast paths; doubles that escape into objects may be *boxed* on the heap. Keeping hot values integral (pixel coordinates, indexes, hash states) and not mixing `undefined` or strings into numeric arrays keeps arrays in their fast "packed numbers" mode. For bulk numeric data (the RGBA bytes of a texture, the positions of 100,000 vertices) use typed arrays like `Uint8ClampedArray` and `Float32Array`: contiguous, fixed type, no boxing, and exactly what canvas and WebGPU consume. They get their own chapter.

### Integer hashing: Math.imul and >>> 0

Procedural generation runs on **deterministic** randomness: the same seed and coordinates must always give the same value, so a texture or terrain can be regenerated, tiled, or computed in any order. That's done with integer hash functions, which need 32-bit multiplication that wraps like C's `uint32_t`. Plain `*` on doubles doesn't wrap (it loses low bits once the product passes 2^53), so use `Math.imul(a, b)` (32-bit wrapping multiply) and `>>> 0` (reinterpret as unsigned):

```js
// A small 2D integer hash: same inputs, same output, on every machine
function hash2(x, y, seed) {
  let h = Math.imul(x, 0x27d4eb2d) ^ Math.imul(y, 0x165667b1) ^ seed;
  h = Math.imul(h ^ (h >>> 15), 0x2c1b3c6d);
  h = Math.imul(h ^ (h >>> 12), 0x297a2d39);
  return (h ^ (h >>> 15)) >>> 0;               // unsigned 32-bit
}
const toUnit = h => h / 4294967296;             // map to [0, 1)
console.log(hash2(0, 0, 1), hash2(1, 0, 1), hash2(0, 0, 1) === hash2(0, 0, 1));
console.log(toUnit(hash2(10, 20, 42)).toFixed(4));
console.log(0x7fffffff * 0x7fffffff, Math.imul(0x7fffffff, 0x7fffffff));
```

`Math.random()` is the opposite: unseeded and unrepeatable. Use it for nothing that must look the same twice.

### NaN

`NaN` ("not a number") comes out of failed math: `0/0`, `Math.sqrt(-1)`, `Number('abc')`, `undefined + 1`. It is the only value not equal to itself, and it spreads through every operation it touches.

```js
const n = Number('12px');
console.log(n, n === NaN, Number.isNaN(n), isNaN('hello'), Number.isNaN('hello'));
console.log(parseInt('12px'), parseFloat('3.5e2kg'), Number(''), Number(' 42 '), +'0x1f');
console.log(parseInt('08'), parseInt('ff', 16), (255).toString(2), (3.14159).toFixed(2));
```

Prefer `Number.isNaN` and `Number.isFinite` (no coercion) over the global `isNaN`/`isFinite` (which coerce strings first). `Number(s)` is strict about the whole string but treats `''` as `0`; `parseInt` reads a prefix and stops. Always pass `parseInt` a radix if the input isn't trusted.

## Strings and template literals

Strings are immutable sequences of UTF-16 code units, as in C#. Single and double quotes are equivalent. Backtick **template literals** interpolate any expression, can span lines, and can be *tagged* (passed to a function, covered later).

```js
const name = 'Ada', items = 3, price = 4.5;
console.log(`${name} bought ${items} items for $${(items * price).toFixed(2)}`);
console.log(`multi
line`);
console.log('abc'.at(-1), 'abc'.slice(1), 'a,b,,c'.split(','), 'x'.padStart(3, '.'));
console.log('Hello'.includes('ell'), 'Hello'.startsWith('He'), '  trim me '.trim() + '|');
console.log('ab'.repeat(3), 'a-b-c'.replaceAll('-', '+'), 'é'.length, '😀'.length, [...'😀'].length);
```

`+` with a string on either side concatenates: `1 + '2'` is `'12'`, but `'3' * '4'` is `12` because `*` only does numbers. `length` counts UTF-16 code units, so an emoji is 2; `[...str]` iterates by code point.

> **Performance:** every template literal or `+` concatenation creates a new string. A debug overlay that rebuilds `` `fps ${fps.toFixed(1)}` `` every frame is cheap; building a string per *pixel* or per *vertex* is not. Never use string keys like `` `${x},${y}` `` for lookups in a per-pixel loop: compute a numeric index `y * width + x` instead. And never build image data as text (`'rgb(' + r + ...`) when you can write bytes into a typed array.

## Optional chaining and nullish coalescing

`?.` short-circuits to `undefined` when the left side is `null` or `undefined`, exactly like C#'s `?.`. It works for properties, indexes and calls:

```js
const user = { profile: { tags: ['admin'] }, greet() { return 'hi'; } };
const nobody = null;
console.log(user.profile?.tags?.[0], nobody?.profile.tags, user.missing?.deep.deeper);
console.log(user.greet?.(), user.nope?.(), nobody?.greet());
```

`??` returns the right side only when the left is `null` or `undefined`, like C#'s `??`. Contrast with `||`, which also replaces `0`, `''`, `false` and `NaN`:

```js
const settings = { volume: 0, title: '', retries: null };
console.log(settings.volume || 50, settings.volume ?? 50);
console.log(settings.title || 'Untitled', settings.title ?? 'Untitled');
console.log(settings.retries ?? 3, settings.missing ?? 'none');

settings.retries ??= 5;      // assign only if null/undefined
settings.volume ||= 10;      // assign if falsy
settings.title &&= settings.title.trim();
console.log(settings);
```

You can't mix `??` with `||` or `&&` without parentheses; it's a syntax error, on purpose.

## C# to JavaScript cheat sheet

| C# | JavaScript |
|---|---|
| `var x = 1;` / `int x = 1;` | `let x = 1;` (or `const`) |
| `readonly` local | `const` |
| `string.Format` / `$"{x}"` | `` `${x}` `` |
| `x is null` | `x === null` (or `x == null` for null or undefined) |
| `a ?? b`, `a?.b`, `a ??= b` | same |
| `(int)(a / b)` | `Math.trunc(a / b)` |
| `long` | `number` up to 2^53, else `bigint` (`10n`) |
| `List<T>` | `Array` |
| `Dictionary<K,V>` | `Map` (or a plain object for string keys) |
| `HashSet<T>` | `Set` |
| `x => x * 2` (lambda) | `x => x * 2` (arrow function) |
| `Func<int,int> f` | any function value |
| LINQ `Select`/`Where`/`Aggregate` | `map`/`filter`/`reduce` |
| `foreach (var x in xs)` | `for (const x of xs)` |
| `Task<T>`, `async`/`await` | `Promise<T>`, `async`/`await` |
| `throw new Exception("x")` | `throw new Error('x')` |
| `default(T)` | `undefined` |
| `nameof`, generics, interfaces | nothing at runtime (TypeScript adds types) |

Watch out for `for (const k in obj)`: `for...in` iterates *keys* (as strings, including inherited ones). For arrays you almost always want `for...of`.

=== exercise toInt
title: Strict integer parsing
--- prompt
Write `parseIntStrict(s)` that returns the integer a string represents, or `null` if it isn't a valid decimal integer.

Rules: optional surrounding whitespace is allowed; an optional leading `+` or `-`; then one or more digits `0`-`9`, and nothing else. The result must be a safe integer (`Number.isSafeInteger`), else return `null`. `'-0'` returns `0` (not `-0`).

```js
parseIntStrict(' 42 ')   // 42
parseIntStrict('12px')   // null   (parseInt would say 12)
parseIntStrict('')       // null   (Number would say 0)
parseIntStrict('1e3')    // null   (Number would say 1000)
parseIntStrict('0x10')   // null
```
--- starter
function parseIntStrict(s) {
  return parseInt(s);
}
--- solution
function parseIntStrict(s) {
  const t = s.trim();
  if (!/^[+-]?\d+$/.test(t)) return null;
  const n = Number(t);
  if (!Number.isSafeInteger(n)) return null;
  return n === 0 ? 0 : n;
}
--- hint
A regular expression like `/^[+-]?\d+$/` checks the shape after `trim()`. Then `Number(t)` converts it.
--- hint
`Number.isSafeInteger(9007199254740993)` is false. `-0 === 0` is true, so `n === 0 ? 0 : n` normalizes the sign.
--- harness
eq(parseIntStrict('42'), 42);
eq(parseIntStrict(' 42 '), 42);
eq(parseIntStrict('\t-17\n'), -17);
eq(parseIntStrict('+5'), 5);
eq(parseIntStrict('007'), 7);
eq(parseIntStrict('-0'), 0, '-0 should become 0');
eq(parseIntStrict('12px'), null);
eq(parseIntStrict(''), null);
eq(parseIntStrict('   '), null);
eq(parseIntStrict('1e3'), null);
eq(parseIntStrict('0x10'), null);
eq(parseIntStrict('3.0'), null);
eq(parseIntStrict('1 2'), null);
eq(parseIntStrict('+-1'), null);
eq(parseIntStrict('-'), null);
eq(parseIntStrict('Infinity'), null);

=== exercise intdiv
title: Integer math with doubles
--- prompt
JavaScript has no integer division, and texture and grid code needs it constantly. Write two functions that work on integer-valued numbers:

- `idiv(a, b)`: division truncated toward zero, like C# `a / b` on ints. Throw an `Error` if `b` is `0`.
- `mod(a, b)`: the mathematical modulo, always in `[0, |b|)`, so `mod(-1, 5)` is `4` (C#'s and JS's `%` give `-1`). This is *wrap* addressing for tileable textures: sampling column `-1` of a 5-pixel-wide texture must read column `4`, so the pattern repeats seamlessly in both directions.

Make sure neither ever returns `-0`.
--- starter
function idiv(a, b) {
  return a / b;
}

function mod(a, b) {
  return a % b;
}
--- solution
function idiv(a, b) {
  if (b === 0) throw new Error('division by zero');
  return Math.trunc(a / b) + 0;
}

function mod(a, b) {
  const m = Math.abs(b);
  return ((a % m) + m) % m + 0;
}
--- hint
`Math.trunc` rounds toward zero; `Math.floor` rounds toward negative infinity.
--- hint
`((a % m) + m) % m` maps any remainder into `[0, m)`. Adding `0` turns `-0` into `0` (`-0 + 0` is `0`).
--- harness
eq(idiv(7, 2), 3);
eq(idiv(-7, 2), -3);
eq(idiv(7, -2), -3);
eq(idiv(-7, -2), 3);
eq(idiv(1, 3), 0);
eq(idiv(-1, 3), 0, 'no -0');
eq(idiv(0, -5), 0, 'no -0');
throws(() => idiv(1, 0), 'idiv by zero should throw');
eq(mod(7, 5), 2);
eq(mod(-1, 5), 4);
eq(mod(-5, 5), 0, 'no -0');
eq(mod(-10, 3), 2);
eq(mod(10, -3), 1);
eq(mod(-7, -3), 2);
eq(mod(0, 4), 0);

=== exercise getPath
title: Safe deep property access
--- prompt
Scene and material files come in as loosely structured JSON. Write `getPath(obj, path, fallback)` where `path` is a dotted string like `'material.layers.0.color'`. Walk the path one key at a time and return the value found. If any step hits `null` or `undefined` (including the final value), return `fallback`.

Only `null`/`undefined` count as missing: a final value of `0`, `''` or `false` is returned as is. An empty path returns `obj` itself (or `fallback` if `obj` is nullish). Array indexes are just keys (`arr['0']` works).

```js
const scene = { material: { name: 'marble', layers: ['base', 'veins'], roughness: 0 } };
getPath(scene, 'material.layers.1')            // 'veins'
getPath(scene, 'material.roughness', 0.5)      // 0
getPath(scene, 'material.normalMap.url', '')   // ''
```

> **Performance:** splitting a path string is fine for loading a scene once. Don't do lookups like this per vertex or per pixel: parsing strings in a hot loop is pure overhead compared to `mat.roughness`. Resolve the path once, keep the result in a local, then loop.
--- starter
function getPath(obj, path, fallback) {
  // walk the path
}
--- solution
function getPath(obj, path, fallback) {
  const keys = path === '' ? [] : path.split('.');
  let cur = obj;
  for (const k of keys) {
    if (cur == null) return fallback;
    cur = cur[k];
  }
  return cur ?? fallback;
}
--- hint
Split on `'.'`, then loop: `cur = cur[key]`, bailing out with `fallback` as soon as `cur == null`.
--- hint
`''.split('.')` is `['']`, not `[]`; handle the empty path first.
--- harness

=== exercise prng
title: An integer hash for procedural noise
--- prompt
Procedural textures need a function from integer coordinates to a random-looking but **deterministic** value. Implement the well-known *lowbias32* integer hash:

```text
x ^= x >>> 16
x  = x * 0x7feb352d      (32-bit wrapping multiply)
x ^= x >>> 15
x  = x * 0x846ca68b      (32-bit wrapping multiply)
x ^= x >>> 16
return x as an unsigned 32-bit integer
```

- `hashInt(x)` takes any integer (negative ones included; treat it as its 32-bit two's complement pattern) and returns an integer in `[0, 2^32)`.
- `valueAt(x, y, seed)` returns `hashInt(x + hashInt(y + hashInt(seed))) / 2^32`, a value in `[0, 1)`. This is "value noise" before smoothing: one random value per lattice point.

The starter uses `*`, which looks right but isn't: the products exceed 2^53, so low bits are lost to double rounding. The tests compare against an exact BigInt reference.
--- starter
function hashInt(x) {
  x ^= x >>> 16;
  x = x * 0x7feb352d;
  x ^= x >>> 15;
  x = x * 0x846ca68b;
  x ^= x >>> 16;
  return x;
}

function valueAt(x, y, seed) {
  return hashInt(x + hashInt(y + hashInt(seed))) / 4294967296;
}
--- solution
function hashInt(x) {
  x ^= x >>> 16;
  x = Math.imul(x, 0x7feb352d);
  x ^= x >>> 15;
  x = Math.imul(x, 0x846ca68b);
  x ^= x >>> 16;
  return x >>> 0;
}

function valueAt(x, y, seed) {
  return hashInt(x + hashInt(y + hashInt(seed))) / 4294967296;
}
--- hint
`Math.imul(a, b)` multiplies as 32-bit integers and keeps the low 32 bits, exactly like C's `uint32_t` multiply.
--- hint
`^` and `>>>` produce signed and unsigned 32-bit results respectively. Finish with `>>> 0` so the result is never negative.
--- harness
{
  const M = 0xffffffffn;
  const ref = (x) => {
    let v = BigInt.asUintN(32, BigInt(x));
    v ^= v >> 16n; v = (v * 0x7feb352dn) & M;
    v ^= v >> 15n; v = (v * 0x846ca68bn) & M;
    v ^= v >> 16n;
    return Number(v);
  };
  for (const x of [0, 1, 2, 3, 42, 255, 65535, 65536, 123456789, 2147483647, -1, -2, -123456, 4294967295]) {
    eq(hashInt(x), ref(x), 'hashInt(' + x + ')');
  }
  let ok = true;
  for (let x = -500; x < 500; x++) if (hashInt(x * 7919) !== ref(x * 7919)) ok = false;
  check(ok, 'hashInt matches the reference on 1000 inputs');
  check(hashInt(-1) >= 0, 'unsigned result');
  const refVal = (x, y, s) => ref(x + ref(y + ref(s))) / 4294967296;
  for (const [x, y, s] of [[0, 0, 0], [1, 2, 3], [-5, 7, 42], [100, -100, 1337], [65535, 65536, 7]]) {
    eq(valueAt(x, y, s), refVal(x, y, s), `valueAt(${x}, ${y}, ${s})`);
  }
  let inRange = true;
  for (let i = 0; i < 2000; i++) { const v = valueAt(i, i * 3, 9); if (!(v >= 0 && v < 1)) inRange = false; }
  check(inRange, 'values in [0, 1)');
  eq(valueAt(3, 4, 5), valueAt(3, 4, 5), 'deterministic');
  check(valueAt(3, 4, 5) !== valueAt(3, 4, 6), 'seed changes the value');
}
