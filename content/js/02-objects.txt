## Objects are property bags

A JavaScript object is a collection of properties: string (or symbol) keys mapped to values. There's no class required, no fixed shape, and you can add or delete properties at any time. Think `Dictionary<string, object>` with nicer syntax, plus a link to a *prototype* (the classes chapter).

```js
const material = {
  name: 'marble',
  roughness: 0.3,
  'base color': [0.9, 0.9, 0.85],     // any string works as a key if quoted
  42: 'answer',                       // number keys become strings
  describe() { return `${this.name} (roughness ${this.roughness})`; },   // method shorthand
};
material.metallic = 0;                // add
delete material[42];                  // remove (but see the performance note below)
console.log(material.name, material['base color'], material.describe());
console.log('metallic' in material, material.missing, Object.keys(material));
```

Dot access needs a valid identifier; bracket access takes any expression. Reading a missing property gives `undefined` (no exception, unlike a C# dictionary indexer), which is why typos produce `undefined` instead of errors.

### Shapes: how engines make objects fast

Under the hood, V8, SpiderMonkey and JavaScriptCore give every object a hidden *shape* (also called a hidden class or map): the list of its property names in order. Objects created the same way share a shape, and code like `e.x += e.vx` gets compiled into "load from offset 0, offset 2", almost like a C# struct field access. That fast path, an *inline cache*, holds as long as the objects flowing through a piece of code have one shape (monomorphic) or a few.

> **Performance:** keep hot objects shape-stable. Create every field up front in the same order, even if it starts as `null` or `0` (`{ x, y, z, nx: 0, ny: 0, nz: 0, uv: null }`), instead of adding `uv` later on some vertices. Never `delete` a property from a hot object: it typically drops the object into slow "dictionary mode". Set it to `null` or `undefined` instead. Don't mix types in one field (`weight` sometimes a number, sometimes a string). And don't use plain objects as dynamic dictionaries with keys you add and remove constantly (like a cache from id to mesh): that's what `Map` is for. Better still, for a hundred thousand vertices don't use one object each at all: a `Float32Array` of packed `x, y, z` triples is a fraction of the memory and is what the GPU wants anyway.

### Shorthand and computed keys

```js
const x = 3, y = 4, field = 'color';
const point = { x, y };                         // same as { x: x, y: y }
const styled = { [field]: 'red', [`${field}Alt`]: 'blue', [1 + 1]: 'two' };
console.log(point, styled);

// Common pattern: build a lookup from a dynamic key
const counts = {};
for (const w of 'the cat and the hat'.split(' ')) counts[w] = (counts[w] ?? 0) + 1;
console.log(counts);
```

### Property order

Keys come out in a defined order: integer-like keys first in ascending numeric order, then string keys in insertion order, then symbols. That surprises people who use objects as ordered maps with numeric-looking keys; use a `Map` when order matters.

```js
console.log(Object.keys({ b: 1, 10: 1, a: 1, 2: 1, '-1': 1, '01': 1 }));
```

## Destructuring

Destructuring pulls values out of objects (and arrays) into variables. C# has deconstruction for tuples and records; JavaScript's version is more flexible and is used everywhere, especially in parameter lists.

```js
const config = { host: 'localhost', port: 8080, db: { name: 'app', pool: { max: 10 } } };

const { host, port } = config;                         // pick properties
const { host: h, port: p = 80 } = config;              // rename, default
const { timeout = 5000 } = config;                     // default for missing
const { db: { name: dbName, pool: { max } } } = config; // nested (db itself isn't bound)
const { host: _, ...others } = config;                 // rest: everything else
console.log(host, port, h, p, timeout, dbName, max);
console.log(others);
```

- A default applies only when the value is `undefined` (same as parameter defaults).
- Nested destructuring throws if the intermediate is missing: `const { a: { b } } = {}` is a `TypeError`. Give it a default: `const { a: { b } = {} } = obj`.
- To destructure into existing variables, wrap the statement in parentheses: `({ x, y } = point);`. Without them, `{` starts a block.

### Destructuring parameters: named arguments

```js
function connect({ host = 'localhost', port = 5432, ssl = false, retries: { count = 3, delay = 100 } = {} } = {}) {
  return `${host}:${port} ssl=${ssl} retry ${count}x every ${delay}ms`;
}
console.log(connect());
console.log(connect({ port: 6543, retries: { count: 5 } }));
```

This is the idiomatic replacement for C# named and optional arguments: order-independent, self-documenting at the call site, and easy to extend without breaking callers. The trailing `= {}` makes calling with no argument at all legal.

## Spread and rest

`...` in an object literal copies own enumerable properties into the new object. Later properties win, so spread is how you write "copy with changes", the equivalent of a C# record's `with` expression.

```js
const base = { theme: 'dark', font: 14, plugins: ['git'] };
const custom = { ...base, font: 16 };               // override
const defaulted = { font: 12, lang: 'en', ...base }; // base wins over defaults
console.log(custom, defaulted);
console.log({ ...null, ...undefined, ...'hi', ...[7] });   // nullish spreads are ignored
```

## Reference semantics and copying

Objects (including arrays and functions) are reference values, like C# classes. Assignment copies the reference; `===` compares identity. There are no value-type structs.

```js
const a = { n: 1, inner: { m: 2 } };
const b = a;               // same object
const c = { ...a };        // shallow copy: new outer, same inner
b.n = 10;
c.inner.m = 20;
console.log(a, a === b, a === c, a.inner === c.inner);
```

A **shallow copy** (`{ ...obj }`, `Object.assign({}, obj)`, `[...arr]`, `arr.slice()`) duplicates the top level only. For a **deep copy**, use `structuredClone`, built into browsers and Node. It handles nesting, cycles, `Date`, `Map`, `Set`, typed arrays, and more. It can't clone functions, DOM nodes, or class identity (instances come back as plain objects).

```js
const original = { when: new Date(0), tags: new Set(['a']), nested: { list: [1, 2] } };
original.self = original;                     // a cycle
const copy = structuredClone(original);
copy.nested.list.push(3);
console.log(original.nested.list, copy.nested.list, copy.self === copy, copy.when instanceof Date);

try { structuredClone({ f() {} }); } catch (e) { console.log(e.name); }
```

The old trick `JSON.parse(JSON.stringify(x))` loses `undefined`, functions, `Date` (becomes a string), `Map`/`Set` (become `{}`), `NaN`/`Infinity` (become `null`), and throws on cycles. Don't use it as a clone.

> **Performance:** spread, `Object.assign`, `structuredClone` and the immutable-update style ("copy with changes") all allocate. That's the right trade for UI state, preset files and undo snapshots. It's the wrong one for per-frame or per-vertex updates: `points = points.map(p => ({ ...p, x: p.x + p.vx }))` creates thousands of objects every frame for the collector to chase. Mutate hot data in place; copy at the boundaries (saving, sending to a worker, undo).

### Equality

There's no built-in structural equality for objects. `===` is identity. You'll write (or import) a `deepEqual` when you need it; one of the exercises below is exactly that.

## The Object toolbox

| Call | Does |
|---|---|
| `Object.keys(o)` / `values` / `entries` | own enumerable string keys / values / `[key, value]` pairs |
| `Object.fromEntries(pairs)` | the inverse of `entries`; also takes a `Map` |
| `Object.assign(target, ...srcs)` | copies own enumerable props into `target` (mutates it, returns it) |
| `Object.freeze(o)` | makes `o` shallowly immutable |
| `Object.isFrozen(o)` | |
| `Object.hasOwn(o, k)` | own property check (safer than `o.hasOwnProperty(k)`) |
| `k in o` | own *or inherited* property check |
| `Object.create(proto)` | new object with the given prototype (`null` for a pure dictionary) |
| `Object.getPrototypeOf(o)` | |
| `Object.defineProperty(o, k, desc)` | define with full control (below) |
| `Object.groupBy(items, fn)` | group into `{ key: [items] }` (arrays chapter) |

`entries` + `fromEntries` is the standard way to map over an object, since objects have no `map`:

```js
const prices = { apple: 1.2, pear: 0.8, kiwi: 2.5 };
const discounted = Object.fromEntries(
  Object.entries(prices).map(([k, v]) => [k, +(v * 0.9).toFixed(2)])
);
const cheap = Object.fromEntries(Object.entries(prices).filter(([, v]) => v < 2));
console.log(discounted, cheap);

for (const [fruit, price] of Object.entries(prices)) console.log(`${fruit.padEnd(6)}${price}`);
```

### Freezing

`Object.freeze` is **shallow**: nested objects stay mutable. In sloppy mode (which is how this site runs your code) writes to a frozen object fail *silently*; in strict mode (modules, classes) they throw a `TypeError`. `Object.seal` is a weaker version: existing properties can change, but none can be added or removed.

```js
const settings = Object.freeze({ level: 1, nested: { deep: true } });
settings.level = 99;            // silently ignored here
settings.nested.deep = false;   // allowed: freeze is shallow
console.log(settings, Object.isFrozen(settings));

(function () {
  'use strict';
  try { settings.level = 2; } catch (e) { console.log('strict:', e.name); }
})();
```

## Getters and setters

Accessor properties run code on read or write, like C# properties. They're defined with `get`/`set` in literals and classes, and look like plain fields to the caller.

```js
const temp = {
  _c: 20,
  get celsius() { return this._c; },
  set celsius(v) {
    if (typeof v !== 'number' || Number.isNaN(v)) throw new TypeError('not a number');
    this._c = v;
  },
  get fahrenheit() { return this._c * 9 / 5 + 32; },
  set fahrenheit(f) { this.celsius = (f - 32) * 5 / 9; },
};
temp.fahrenheit = 212;
console.log(temp.celsius, temp.fahrenheit);
try { temp.celsius = 'hot'; } catch (e) { console.log(e.message); }
```

A getter without a setter makes the property read-only: assignments are silently ignored in sloppy mode and throw in strict mode. Getters run every time, so keep them cheap.

## Property descriptors (briefly)

Every property has attributes. Data properties have `value`, `writable`; accessors have `get`, `set`; both have `enumerable` (shows up in `keys`, spread, `for...in`, `JSON.stringify`) and `configurable` (can be deleted or redefined). Literal properties are all `true`; `defineProperty` defaults them all to `false`.

```js
const o = { visible: 1 };
Object.defineProperty(o, 'hidden', { value: 2, enumerable: false });
Object.defineProperty(o, 'id', { value: 7, writable: false, enumerable: true });
o.id = 8;   // ignored
console.log(o, o.hidden, Object.keys(o), JSON.stringify(o));
console.log(Object.getOwnPropertyDescriptor(o, 'id'));
```

You'll rarely write descriptors by hand, but they explain why some properties (like `length` on arrays, or methods on classes) don't show up when you list keys: they're non-enumerable.

## JSON

`JSON.stringify` and `JSON.parse` convert between values and JSON text. The rules worth knowing:

- `undefined`, functions and symbols are **skipped** as object values and become `null` inside arrays.
- `NaN` and `Infinity` become `null`; `Date` becomes its ISO string (via `toJSON`); `Map` and `Set` become `{}`. `bigint` throws.
- An object with a `toJSON()` method is serialized as whatever that returns.
- The second argument is a *replacer* (function or key whitelist); the third is indentation.
- `JSON.parse` takes a *reviver* function to transform values on the way in (e.g. turning date strings back into `Date`).

```js
const data = { id: 1, name: 'x', skip: undefined, fn() {}, when: new Date(0), list: [1, undefined, NaN], tags: new Set([1]) };
console.log(JSON.stringify(data));
console.log(JSON.stringify({ a: 1, b: [1, 2] }, null, 2));
console.log(JSON.stringify(data, ['id', 'name']));
console.log(JSON.stringify(data, (k, v) => (v instanceof Set ? [...v] : v)));

const parsed = JSON.parse('{"when":"2024-01-02T03:04:05.000Z","n":5}', (k, v) =>
  typeof v === 'string' && /^\d{4}-\d\d-\d\dT/.test(v) ? new Date(v) : v);
console.log(parsed.when.getUTCFullYear(), parsed.n);
```

`JSON.parse` throws a `SyntaxError` on bad input, including trailing commas and single-quoted strings: JSON is stricter than JavaScript literal syntax.

### Preset files

A procedural generator's whole output is determined by its seed and parameters, so the natural "save file" is tiny: a JSON preset. Store the inputs, never the generated pixels or vertices, which can be recomputed. A few habits keep presets robust:

```js
const PRESET_VERSION = 2;
function serialize(gen) {
  // only the inputs; derived data (the texture, caches) stays out
  return JSON.stringify({ v: PRESET_VERSION, seed: gen.seed, noise: { octaves: gen.noise.octaves, gain: gen.noise.gain }, palette: [...gen.palette] });
}
function load(text) {
  let data;
  try { data = JSON.parse(text); } catch { return null; }    // corrupt file
  if (data.v === 1) data.palette ??= [];                   // migrate old versions
  return { seed: data.seed ?? 0, noise: { octaves: 4, gain: 0.5, lacunarity: 2, ...data.noise }, palette: new Set(data.palette) };
}
const gen = { seed: 1337, noise: { octaves: 6, gain: 0.45, lacunarity: 2 }, palette: new Set(['#223', '#8a5']), pixels: '<1M bytes>' };
const text = serialize(gen);
console.log(text);
console.log(load(text), load('{oops'));
```

Version the format from day one, merge loaded data over defaults so new parameters get values (here `lacunarity`), and treat parse failure as "no preset" rather than a crash.

=== exercise pick
title: pick and omit
--- prompt
Useful for sending only some parameters of a generator to a worker, or into a preset file. Write two functions:

- `pick(obj, keys)` returns a new object with only the listed keys that `obj` actually has as **own** properties (keys not present are skipped, not set to `undefined`). A property whose value is `undefined` but which exists is included.
- `omit(obj, keys)` returns a new object with all own enumerable properties except the listed ones.

Neither may modify `obj`. Key order in the result follows the normal object rules, so the tests don't care about it.
--- starter
function pick(obj, keys) {
  const out = {};
  for (const k of keys) out[k] = obj[k];
  return out;
}

function omit(obj, keys) {
  for (const k of keys) delete obj[k];
  return obj;
}
--- solution
function pick(obj, keys) {
  return Object.fromEntries(keys.filter(k => Object.hasOwn(obj, k)).map(k => [k, obj[k]]));
}

function omit(obj, keys) {
  const drop = new Set(keys);
  return Object.fromEntries(Object.entries(obj).filter(([k]) => !drop.has(k)));
}
--- hint
`Object.hasOwn(obj, k)` tells "exists with value undefined" apart from "missing" and ignores inherited properties like `toString`.
--- hint
`Object.fromEntries(Object.entries(obj).filter(...))` builds a filtered copy.
--- harness
{
  const src = { a: 1, b: 2, c: undefined, d: { deep: 1 } };
  eq(pick(src, ['a', 'c']), { a: 1, c: undefined });
  eq(Object.keys(pick(src, ['a', 'zzz'])), ['a'], 'missing keys are not added');
  eq(pick(src, []), {});
  eq(Object.keys(pick(src, ['toString'])), [], 'inherited props are not own');
  check(pick(src, ['d']).d === src.d, 'shallow: same nested object');
  eq(omit(src, ['a', 'd']), { b: 2, c: undefined });
  eq(omit(src, []), src);
  check(omit(src, []) !== src, 'omit returns a new object');
  eq(omit(src, ['nope']), src);
  eq(src, { a: 1, b: 2, c: undefined, d: { deep: 1 } }, 'input untouched');

}

=== exercise deepEqual
title: deepEqual
--- prompt
Write `deepEqual(a, b)` for JSON-like data plus a few extras:

- Primitives compare with `Object.is` semantics, except that `0` and `-0` are equal (so `NaN` equals `NaN`).
- Arrays are equal if they have the same length and equal elements in order. An array never equals a plain object, even `[]` vs `{}`.
- Plain objects are equal if they have the same set of own enumerable keys (in any order) with deeply equal values. `{ a: undefined }` does **not** equal `{}`.
- `Date`s are equal if they hold the same time.
- Anything else compares by identity.

You don't need to handle cycles.
--- starter
function deepEqual(a, b) {
  return JSON.stringify(a) === JSON.stringify(b);
}
--- solution
function deepEqual(a, b) {
  if (a === b || (Number.isNaN(a) && Number.isNaN(b))) return true;
  if (typeof a !== 'object' || typeof b !== 'object' || a === null || b === null) return false;
  if (a instanceof Date || b instanceof Date) {
    return a instanceof Date && b instanceof Date && a.getTime() === b.getTime();
  }
  if (Array.isArray(a) !== Array.isArray(b)) return false;
  if (Array.isArray(a)) {
    return a.length === b.length && a.every((x, i) => deepEqual(x, b[i]));
  }
  if (Object.getPrototypeOf(a) !== Object.prototype || Object.getPrototypeOf(b) !== Object.prototype) return false;
  const ka = Object.keys(a), kb = Object.keys(b);
  return ka.length === kb.length && ka.every(k => Object.hasOwn(b, k) && deepEqual(a[k], b[k]));
}
--- hint
Handle the cheap cases first: `a === b` (which already treats `0` and `-0` as equal), both `NaN`, then "either is not a non-null object" means not equal.
--- hint
Check `Array.isArray` on both sides. For objects, compare key counts and then check that every key of `a` is an own key of `b` with an equal value; `Object.hasOwn` catches `{ a: undefined }` vs `{ b: undefined }`.
--- hint
For "anything else compares by identity", you need to recognise plain objects: `Object.getPrototypeOf(x) === Object.prototype`. Two different `Map`s fall through to `false`.

=== exercise deepMerge
title: deepMerge
--- prompt
Generators layer configuration: built-in defaults, then a named preset ("desert", "alpine"), then the user's tweaks. Write `deepMerge(target, source)` that returns a **new** object combining two such layers:

- Every key of `target` and `source` appears in the result.
- If both sides have a key whose values are both plain objects (not arrays, not `null`), merge them recursively.
- Otherwise the `source` value wins, **unless it is `undefined`**, in which case the `target` value is kept.
- Arrays are replaced, not merged. Values that end up in the result should not be shared with the inputs where a merge produced a new object; leaf values (arrays, primitives) may be shared.
- Neither input is modified.

```js
deepMerge({ seed: 1, noise: { octaves: 4, gain: 0.5 } }, { noise: { octaves: 6 }, erosion: true })
// { seed: 1, noise: { octaves: 6, gain: 0.5 }, erosion: true }
```
--- starter
function deepMerge(target, source) {
  return { ...target, ...source };
}
--- solution
function deepMerge(target, source) {
  const isPlain = v => v !== null && typeof v === 'object' && !Array.isArray(v);
  const out = { ...target };
  for (const [k, v] of Object.entries(source)) {
    if (v === undefined) continue;
    out[k] = isPlain(v) && isPlain(out[k]) ? deepMerge(out[k], v) : v;
  }
  return out;
}
--- hint
Start from `{ ...target }`, then walk `Object.entries(source)` and decide per key.
--- hint
Write a small `isPlain(v)` check: non-null, `typeof 'object'`, and not an array.
--- harness

=== exercise flatten
title: Flatten and unflatten
--- prompt
Write `flattenObj(obj)` turning nested plain objects into a single-level object with dotted keys, and `unflattenObj(flat)` doing the reverse.

```js
flattenObj({ a: 1, b: { c: 2, d: { e: 3 } }, f: [1, 2] })
// { a: 1, 'b.c': 2, 'b.d.e': 3, f: [1, 2] }
```

Only plain objects are descended into; arrays, `null`, dates and primitives are leaves. An empty nested object `{}` is kept as a leaf (so `{ a: {} }` flattens to `{ a: {} }`). `unflattenObj` splits each key on `.` and rebuilds the nesting.
--- starter
function flattenObj(obj) {
  return obj;
}

function unflattenObj(flat) {
  return flat;
}
--- solution
function flattenObj(obj, prefix = '', out = {}) {
  for (const [k, v] of Object.entries(obj)) {
    const key = prefix ? `${prefix}.${k}` : k;
    const plain = v !== null && typeof v === 'object' && Object.getPrototypeOf(v) === Object.prototype;
    if (plain && Object.keys(v).length) flattenObj(v, key, out);
    else out[key] = v;
  }
  return out;
}

function unflattenObj(flat) {
  const out = {};
  for (const [key, v] of Object.entries(flat)) {
    const parts = key.split('.');
    let node = out;
    for (const p of parts.slice(0, -1)) node = node[p] ??= {};
    node[parts.at(-1)] = v;
  }
  return out;
}
--- hint
Recurse with a prefix: `flattenObj(value, 'b.d', out)`. A "plain object" check is `Object.getPrototypeOf(v) === Object.prototype`.
--- hint
For unflatten, walk all but the last key part creating objects with `node = node[p] ??= {}`, then assign the last part.
--- harness
{
  const nested = { a: 1, b: { c: 2, d: { e: 3 } }, f: [1, 2] };
  const flat = { a: 1, 'b.c': 2, 'b.d.e': 3, f: [1, 2] };
  eq(flattenObj(nested), flat);
  eq(unflattenObj(flat), nested);

=== exercise immutableUpdate
title: Immutable nested update
--- prompt
Undo stacks in an editor (a node-based texture editor, a terrain tool) want each document state to be its own value, never mutated afterwards. Write `setIn(obj, path, value)` where `path` is an array of keys. It returns a new object with the value at `path` replaced, **without modifying `obj`**, copying only the objects along the path (everything else is shared with the original, which is what makes this cheap: an undo stack of 100 states shares almost all its data; React and Redux depend on the same trick).

- Missing intermediate objects are created as `{}`.
- If an object on the path is an array, copy it as an array (`[...arr]`), so array identity is preserved as "array".
- An empty path returns `value`.
--- starter
function setIn(obj, path, value) {
  let node = obj;
  for (const k of path.slice(0, -1)) node = node[k];
  node[path.at(-1)] = value;
  return obj;
}
--- solution
function setIn(obj, path, value) {
  if (path.length === 0) return value;
  const [head, ...rest] = path;
  const copy = Array.isArray(obj) ? [...obj] : { ...obj };
  copy[head] = setIn(obj?.[head], rest, value);
  return copy;
}
--- hint
Recursion fits: copy the current level, then set `copy[head] = setIn(obj[head], rest, value)`.
--- hint
When `obj` is `undefined` (a missing intermediate), `{ ...undefined }` is `{}`, and `obj?.[head]` keeps going safely.
--- harness
{
  const state = { output: { name: 'rock', size: { w: 512 } }, nodes: [{ id: 1, scale: 5 }, { id: 2, scale: 5 }], view: { zoom: 1 } };
  const snapshot = structuredClone(state);
  const s2 = setIn(state, ['output', 'size', 'w'], 1024);
  eq(s2.output.size.w, 1024);
  eq(state, snapshot, 'original unchanged');
  check(s2 !== state && s2.output !== state.output && s2.output.size !== state.output.size, 'path copied');
  check(s2.nodes === state.nodes && s2.view === state.view, 'siblings shared');
  const s3 = setIn(state, ['nodes', 1, 'scale'], 0);
  eq(s3.nodes[1], { id: 2, scale: 0 });
  check(Array.isArray(s3.nodes), 'arrays stay arrays');
  check(s3.nodes[0] === state.nodes[0], 'other elements shared');
  eq(state.nodes[1].scale, 5);
  eq(setIn({}, ['a', 'b', 'c'], 1), { a: { b: { c: 1 } } }, 'creates missing objects');
  eq(setIn({ a: 1 }, [], 'whole'), 'whole');
  eq(setIn({ a: 1 }, ['b'], 2), { a: 1, b: 2 });
  eq(state, snapshot, 'still unchanged');
}

=== exercise jsonDates
title: JSON with dates, maps and sets
--- prompt
A texture-editor project file holds a `Set` of enabled layers, a `Map` from node id to parameters, and the date it was saved. Plain JSON loses `Date`, `Map` and `Set`. Write `toJSONText(value)` and `fromJSONText(text)` that round-trip them, using `JSON.stringify` with a replacer and `JSON.parse` with a reviver.

Encode them as tagged objects: a `Date` as `{ "$date": isoString }`, a `Map` as `{ "$map": [[k, v], ...] }`, a `Set` as `{ "$set": [...] }`. Nested ones (a map inside a set inside an object) must work.

Watch out: `JSON.stringify` calls `Date.prototype.toJSON` *before* your replacer sees the value, so inside the replacer `value` is already a string. The original value is available as `this[key]` (use a `function`, not an arrow).
--- starter
function toJSONText(value) {
  return JSON.stringify(value);
}

function fromJSONText(text) {
  return JSON.parse(text);
}
--- solution
function toJSONText(value) {
  return JSON.stringify(value, function (key, v) {
    const raw = this[key];
    if (raw instanceof Date) return { $date: raw.toISOString() };
    if (raw instanceof Map) return { $map: [...raw] };
    if (raw instanceof Set) return { $set: [...raw] };
    return v;
  });
}

function fromJSONText(text) {
  return JSON.parse(text, (key, v) => {
    if (v && typeof v === 'object' && !Array.isArray(v)) {
      if ('$date' in v) return new Date(v.$date);
      if ('$map' in v) return new Map(v.$map);
      if ('$set' in v) return new Set(v.$set);
    }
    return v;
  });
}
--- hint
The replacer is called with `this` set to the object holding the key, so `this[key]` is the original `Date`. For the root value the key is `''` and `this` is a wrapper `{ '': value }`.
--- hint
The reviver runs bottom-up: by the time it sees `{ $map: [...] }`, the entries inside have already been revived. So `new Map(v.$map)` just works.
--- harness
{
  const value = {
    when: new Date('2024-05-06T07:08:09.000Z'),
    tags: new Set(['a', 'b']),
    index: new Map([['x', 1], ['y', new Set([new Date(0)])]]),
    plain: [1, 'two', { three: null }],
  };
  const text = toJSONText(value);
  check(typeof text === 'string', 'returns a string');
  check(text.includes('"$date"') && text.includes('"$map"') && text.includes('"$set"'), 'uses the tags');
  const back = fromJSONText(text);
  check(back.when instanceof Date, 'Date revived');
  eq(back.when.getTime(), value.when.getTime());
  check(back.tags instanceof Set, 'Set revived');
  eq([...back.tags], ['a', 'b']);
  check(back.index instanceof Map, 'Map revived');
  eq(back.index.get('x'), 1);
  const inner = back.index.get('y');
  check(inner instanceof Set && [...inner][0] instanceof Date && [...inner][0].getTime() === 0, 'nested set of dates');
  eq(back.plain, [1, 'two', { three: null }]);
  check(fromJSONText(toJSONText(new Date(42))).getTime() === 42, 'root date');
  eq(fromJSONText(toJSONText({ n: 1 })), { n: 1 });
}
