## Constants for a draw call

So far every number a shader used was either baked into the WGSL source or came in per vertex. Most real parameters are neither: a color, a time, a camera, an object's position. They are the same for every vertex and fragment in a draw, but change between draws or frames. That is what a **uniform buffer** is for.

| | Uniform buffer | Storage buffer |
|---|---|---|
| WGSL declaration | `var<uniform> u: T` | `var<storage, read> s: T` or `read_write` |
| Writable from shaders | never | `read_write` (not from vertex shaders) |
| Size per binding | small: at least 64 KiB guaranteed | large: 128 MiB+ |
| Runtime-sized arrays | no | yes (`array<T>`) |
| Layout rules | stricter (16-byte array strides) | normal |
| Typical use | per-frame / per-object parameters | bulk data, results |

Uniforms are the C# equivalent of passing arguments to every invocation: read-only, the same for everyone, and cheap because hardware caches them aggressively.

## A first uniform

Three steps, and you have done each before with storage buffers:

1. Declare the struct and the binding in WGSL.
2. Create a buffer with `UNIFORM | COPY_DST` and fill it with `writeBuffer`.
3. Put it in a bind group and `setBindGroup` before drawing.

```js
const device = await getDevice();
const ctx = canvas.getContext('webgpu');
const format = navigator.gpu.getPreferredCanvasFormat();
ctx.configure({ device, format });

const module = device.createShaderModule({ code: `
  struct Params {
    color: vec4f,    // offset 0, 16 bytes
    offset: vec2f,   // offset 16, 8 bytes
    scale: f32,      // offset 24, 4 bytes
  }                  // size 28, rounded up to 32 (struct alignment is 16)
  @group(0) @binding(0) var<uniform> params: Params;

  @vertex fn vs(@builtin(vertex_index) i: u32) -> @builtin(position) vec4f {
    let p = array(vec2f(0, 0.5), vec2f(-0.5, -0.5), vec2f(0.5, -0.5));
    return vec4f(p[i] * params.scale + params.offset, 0, 1);
  }
  @fragment fn fs() -> @location(0) vec4f { return params.color; }
`});
const pipeline = device.createRenderPipeline({
  layout: 'auto',
  vertex: { module, entryPoint: 'vs' },
  fragment: { module, entryPoint: 'fs', targets: [{ format }] },
});

const uniforms = device.createBuffer({ size: 32, usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST });
//                                          color             offset      scale
device.queue.writeBuffer(uniforms, 0, new Float32Array([1, 0.6, 0.1, 1,  0.2, -0.1,  0.8]));
const bindGroup = device.createBindGroup({
  layout: pipeline.getBindGroupLayout(0),
  entries: [{ binding: 0, resource: { buffer: uniforms } }],
});

const enc = device.createCommandEncoder();
const pass = enc.beginRenderPass({ colorAttachments: [{
  view: ctx.getCurrentTexture().createView(), clearValue: [0.1, 0.1, 0.15, 1], loadOp: 'clear', storeOp: 'store' }] });
pass.setPipeline(pipeline);
pass.setBindGroup(0, bindGroup);
pass.draw(3);
pass.end();
device.queue.submit([enc.finish()]);
```

The buffer is 32 bytes even though we only write 28: a binding must be at least as large as the WGSL struct, and the struct's size is rounded up to its alignment.

## Layout rules

WGSL lays out structs like C does: each member starts at the next offset that is a multiple of its **alignment**, the struct's alignment is the largest member alignment, and its size is rounded up to that. What surprises everyone is the alignment of 3-component vectors and matrices:

| Type | Size | Align |
|---|---|---|
| `f32`, `u32`, `i32` | 4 | 4 |
| `vec2f` | 8 | 8 |
| `vec3f` | 12 | **16** |
| `vec4f` | 16 | 16 |
| `mat2x2f` | 16 | 8 |
| `mat3x3f` | **48** | 16 |
| `mat4x4f` | 64 | 16 |
| `array<E, N>` in a uniform | N × stride, stride a multiple of **16** | 16 |

A `vec3f` takes 12 bytes but must start on a 16-byte boundary. A scalar after it slots into the 4 spare bytes:

```wgsl
struct Light {
  position: vec3f,    // offset 0..12
  intensity: f32,     // offset 12 (fits in the vec3's padding)
  color: vec3f,       // offset 16..28
  // 4 bytes padding
  direction: vec2f,   // offset 32..40
}                     // size 40 rounded up to 48
```

Put the same fields in the order `intensity, position, color, direction` and `position` jumps to offset 16, `color` to 32, `direction` to 48: 64 bytes, and every JS index changes. When in doubt, order members from largest alignment to smallest, or just use `vec4f` and pack scalars into its `.w`.

Uniforms add one more rule: **array elements must be 16 bytes apart**. `array<f32, 8>` in a uniform is a compile error ("'uniform' storage requires that array elements are aligned to 16 bytes"); write `array<vec4f, 2>` and index `a[i / 4][i % 4]`. Nested structs must also start on a 16-byte boundary. Storage buffers do not have these extra rules.

On the JS side you fill the bytes. A `Float32Array` works when everything is `f32`; for mixed `u32`/`f32` fields, create two views over one `ArrayBuffer`:

```js
// struct { tint: vec3f, count: u32, time: f32 }  ->  offsets 0, 12, 16; size 20 -> 32
const data = new ArrayBuffer(32);
const f32 = new Float32Array(data), u32 = new Uint32Array(data);
f32.set([1, 0.5, 0.25], 0);   // tint at byte 0  = float index 0
u32[3] = 7;                   // count at byte 12 = index 3
f32[4] = 1.5;                 // time at byte 16  = index 4
console.log(new Uint8Array(data).slice(0, 20));
```

## Animating: requestAnimationFrame in a worker

Code here runs in a Web Worker that owns `canvas` (an `OffscreenCanvas`). Dedicated workers have `requestAnimationFrame` too, so the loop looks the same as on a page:

```text
frame(timestamp):
  write this frame's uniforms with writeBuffer
  encode a pass into ctx.getCurrentTexture()
  submit
  requestAnimationFrame(frame)
```

Two rules:

- **Call `getCurrentTexture()` every frame.** The canvas hands out a fresh texture per frame and presents it when your callback returns. Holding on to last frame's texture is an error.
- **Animate by time, not by frame count.** The callback receives a timestamp in milliseconds. Screens run at 60, 120 or 144 Hz; `angle += 0.02` per frame spins twice as fast on a 120 Hz monitor. Use `t / 1000` seconds, or a `dt` between frames.

```js
const device = await getDevice();
const ctx = canvas.getContext('webgpu');
const format = navigator.gpu.getPreferredCanvasFormat();
ctx.configure({ device, format });

const module = device.createShaderModule({ code: `
  struct Frame { time: f32, aspect: f32 }
  @group(0) @binding(0) var<uniform> frame: Frame;

  struct VOut { @builtin(position) pos: vec4f, @location(0) color: vec3f }

  @vertex fn vs(@builtin(vertex_index) i: u32) -> VOut {
    let p = array(vec2f(0, 0.6), vec2f(-0.52, -0.3), vec2f(0.52, -0.3));
    let c = array(vec3f(1, 0.3, 0.3), vec3f(0.3, 1, 0.3), vec3f(0.3, 0.4, 1));
    let a = frame.time;                       // radians: one turn every 6.28 s
    let r = vec2f(p[i].x * cos(a) - p[i].y * sin(a), p[i].x * sin(a) + p[i].y * cos(a));
    let s = 0.8 + 0.2 * sin(frame.time * 3.0); // pulse
    return VOut(vec4f(r.x * s / frame.aspect, r.y * s, 0, 1), c[i]);
  }
  @fragment fn fs(v: VOut) -> @location(0) vec4f { return vec4f(v.color, 1); }
`});
const pipeline = device.createRenderPipeline({
  layout: 'auto',
  vertex: { module, entryPoint: 'vs' },
  fragment: { module, entryPoint: 'fs', targets: [{ format }] },
});
const uniforms = device.createBuffer({ size: 8, usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST });
const bindGroup = device.createBindGroup({ layout: pipeline.getBindGroupLayout(0),
  entries: [{ binding: 0, resource: { buffer: uniforms } }] });
const frameData = new Float32Array(2);   // reused every frame

function frame(ms) {
  frameData[0] = ms / 1000;
  frameData[1] = canvas.width / canvas.height;
  device.queue.writeBuffer(uniforms, 0, frameData);

  const enc = device.createCommandEncoder();
  const pass = enc.beginRenderPass({ colorAttachments: [{
    view: ctx.getCurrentTexture().createView(), clearValue: [0.08, 0.08, 0.1, 1], loadOp: 'clear', storeOp: 'store' }] });
  pass.setPipeline(pipeline);
  pass.setBindGroup(0, bindGroup);
  pass.draw(3);
  pass.end();
  device.queue.submit([enc.finish()]);
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

Your function returns immediately; the loop keeps running in the worker until you click Run again (which terminates the worker).

`writeBuffer` copies your data **when you call it**, into a staging area, and the copy into the GPU buffer is ordered before any later `submit`. So reusing one `Float32Array` every frame is safe and avoids garbage.

## The one-buffer-many-draws trap

Here is the bug everyone writes once. You have three objects and one uniform buffer:

```text
for each object:
  writeBuffer(uniforms, 0, object.color)
  pass.draw(...)
submit
```

All three objects come out in the **last** color. `writeBuffer` is a queue operation: all three writes execute before the submitted command buffer runs, so by the time any draw executes, the buffer holds the last value. Commands in a pass record *which buffer* to read, not its contents.

Fixes, from simplest to most scalable:

1. One uniform buffer (and bind group) per object.
2. One big buffer holding every object's data at different offsets, a bind group per offset.
3. One big buffer and **dynamic offsets**: one bind group, offset chosen at `setBindGroup` time.
4. Put per-object data in a storage buffer array and index it with `instance_index` (the instancing chapter, and the next ones).

## Grouping by update frequency

You can have up to 4 bind groups (`@group(0)` to `@group(3)`). The convention is to group bindings by how often they change:

| Group | Changes | Typical contents |
|---|---|---|
| 0 | once per frame | time, camera, lights |
| 1 | per material | textures, samplers, material color |
| 2 | per object | model transform |

Setting a bind group is cheap but not free; with this split, drawing 100 objects sets group 0 once and group 2 a hundred times. To share a group between pipelines, the pipelines need a compatible layout. `layout: 'auto'` gives each pipeline its own private layouts, so a bind group made for one cannot be used with another. Shared groups need an explicit `device.createBindGroupLayout` and `device.createPipelineLayout({ bindGroupLayouts: [...] })`.

## Dynamic offsets

A dynamic offset lets one bind group point at different slices of one buffer. The layout must say so, which means an explicit layout:

```js
const device = await getDevice();
const bgl = device.createBindGroupLayout({ entries: [{
  binding: 0, visibility: GPUShaderStage.VERTEX | GPUShaderStage.FRAGMENT,
  buffer: { type: 'uniform', hasDynamicOffset: true } }] });
const layout = device.createPipelineLayout({ bindGroupLayouts: [bgl] });

const STRIDE = device.limits.minUniformBufferOffsetAlignment; // 256 almost everywhere
const objects = 3;
const buf = device.createBuffer({ size: STRIDE * objects, usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST });
const bg = device.createBindGroup({ layout: bgl, entries: [{ binding: 0, resource: { buffer: buf, size: 16 } }] });
// later: pass.setBindGroup(0, bg, [i * STRIDE]); pass.draw(...);
console.log('stride', STRIDE, 'bytes per object, buffer', buf.size);
```

The bind group's `size` is the size of *one* slice (the struct), not the whole buffer. Offsets must be multiples of `minUniformBufferOffsetAlignment`, usually 256, so a 16-byte struct wastes 240 bytes per object. That is fine for hundreds of objects; for many thousands, use a storage buffer and instancing.

## 2D transforms as matrices

Passing `offset`, `scale` and `angle` separately works until you want to combine them: rotate around a point, then scale, then move, or attach a child to a parent. Matrices compose by multiplication. In 2D with translation you need **3×3 matrices** acting on `(x, y, 1)`.

WGSL matrices are **column-major**: `mat3x3f` is three column vectors, and `m * v` treats `v` as a column. We store them in JS as 9 numbers, column by column:

```text
translation(tx, ty)   rotation(a)            scaling(sx, sy)
| 1 0 tx |            | cos -sin 0 |         | sx 0  0 |
| 0 1 ty |            | sin  cos 0 |         | 0  sy 0 |
| 0 0 1  |            | 0    0   1 |         | 0  0  1 |
JS: [1,0,0, 0,1,0, tx,ty,1]   [c,s,0, -s,c,0, 0,0,1]   [sx,0,0, 0,sy,0, 0,0,1]
```

`multiply(a, b)` gives the matrix that applies `b` first, then `a`. So `T * R * S` scales, then rotates, then translates: the usual order for placing an object.

**The mat3x3f padding gotcha.** In a buffer, each column of a `mat3x3f` is a `vec3f`, which is aligned to 16. The matrix is 48 bytes: 12 floats, with a padding float after each column. Upload the 9 numbers directly and the second column starts in the first column's padding slot, so the shader sees garbage. Pad it:

```js
const pad3 = m => new Float32Array([m[0], m[1], m[2], 0, m[3], m[4], m[5], 0, m[6], m[7], m[8], 0]);
console.log(pad3([1, 2, 3, 4, 5, 6, 7, 8, 9]));
```

(Many engines just send a `mat4x4f` even in 2D to avoid this.)

Here is everything together: a per-frame group with the aspect ratio, and per-object uniform buffers holding a padded `mat3x3f` and a color, for a little solar system where the moon's matrix is the earth's matrix times its own:

```js
const device = await getDevice();
const ctx = canvas.getContext('webgpu');
const format = navigator.gpu.getPreferredCanvasFormat();
ctx.configure({ device, format });

const mul = (a, b) => {                 // column-major 3x3: result = a * b
  const r = new Array(9);
  for (let c = 0; c < 3; c++) for (let row = 0; row < 3; row++)
    r[c * 3 + row] = a[row] * b[c * 3] + a[3 + row] * b[c * 3 + 1] + a[6 + row] * b[c * 3 + 2];
  return r;
};
const T = (x, y) => [1, 0, 0, 0, 1, 0, x, y, 1];
const R = a => [Math.cos(a), Math.sin(a), 0, -Math.sin(a), Math.cos(a), 0, 0, 0, 1];
const S = s => [s, 0, 0, 0, s, 0, 0, 0, 1];

const module = device.createShaderModule({ code: `
  struct Frame { aspect: f32 }
  struct Object { transform: mat3x3f, color: vec4f }   // 48 + 16 = 64 bytes
  @group(0) @binding(0) var<uniform> frame: Frame;
  @group(1) @binding(0) var<uniform> obj: Object;

  @vertex fn vs(@builtin(vertex_index) i: u32) -> @builtin(position) vec4f {
    let a = f32(i / 3u) * 0.5236 + f32(i % 3u) * 0.5236;  // 12 wedges around a circle
    var p = vec2f(0);
    if (i % 3u != 0u) { p = vec2f(cos(a - 0.5236), sin(a - 0.5236)); }
    let w = obj.transform * vec3f(p, 1);
    return vec4f(w.x / frame.aspect, w.y, 0, 1);
  }
  @fragment fn fs() -> @location(0) vec4f { return obj.color; }
`});
const pipeline = device.createRenderPipeline({
  layout: 'auto',
  vertex: { module, entryPoint: 'vs' },
  fragment: { module, entryPoint: 'fs', targets: [{ format }] },
});
const frameBuf = device.createBuffer({ size: 16, usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST });
const frameGroup = device.createBindGroup({ layout: pipeline.getBindGroupLayout(0),
  entries: [{ binding: 0, resource: { buffer: frameBuf } }] });

const objects = [[1, 0.8, 0.2, 1], [0.2, 0.5, 1, 1], [0.8, 0.8, 0.8, 1]].map(color => {
  const buffer = device.createBuffer({ size: 64, usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST });
  const group = device.createBindGroup({ layout: pipeline.getBindGroupLayout(1),
    entries: [{ binding: 0, resource: { buffer } }] });
  const data = new Float32Array(16);
  data.set(color, 12);
  return { buffer, group, data };
});

function frame(ms) {
  const t = ms / 1000;
  device.queue.writeBuffer(frameBuf, 0, new Float32Array([canvas.width / canvas.height]));
  const sun = S(0.25);
  const earthOrbit = mul(R(t * 0.8), T(0.6, 0));        // rotate the offset: an orbit
  const earth = mul(earthOrbit, S(0.1));
  const moon = mul(earthOrbit, mul(R(t * 3), mul(T(0.18, 0), S(0.04))));
  [sun, earth, moon].forEach((m, i) => {
    const o = objects[i];
    o.data.set([m[0], m[1], m[2], 0, m[3], m[4], m[5], 0, m[6], m[7], m[8], 0]);  // padded columns
    device.queue.writeBuffer(o.buffer, 0, o.data);
  });

  const enc = device.createCommandEncoder();
  const pass = enc.beginRenderPass({ colorAttachments: [{
    view: ctx.getCurrentTexture().createView(), clearValue: [0.02, 0.02, 0.06, 1], loadOp: 'clear', storeOp: 'store' }] });
  pass.setPipeline(pipeline);
  pass.setBindGroup(0, frameGroup);          // once per frame
  for (const o of objects) {
    pass.setBindGroup(1, o.group);           // once per object
    pass.draw(36);
  }
  pass.end();
  device.queue.submit([enc.finish()]);
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

Note that each object has its *own* buffer, so writing all three before the submit is correct, unlike the trap above.

> Try it: change `S(0.1)` for the earth to `mul(S(0.1), R(t))`. A circle does not show rotation, but swap the wedge shape for a triangle and it will.

async function affine(device, data, a, b) {
  const module = device.createShaderModule({ code: `
    struct Params { a: f32, b: f32 }
    @group(0) @binding(0) var<storage, read_write> xs: array<f32>;
    @group(0) @binding(1) var<uniform> params: Params;
    @compute @workgroup_size(64) fn main(@builtin(global_invocation_id) id: vec3u) {
      if (id.x < arrayLength(&xs)) { xs[id.x] = params.a * xs[id.x] + params.b; }
    }` });
  const pipeline = device.createComputePipeline({ layout: 'auto', compute: { module, entryPoint: 'main' } });
  const buf = device.createBuffer({ size: data.byteLength, usage: GPUBufferUsage.STORAGE | GPUBufferUsage.COPY_SRC | GPUBufferUsage.COPY_DST });
  device.queue.writeBuffer(buf, 0, data);

  const ubuf = device.createBuffer({ size: 8, usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST });
  device.queue.writeBuffer(ubuf, 0, new Float32Array([a, b]));

  const bindGroup = device.createBindGroup({ layout: pipeline.getBindGroupLayout(0), entries: [
    { binding: 0, resource: { buffer: buf } },
    { binding: 1, resource: { buffer: ubuf } },
  ] });
  const enc = device.createCommandEncoder();
  const pass = enc.beginComputePass();
  pass.setPipeline(pipeline);
  pass.setBindGroup(0, bindGroup);
  pass.dispatchWorkgroups(Math.ceil(data.length / 64));
  pass.end();
  device.queue.submit([enc.finish()]);
  return new Float32Array(await readBuffer(device, buf));
}

title: Pack a uniform struct
--- prompt
Write `packParams(p)` that returns an `ArrayBuffer` laid out exactly like this WGSL struct in a uniform buffer:

```wgsl
struct Params {
  offset: vec2f,
  color: vec3f,
  scale: f32,
  tint: vec4f,
  count: u32,
}
```

`p` looks like `{ offset: [x, y], color: [r, g, b], scale, tint: [r, g, b, a], count }`. The returned buffer must be exactly the size of the struct. Work out each member's offset from the alignment table first.

The tests upload your bytes and read every field back in a compute shader.
--- starter
function packParams(p) {
  // naive: everything back to back. Wrong!
  const f = new Float32Array([...p.offset, ...p.color, p.scale, ...p.tint, p.count]);
  return f.buffer;
}
--- solution
function packParams(p) {
  // offset @0, color @16 (vec3 aligns to 16), scale @28, tint @32, count @48, size 52 -> 64
  const buf = new ArrayBuffer(64);
  const f = new Float32Array(buf), u = new Uint32Array(buf);
  f.set(p.offset, 0);
  f.set(p.color, 4);
  f[7] = p.scale;
  f.set(p.tint, 8);
  u[12] = p.count;
  return buf;
}
--- hint
`offset` is at 0 and takes 8 bytes. `color` is a `vec3f`, so it cannot start at 8: it starts at 16. `scale` fits in the 4 bytes after `color`.
--- hint
`count` is a `u32`: write it through a `Uint32Array` view, not as a float. The struct's size is rounded up to its alignment, 16.
--- harness
{

--- solution
function translation(tx, ty) { return [1, 0, 0, 0, 1, 0, tx, ty, 1]; }
function rotation(a) {
  const c = Math.cos(a), s = Math.sin(a);
  return [c, s, 0, -s, c, 0, 0, 0, 1];
}
function scaling(sx, sy) { return [sx, 0, 0, 0, sy, 0, 0, 0, 1]; }
function multiply(a, b) {
  const r = new Array(9);
  for (let c = 0; c < 3; c++)
    for (let row = 0; row < 3; row++)
      r[c * 3 + row] = a[row] * b[c * 3] + a[3 + row] * b[c * 3 + 1] + a[6 + row] * b[c * 3 + 2];
  return r;
}
function apply(m, [x, y]) {
  return [m[0] * x + m[3] * y + m[6], m[1] * x + m[4] * y + m[7]];
}
function pad(m) {
  return new Float32Array([m[0], m[1], m[2], 0, m[3], m[4], m[5], 0, m[6], m[7], m[8], 0]);
}

--- hint
`(a * b)[row, col]` is the dot product of row `row` of `a` with column `col` of `b`: `sum over k of a[k * 3 + row] * b[col * 3 + k]`.

      let c = array(vec2f(-1, -1), vec2f(1, -1), vec2f(-1, 1), vec2f(-1, 1), vec2f(1, -1), vec2f(1, 1));
      return vec4f(obj.center + c[i] * 0.25, 0, 1);
    }
    @fragment fn fs() -> @location(0) vec4f { return vec4f(obj.color * frame.tint, 1); }` });
  const pipeline = device.createRenderPipeline({ layout: 'auto',
    vertex: { module, entryPoint: 'vs' },
    fragment: { module, entryPoint: 'fs', targets: [{ format: target.format }] } });

  const uniform = (data, group) => {
    const buffer = device.createBuffer({ size: data.byteLength, usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST });
    device.queue.writeBuffer(buffer, 0, data);
    return device.createBindGroup({ layout: pipeline.getBindGroupLayout(group), entries: [{ binding: 0, resource: { buffer } }] });
  };
  const frameGroup = uniform(new Float32Array([...tint, 0]), 0);                     // 12 bytes -> 16
  const objGroups = objects.map(o => uniform(new Float32Array([...o.color, 0, o.x, o.y, 0, 0]), 1));  // 24 -> 32

  const enc = device.createCommandEncoder();
  const pass = enc.beginRenderPass({ colorAttachments: [{ view: target.createView(),
    clearValue: [0, 0, 0, 1], loadOp: 'clear', storeOp: 'store' }] });
  pass.setPipeline(pipeline);
  pass.setBindGroup(0, frameGroup);
  for (const g of objGroups) {
    pass.setBindGroup(1, g);
    pass.draw(6);
  }
  pass.end();
  device.queue.submit([enc.finish()]);
}
--- hint
`Frame` is 16 bytes (a `vec3f` rounds the struct up to 16). `Obj` has `center` at offset 16 and a size of 32.
--- hint
`pipeline.getBindGroupLayout(1)` gives the layout for group 1.

`b` is a `vec3f`, aligned to 16, so it starts at offset 16 and ends at 28. The struct's alignment is 16, so 28 rounds up to 32. Reversing the members (`b: vec3f, a: f32`) gives 16 bytes: `a` fills the vec3's padding.
