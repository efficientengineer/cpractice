## const correctness

`const` in C is a promise made *through a particular name*: "I will not modify the object via this lvalue". It is not C#'s `const` (a compile-time constant) and not quite `readonly`; the closest JS analogue is nothing at all, since `Object.freeze` is a runtime property.

Read declarations right to left from the name:

```c
const char *p;        // p is a pointer to const char: *p = 'x' is an error, p++ is fine
char *const q = buf;  // q is a const pointer to char: *q = 'x' is fine, q++ is an error
const char *const r;  // neither
```

In an API, `const` on a pointer parameter is documentation the compiler enforces: `size_t strlen(const char *s)` tells every caller that the string will not be modified, and lets them pass string literals and other `const` data. Rules of thumb:

- Every pointer parameter that the function only reads should be `const T *`.
- Return `const T *` when the caller may look but must not touch (internal storage, string tables).
- Never cast `const` away to write through it. If the object was *defined* `const`, writing to it is UB; it may sit in read-only memory.
- `const` does not mean "this value cannot change": another non-const pointer to the same object can change it.

```c
#include <stdio.h>

static int sum(const int *v, size_t n) {   // promises not to modify v[]
    int s = 0;
    for (size_t i = 0; i < n; i++) s += v[i];
    return s;
}

int main(void) {
    int data[] = {1, 2, 3};
    const int *view = data;
    data[0] = 10;                 // allowed: data itself is not const
    printf("%d %d\n", *view, sum(data, 3));   // 10 15
    return 0;
}
```

One wart: `char **` does not convert implicitly to `const char **` (doing so would open a hole in the type system), so functions taking arrays of strings often take `char *const *` or `const char *const *`.

## restrict

`restrict` on a pointer parameter promises that, for the lifetime of that pointer, the object it points to is accessed *only* through it (or pointers derived from it). It lets the compiler skip reloading memory after writes through other pointers, and vectorize loops.

```c
#include <stdio.h>

void add_into(int *restrict dst, const int *restrict src, size_t n) {
    for (size_t i = 0; i < n; i++) dst[i] += src[i];  // free to vectorize
}

int main(void) {
    int a[4] = {1, 2, 3, 4}, b[4] = {10, 20, 30, 40};
    add_into(a, b, 4);
    printf("%d %d %d %d\n", a[0], a[1], a[2], a[3]);
    return 0;
}
```

This is the difference between `memcpy(void *restrict dst, const void *restrict src, size_t n)` (regions must not overlap) and `memmove` (they may). Breaking a `restrict` promise is UB, and nothing checks it. Use it in hot inner loops where you control the callers; leave it off elsewhere.

## Opaque types: private fields in C

C has no `private`, but it has something stronger: callers can be denied the struct's *definition* entirely. The header declares an incomplete type; only the `.c` file defines it.

```c
// stack.h
typedef struct Stack Stack;            // incomplete: callers cannot see inside
Stack *stack_new(void);
void   stack_free(Stack *s);
int    stack_push(Stack *s, int v);    // 0 on success, -1 on allocation failure
int    stack_pop(Stack *s, int *out);  // 0 on success, -1 if empty

// stack.c
struct Stack { int *items; size_t len, cap; };
```

Code that includes `stack.h` can hold `Stack *` pointers and call the functions, but cannot write `s->len`, cannot declare a `Stack` on the stack, and cannot use `sizeof(Stack)`. You can change the layout without recompiling callers: this is how `FILE` works, and how stable library ABIs are built. The cost is one heap allocation per object and no inlining of accessors across files. This is the C version of a C# class with all-private fields and a factory method.

## Arena (bump) allocators

`malloc`/`free` per object is slow when you allocate thousands of small things, and error-prone when they all die together. An **arena** grabs one big block and hands out slices of it by bumping an offset. Individual objects are never freed; the whole arena is reset or destroyed at once.

```c
#include <stdalign.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct { unsigned char *base; size_t cap, used; } Arena;

static void *arena_alloc(Arena *a, size_t size, size_t align) {
    uintptr_t start = (uintptr_t)(a->base + a->used);
    uintptr_t aligned = (start + (align - 1)) & ~(uintptr_t)(align - 1);
    size_t pad = aligned - start;
    if (pad > a->cap - a->used || size > a->cap - a->used - pad) return NULL;
    a->used += pad + size;
    return (void *)aligned;
}

int main(void) {
    Arena a = { malloc(1024), 1024, 0 };
    char *name = arena_alloc(&a, 6, 1);
    strcpy(name, "arena");
    double *d = arena_alloc(&a, sizeof *d, alignof(double));
    *d = 2.5;
    printf("%s %.1f used=%zu\n", name, *d, a.used);   // arena 2.5 used=16
    free(a.base);   // frees everything at once
    return 0;
}
```

Arenas are standard in compilers, games (a per-frame arena reset every frame) and request handlers (a per-request arena). They make lifetime management trivial: no leaks within the arena, no double frees, and allocation is a few instructions.

> **Performance:** the classic game use is the **frame allocator**: one arena, sized at startup, that every system uses for temporary data during a frame (visible-entity lists, sorted draw lists, formatted text, pathfinding scratch), and that is reset with `used = 0` at the top of the next frame. That replaces hundreds of `malloc`/`free` pairs per frame with pointer bumps, and the data each system builds sits contiguously in memory. Some engines keep two and alternate, so data from the previous frame stays readable for one more frame.

## Alignment

Every type has an **alignment**: its address must be a multiple of it. On x86-64, `int` is 4-aligned, `double` and pointers 8-aligned. `alignof(T)` (from `<stdalign.h>`; keyword `_Alignof`) tells you. `malloc` returns memory aligned for any standard type (`alignof(max_align_t)`, 16 here).

The compiler inserts **padding** in structs so each member is aligned, and at the end so arrays of the struct stay aligned:

```c
#include <stddef.h>
#include <stdio.h>

struct loose { char a; double b; char c; };   // 1 + 7 pad + 8 + 1 + 7 pad = 24
struct tight { double b; char a; char c; };   // 8 + 1 + 1 + 6 pad = 16

int main(void) {
    printf("%zu %zu\n", sizeof(struct loose), sizeof(struct tight));
    printf("offset of c in loose: %zu\n", offsetof(struct loose, c));   // 16
    return 0;
}
```

Order members from largest alignment to smallest to minimize padding. `offsetof(type, member)` (from `<stddef.h>`) gives a member's byte offset. Never assume a struct has no padding when writing it to a file or network: serialize field by field.

To round a size or address up to a power-of-two alignment `a`: `(n + a - 1) & ~(a - 1)`. `alignas(16)` on a declaration requests stricter alignment, e.g. for SIMD.

### Array of structs vs struct of arrays

The CPU never reads one byte from memory: it reads a whole **cache line**, 64 bytes on current x86 and ARM chips. Fast code makes every byte of every line count. Compare two layouts for 10000 particles:

```c
#include <stdio.h>

enum { N = 10000 };

/* Array of structs (AoS): natural, like a C# class array */
struct particle { float x, y, vx, vy; float r, g, b, a; int sprite, flags; float life, age; };
static struct particle aos[N];

/* Struct of arrays (SoA): one array per field */
static struct {
    float x[N], y[N], vx[N], vy[N];
    float life[N], age[N];
    /* colors, sprites, flags: in their own arrays, untouched by the update */
} soa;

int main(void) {
    float dt = 1.0f / 60;
    for (int i = 0; i < N; i++) { aos[i].vx = soa.vx[i] = 1; aos[i].vy = soa.vy[i] = 2; }
    for (int i = 0; i < N; i++) {   /* uses 16 of every 48 bytes it loads */
        aos[i].x += aos[i].vx * dt;
        aos[i].y += aos[i].vy * dt;
    }
    for (int i = 0; i < N; i++) {   /* reads only bytes it uses; easy to vectorize */
        soa.x[i] += soa.vx[i] * dt;
        soa.y[i] += soa.vy[i] * dt;
    }
    printf("%zu bytes per particle; %.3f %.3f\n", sizeof(struct particle), aos[5].x, soa.x[5]);
    return 0;
}
```

> **Performance:** in the AoS loop, each 48-byte particle drags its color, sprite, flags, life and age through the cache, though the loop touches only position and velocity: two thirds of the memory traffic is wasted. In the SoA loop every loaded byte is used, and the four arrays are perfect input for SIMD (the compiler vectorizes it at `-O2`). Rules of thumb: lay data out by *how it is iterated*, not by what "object" it belongs to; split hot fields (touched every frame) from cold ones (touched on spawn or death); and measure with a profiler before and after, since layout wins depend on the access pattern.

## Memory layout of a process

| Region | Contains | Lifetime |
|---|---|---|
| text | machine code, read-only | whole run |
| rodata | string literals, `const` globals | whole run, read-only |
| data | initialized globals and `static` locals: `int g = 5;` | whole run |
| bss | zero-initialized globals and statics: `static int counts[1000];` (takes no space in the file) | whole run |
| heap | `malloc` blocks, growing up | until `free` |
| (shared libraries, `mmap` regions) | | |
| stack | locals, return addresses, growing down; typically 8 MB on Linux | until the function returns |

```c
#include <stdio.h>
#include <stdlib.h>

int initialized = 42;      // data
int zeroed;                // bss
const char *lit = "hi";    // the pointer is in data, "hi" in rodata

int main(void) {
    int local = 1;                 // stack
    int *heap = malloc(sizeof *heap);
    printf("text  %p\n", (void *)main);
    printf("rodata %p\n", (void *)lit);
    printf("data  %p\n", (void *)&initialized);
    printf("bss   %p\n", (void *)&zeroed);
    printf("heap  %p\n", (void *)heap);
    printf("stack %p\n", (void *)&local);
    free(heap);
    return 0;
}
```

(Casting a function pointer to `void *` is not strictly portable, but works on every mainstream platform.) Because the stack is small, large arrays belong in static storage or on the heap, never as locals: `char buf[16 * 1024 * 1024];` in a function crashes.

## Variadic functions

`printf` is an ordinary C function with a `...` parameter. `<stdarg.h>` lets you walk the extra arguments, but nothing tells you how many there are or their types: the function must know from a count, a sentinel or a format string.

```c
#include <stdarg.h>
#include <stdio.h>

static double average(int count, ...) {
    va_list ap;
    va_start(ap, count);              // start after the last named parameter
    double sum = 0;
    for (int i = 0; i < count; i++)
        sum += va_arg(ap, double);    // you must name the type
    va_end(ap);
    return count ? sum / count : 0;
}

int main(void) {
    printf("%.2f\n", average(3, 1.0, 2.0, 4.5));
    printf("%.2f\n", average(2, 1.0f, 2.0f));   // floats are promoted to double
    return 0;
}
```

Rules:

- **Default argument promotions** apply to the `...` part: `char`, `short` and `bool` arrive as `int`, `float` as `double`. `va_arg(ap, float)` or `va_arg(ap, char)` is wrong.
- Reading a type that does not match what was passed is UB. `average(2, 1, 2)` passes `int`s and reads `double`s: garbage. This is why `printf("%f", 3)` is broken and why gcc checks `printf` formats.
- To pass the arguments on, take a `va_list`: that is what `vprintf`, `vfprintf` and `vsnprintf` are for. Write your logger as a `...` wrapper around a `va_list` core.
- `va_copy` duplicates a `va_list` if you need to walk it twice (for instance, `vsnprintf` once to measure, once to write).
- Mark your own printf-like functions with `__attribute__((format(printf, 1, 2)))` so gcc checks their callers.

```c
#include <stdarg.h>
#include <stdio.h>

__attribute__((format(printf, 2, 3)))
static void log_msg(const char *level, const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);
    printf("[%s] ", level);
    vprintf(fmt, ap);
    putchar('\n');
    va_end(ap);
}

int main(void) {
    log_msg("info", "%d items in %.1f ms", 42, 3.5);
    return 0;
}
```

## Static assertions

`static_assert(expr, "message")` (C11, `<assert.h>`) fails the *build* if a constant expression is false. Use it to pin down assumptions your code relies on:

```c
#include <assert.h>
#include <stdint.h>

struct packet { uint32_t id; uint16_t len; uint8_t flags, kind; };
static_assert(sizeof(struct packet) == 8, "packet must have no padding");

enum color { RED, GREEN, BLUE, COLOR_COUNT };
static const char *const color_names[] = { "red", "green", "blue" };
static_assert(sizeof color_names / sizeof color_names[0] == COLOR_COUNT,
              "color_names out of sync with enum color");

int main(void) { return 0; }
```

## Designing C APIs

Without exceptions, classes or a GC, a C API has to state explicitly what C# expresses through the type system and runtime.

**Errors.** Pick one convention per library and stick to it:

- Return a status code (`0` / negative, or an `enum` of error codes) and pass results through **out parameters**. This is the most common style, and leaves the return value free for errors: `int parse_port(const char *s, uint16_t *out);`.
- Return a pointer, `NULL` on failure, with details in `errno` or a `last_error()` function: `fopen`, `malloc`.
- Provide `const char *mylib_strerror(int code)` so callers can print something useful.
- On failure, leave out parameters untouched (or document exactly what they hold).

**Ownership.** Every pointer in an API needs a documented answer to "who frees this, and how?":

```c
/* Returns a newly allocated string; the caller must free() it. NULL on allocation failure. */
char *path_join(const char *dir, const char *file);

/* Returns a pointer into an internal table. Do not free; valid until the next call. */
const char *color_name(int c);

/* Takes ownership of buf: the list frees it in list_free(). */
int list_append_owned(List *l, char *buf);
```

**Other habits**

- Prefix every public name with the library's name (`json_parse`, `json_free`): C has one global namespace.
- Pair constructors and destructors: `x_new`/`x_free` (heap-allocated, opaque) or `x_init`/`x_destroy` (caller provides the storage).
- Make destructors accept `NULL`, like `free` does.
- Let the caller provide buffers when the size is bounded (`snprintf` style: pass `buf` and `cap`, return the length needed). This avoids allocation entirely.
- Take sizes as `size_t`, strings as `const char *`, and `const` everything you only read.

## Generic containers with macros

C has no generics. The options are `void *` with an element size (like `qsort`: flexible, no type checking, an indirection per element) or macros that stamp out a type-specific version per element type:

```c
#include <stdio.h>
#include <stdlib.h>

#define DEFINE_PAIR(T, Name)                                       \
    typedef struct { T first, second; } Name;                      \
    static inline Name Name##_make(T a, T b) { return (Name){a, b}; } \
    static inline T Name##_max(Name p) { return p.first > p.second ? p.first : p.second; }

DEFINE_PAIR(int, IntPair)
DEFINE_PAIR(double, DoublePair)

int main(void) {
    IntPair ip = IntPair_make(3, 9);
    DoublePair dp = DoublePair_make(2.5, -1.0);
    printf("%d %.1f\n", IntPair_max(ip), DoublePair_max(dp));   // 9 2.5
    return 0;
}
```

This is template instantiation done by hand: the macro body is ordinary C with `T` substituted, and `##` builds the names. Each instantiation is fully typed and as fast as hand-written code. The downsides: errors point into a macro, debugging is awkward, and the body cannot contain `#` directives. Comments inside a multi-line macro must be `/* */`, since a `//` comment would swallow the line continuation. Libraries like `stb_ds.h` and the Linux kernel's `list.h` take this to its limit.

> **Performance:** macro-generated containers store elements inline (an `IntVec` is one contiguous `int` array) and their comparisons and copies are inlined, while the `void *` style pays a function-pointer call per comparison (`qsort` cannot inline your comparator) and often a pointer per element. For containers on a hot path, the typed version is usually noticeably faster.

## volatile, briefly

`volatile` tells the compiler that every read and write of the object is an observable side effect: it must not cache the value in a register or remove "redundant" accesses. Legitimate uses:

- memory-mapped hardware registers in embedded code;
- variables modified by a signal handler (`volatile sig_atomic_t stop;`);
- keeping a benchmark from optimizing away its own work.

`volatile` is **not** a threading tool: it gives no atomicity and no ordering between threads, unlike C#'s `volatile`, which has acquire/release semantics. For threads use `<stdatomic.h>` (`_Atomic int`, `atomic_fetch_add`) or a mutex.

Implement an opaque, growable stack of `int`. The "header" part is in the starter; callers (the tests) only see `typedef struct Stack Stack;` and the functions. You define `struct Stack` and the functions.

#include <stdlib.h>

/* ---- stack.h: what callers see ---- */
typedef struct Stack Stack;
Stack *stack_new(void);
void stack_free(Stack *s);
int stack_push(Stack *s, int v);
int stack_pop(Stack *s, int *out);
int stack_peek(const Stack *s, int *out);
size_t stack_size(const Stack *s);

/* ---- stack.c: private ---- */
struct Stack {
    int *items;
    size_t len, cap;
};

Stack *stack_new(void) {
    Stack *s = malloc(sizeof *s);
    if (!s) return NULL;
    s->items = NULL;
    s->len = s->cap = 0;
    return s;
}

void stack_free(Stack *s) {
    if (!s) return;
    free(s->items);
    free(s);
}

int stack_push(Stack *s, int v) {
    if (s->len == s->cap) {
        size_t ncap = s->cap ? s->cap * 2 : 8;
        int *p = realloc(s->items, ncap * sizeof *p);
        if (!p) return -1;
        s->items = p;
        s->cap = ncap;
    }
    s->items[s->len++] = v;
    return 0;
}

int stack_pop(Stack *s, int *out) {
    if (s->len == 0) return -1;
    *out = s->items[--s->len];
    return 0;
}

int stack_peek(const Stack *s, int *out) {
    if (s->len == 0) return -1;
    *out = s->items[s->len - 1];
    return 0;
}

size_t stack_size(const Stack *s) {
    return s->len;
}
--- hint
`struct Stack` needs a pointer to the items, a length and a capacity. `stack_new` allocates the struct; the item array can start as `NULL`, since `realloc(NULL, n)` acts like `malloc(n)`.
--- hint
Assign `realloc`'s result to a temporary so a failure does not lose the old array.

--- solution
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdlib.h>
#include <string.h>

typedef struct {
    unsigned char *base;
    size_t cap;
    size_t used;
} Arena;

bool arena_init(Arena *a, size_t cap) {
    a->base = malloc(cap);
    a->cap = a->base ? cap : 0;
    a->used = 0;
    return a->base != NULL;
}

void *arena_alloc(Arena *a, size_t size, size_t align) {
    uintptr_t start = (uintptr_t)(a->base + a->used);
    uintptr_t aligned = (start + (align - 1)) & ~(uintptr_t)(align - 1);
    size_t pad = (size_t)(aligned - start);
    size_t left = a->cap - a->used;
    if (pad > left || size > left - pad) return NULL;
    a->used += pad + size;
    return a->base + (a->used - size);
}

char *arena_strdup(Arena *a, const char *s) {
    size_t n = strlen(s) + 1;
    char *p = arena_alloc(a, n, 1);
    if (p) memcpy(p, s, n);
    return p;
}

size_t arena_mark(const Arena *a) {
    return a->used;
}

void arena_rewind(Arena *a, size_t mark) {
    if (mark <= a->used) a->used = mark;
}

void arena_reset(Arena *a) {
    a->used = 0;
}

void arena_destroy(Arena *a) {
    free(a->base);

#include <stdarg.h>
#include <stdlib.h>
#include <string.h>

long sum_ints(int count, ...) {
    va_list ap;
    va_start(ap, count);
    long sum = 0;
    for (int i = 0; i < count; i++) sum += va_arg(ap, int);
    va_end(ap);
    return sum;

char *concat_all(const char *first, ...) {
    va_list ap, ap2;
    va_start(ap, first);
    va_copy(ap2, ap);
    size_t total = 0;
    for (const char *s = first; s; s = va_arg(ap, const char *)) total += strlen(s);
    va_end(ap);

    if (!out) { va_end(ap2); return NULL; }
    char *w = out;
    for (const char *s = first; s; s = va_arg(ap2, const char *)) {
        size_t n = strlen(s);
        memcpy(w, s, n);
        w += n;
    }
    va_end(ap2);
    *w = '\0';
    return out;
}

=== exercise miniprintf
title: Your own snprintf
--- prompt
Implement `int mini_snprintf(char *buf, size_t cap, const char *fmt, ...)` **without** calling any `printf`-family function. It follows `snprintf`'s contract:

- It writes at most `cap - 1` characters plus a terminating `'\0'` (nothing at all if `cap` is 0, and then `buf` may be `NULL`).
- It returns the number of characters the full output *would* have had, so a return value `>= cap` means it was truncated.

Supported conversions: `%d` (`int`, including `INT_MIN`), `%u` (`unsigned`), `%x` (`unsigned`, lowercase hex), `%c`, `%s` (a `NULL` pointer prints `(null)`) and `%%`. Each may have a minimum field **width** (decimal digits) and a `-` flag for left alignment, padded with spaces: `%5d`, `%-8s`, `%3c`. Any other character after `%` is output as-is together with the `%` (`"%q"` prints `%q`).
--- starter
#include <stdarg.h>
#include <stddef.h>

int mini_snprintf(char *buf, size_t cap, const char *fmt, ...) {
    (void)fmt;
    if (cap > 0) buf[0] = '\0';
    return 0;
}
--- solution
#include <stdarg.h>
#include <stddef.h>
#include <string.h>

typedef struct {
    char *buf;
    size_t cap;
    size_t len;   /* characters produced so far, even past cap */
} Out;

static void put(Out *o, char c) {
    if (o->cap > 0 && o->len < o->cap - 1) o->buf[o->len] = c;
    o->len++;
}

static void put_padded(Out *o, const char *s, size_t n, int width, int left) {
    size_t pad = (width > 0 && (size_t)width > n) ? (size_t)width - n : 0;
    if (!left) for (size_t i = 0; i < pad; i++) put(o, ' ');
    for (size_t i = 0; i < n; i++) put(o, s[i]);
    if (left) for (size_t i = 0; i < pad; i++) put(o, ' ');
}

/* Writes the digits of v in the given base into the end of tmp; returns a pointer to the first. */
static char *utoa(unsigned v, unsigned base, char *end) {
    const char *digits = "0123456789abcdef";
    char *p = end;
    do {
        *--p = digits[v % base];
        v /= base;
    } while (v);
    return p;
}

int mini_snprintf(char *buf, size_t cap, const char *fmt, ...) {
    Out o = {buf, cap, 0};
    va_list ap;
    va_start(ap, fmt);
    for (const char *f = fmt; *f; f++) {
        if (*f != '%') { put(&o, *f); continue; }
        const char *start = f;
        f++;
        int left = 0, width = 0;
        if (*f == '-') { left = 1; f++; }
        while (*f >= '0' && *f <= '9') width = width * 10 + (*f++ - '0');
        char tmp[16];
        char *end = tmp + sizeof tmp;
        switch (*f) {
        case 'd': {
            int v = va_arg(ap, int);
            unsigned mag = v < 0 ? 0u - (unsigned)v : (unsigned)v;
            char *p = utoa(mag, 10, end);
            if (v < 0) *--p = '-';
            put_padded(&o, p, (size_t)(end - p), width, left);
            break;
        }
        case 'u': case 'x': {
            char *p = utoa(va_arg(ap, unsigned), *f == 'x' ? 16 : 10, end);
            put_padded(&o, p, (size_t)(end - p), width, left);
            break;
        }
        case 'c': {
            char c = (char)va_arg(ap, int);
            put_padded(&o, &c, 1, width, left);
            break;
        }
        case 's': {
            const char *s = va_arg(ap, const char *);
            if (!s) s = "(null)";
            put_padded(&o, s, strlen(s), width, left);
            break;
        }
        case '%':
            put(&o, '%');
            break;
        case '\0':
            for (const char *q = start; q < f; q++) put(&o, *q);
            f--;
            break;
        default:
            for (const char *q = start; q <= f; q++) put(&o, *q);
            break;
        }
    }
    va_end(ap);
    if (cap > 0) buf[o.len < cap ? o.len : cap - 1] = '\0';
    return (int)o.len;
}
--- hint
Route every output character through one helper that stores it only while there is room (`len < cap - 1`) but always increments the count. Then truncation and the return value fall out for free, and the terminator goes at `min(len, cap - 1)`.
--- hint
`INT_MIN` cannot be negated as an `int`. Convert to `unsigned` first: `0u - (unsigned)v` is the magnitude, computed with defined wrap-around.
--- hint
Generate digits backwards into the end of a small buffer (`digits[v % base]`, `v /= base`), then pad and copy. A `%c` argument arrives as an `int` (default promotions).
--- harness

--- solution
#include <stddef.h>
#include <string.h>
#include <limits.h>
#include <stdbool.h>

typedef enum { KV_OK = 0, KV_ESYNTAX, KV_EKEYLEN, KV_ERANGE } kv_status;

static bool is_space(char c) { return c == ' ' || c == '\t'; }
static bool is_alpha_(char c) { return (c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z') || c == '_'; }
static bool is_digit(char c) { return c >= '0' && c <= '9'; }

kv_status parse_kv(const char *line, char *key, size_t keycap, long *value) {
    const char *p = line;
    while (is_space(*p)) p++;
    if (!is_alpha_(*p)) return KV_ESYNTAX;
    const char *kstart = p;
    while (is_alpha_(*p) || is_digit(*p)) p++;
    size_t klen = (size_t)(p - kstart);
    while (is_space(*p)) p++;
    if (*p++ != '=') return KV_ESYNTAX;
    while (is_space(*p)) p++;
    bool neg = false;
    if (*p == '+' || *p == '-') neg = (*p++ == '-');
    if (!is_digit(*p)) return KV_ESYNTAX;
    bool overflow = false;
    long v = 0;
    while (is_digit(*p)) {
        int d = *p++ - '0';
        if (!overflow) {
            /* accumulate as a negative number: its range is one larger */
            if (v < (LONG_MIN + d) / 10) overflow = true;
            else v = v * 10 - d;
        }
    }
    while (is_space(*p)) p++;
    if (*p != '\0') return KV_ESYNTAX;
    if (klen + 1 > keycap) return KV_EKEYLEN;
    if (overflow || (!neg && v == LONG_MIN)) return KV_ERANGE;
    memcpy(key, kstart, klen);
    key[klen] = '\0';
    *value = neg ? v : -v;
    return KV_OK;
}

const char *kv_strerror(kv_status s) {
    switch (s) {
    case KV_OK: return "ok";
    case KV_ESYNTAX: return "syntax error";
    case KV_EKEYLEN: return "key too long";
    case KV_ERANGE: return "value out of range";
    }
    return "unknown error";
}
--- hint
Walk the string with a pointer through each part in order, returning `KV_ESYNTAX` at the first surprise. Remember where the key starts and how long it is, but do not copy it until everything has been validated.
--- hint
For the range check you can use `strtol` with `errno` on the digits, or accumulate digits yourself checking `v > (LONG_MAX - d) / 10` before each step. `LONG_MIN` has no positive counterpart, so either accumulate negatively or treat it specially.
--- hint
Syntax is checked for the whole line first, then key length, then range: `"k=99999999999999999999 x"` is a syntax error, not a range error.

    CHECK_INT(parse_kv("abcdefgh=1", key, sizeof key, &v), KV_EKEYLEN);
    CHECK_INT(parse_kv("toolongkey=99999999999999999999", key, sizeof key, &v), KV_EKEYLEN);

    CHECK_INT(parse_kv("a=-9223372036854775809", key, sizeof key, &v), KV_ERANGE);
    CHECK_INT(parse_kv("a=99999999999999999999999999", key, sizeof key, &v), KV_ERANGE);
    CHECK_STR(key, "keep");
    CHECK_INT(v, 77);
    CHECK_INT(parse_kv("x=1", key, 1, &v), KV_EKEYLEN);
    CHECK_INT(parse_kv("x=1", key, 2, &v), KV_OK);
    CHECK_STR(key, "x");

    CHECK_STR(kv_strerror(KV_OK), "ok");
    CHECK_STR(kv_strerror(KV_ESYNTAX), "syntax error");
    CHECK_STR(kv_strerror(KV_EKEYLEN), "key too long");
    CHECK_STR(kv_strerror(KV_ERANGE), "value out of range");
    CHECK_STR(kv_strerror((kv_status)99), "unknown error");
    return TEST_END();

=== exercise layout
title: Padding, alignment and static_assert
--- prompt
A particle system keeps 100000 of these structs in an array, so every wasted byte is wasted 100000 times and dilutes every cache line. Three small tasks about memory layout.

1. Reorder the members of `struct Particle` (keep the same names and types) so that `sizeof(struct Particle)` is 16 instead of 32, and add a `static_assert` that it is 16.
2. `size_t align_up(size_t n, size_t align)`: round `n` up to a multiple of `align`, a power of two. Use bit operations, no division or loops.
3. `size_t particle_padding(void)`: the number of padding bytes in `struct Particle`, computed from `sizeof` and the member sizes (so it reports `0` once the struct is tight, and would report 16 for the original order).
--- starter

#include <stddef.h>
#include <stdint.h>

struct Particle {
    char kind;
    double lifetime;
    char alive;
    int32_t id;
    int16_t frame;
};

    (void)align;
    return n;
}

    return 0;
}
--- solution
#include <assert.h>
#include <stddef.h>
#include <stdint.h>

struct Particle {
    double lifetime;
    int32_t id;
    int16_t frame;
    char kind;
    char alive;
};
static_assert(sizeof(struct Particle) == 16, "struct Particle should have no padding");

size_t align_up(size_t n, size_t align) {
    return (n + align - 1) & ~(align - 1);
}

size_t particle_padding(void) {
    struct Particle r;
    return sizeof r - (sizeof r.kind + sizeof r.lifetime + sizeof r.alive + sizeof r.id + sizeof r.frame);
}
--- hint
Sort members by alignment, largest first: `double` (8), `int32_t` (4), `int16_t` (2), then the two `char`s.
--- hint
`(n + align - 1) & ~(align - 1)`: adding `align - 1` pushes any partial block over the boundary, and the mask clears the low bits.
--- hint
`sizeof` works on an expression without evaluating it, so `sizeof r.id` is fine for an uninitialized `r`.
--- harness
#include <stddef.h>

int main(void) {
    CHECK_INT(sizeof(struct Particle), 16);
    struct Particle r = {0};
    r.kind = 'T'; r.alive = 1; r.lifetime = 9.5; r.id = 1234567; r.frame = 2024;
    CHECK_INT(r.kind, 'T');
    CHECK_DBL(r.lifetime, 9.5);
    CHECK_INT(r.id + r.frame + r.alive, 1234567 + 2024 + 1);
    CHECK_INT(offsetof(struct Particle, lifetime) % 8, 0);
    CHECK_INT(particle_padding(), 0);
    CHECK_INT(align_up(0, 8), 0);
    CHECK_INT(align_up(1, 8), 8);
    CHECK_INT(align_up(8, 8), 8);
    CHECK_INT(align_up(13, 4), 16);
    CHECK_INT(align_up(17, 16), 32);
    CHECK_INT(align_up(5, 1), 5);
    CHECK_INT(align_up(4097, 4096), 8192);
    return TEST_END();
}

What does declaring a parameter `int *restrict a` promise the compiler?
--- choice
That `a` is never NULL
--- choice
That the function will not modify `*a`
--- answer
That while the function runs, the memory reached through `a` is not accessed through any other pointer
--- choice
That `a` is aligned for SIMD instructions
--- explain
`restrict` is an aliasing promise: no other pointer touches the same object during the pointer's lifetime. The compiler can then keep values in registers and vectorize. Breaking the promise is undefined behavior and is not checked.
