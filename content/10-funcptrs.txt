## Functions have addresses

Compiled code lives in memory like everything else, so a function has an address and you can store it in a variable. A function pointer is C's `Func<>`/`Action<>`, minus everything a delegate carries besides the method: no captured target object, no multicast, no lambdas.

```c
#include <stdio.h>

int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }

int main(void) {
    int (*op)(int, int);         // op: pointer to function taking (int, int) returning int
    op = add;                    // a function name decays to its address (&add also works)
    printf("%d\n", op(3, 4));    // call through it: 7. (*op)(3, 4) is the same thing
    op = mul;
    printf("%d\n", op(3, 4));    // 12
    return 0;
}
```

The parentheses in `int (*op)(int, int)` matter: `int *op(int, int)` declares a *function* returning `int *`. Read declarations from the name outward: "`op` is a pointer (`*op`) to a function taking `(int, int)` returning `int`".

### typedef it

Raw function pointer types get unreadable fast, especially as parameters and return types. Name them:

```c
typedef int (*BinOp)(int, int);     // BinOp is "pointer to int(int, int)"

int apply(BinOp f, int a, int b) { return f(a, b); }

// Without the typedef, a function returning a BinOp looks like this:
int (*pick_raw(char c))(int, int);
// With it:
BinOp pick(char c);
```

Some codebases typedef the *function type* instead and write the star at use sites: `typedef int BinOpFn(int, int); BinOpFn *f;`. Both are fine; be consistent. The standard library's own `signal` is the classic monster: `void (*signal(int sig, void (*handler)(int)))(int);`

| C# | C |
|---|---|
| `Func<int, int, int> f = Add;` | `int (*f)(int, int) = add;` |
| `delegate int BinOp(int a, int b);` | `typedef int (*BinOp)(int, int);` |
| `f(1, 2)` / `f.Invoke(1, 2)` | `f(1, 2)` / `(*f)(1, 2)` |
| `f == null` | `f == NULL` (calling a NULL function pointer crashes) |
| lambda capturing locals | not possible: pass a `void *ctx` instead (below) |

A function pointer and a data pointer (`void *`) are not interchangeable in standard C. Don't store functions in `void *`; use a function pointer type (any one, cast back before calling) if you need a generic slot.

## Callbacks

Passing a function into another function is how C does strategy, events and iteration:

```c
#include <stdio.h>

typedef void (*IntVisitor)(int value, size_t index);

void for_each(const int *a, size_t n, IntVisitor visit) {
    for (size_t i = 0; i < n; i++) visit(a[i], i);
}

void print_item(int value, size_t index) {
    printf("[%zu] = %d\n", index, value);
}

int main(void) {
    int xs[] = {7, 1, 9};
    for_each(xs, 3, print_item);
    return 0;
}
```

## qsort: the standard library's callback showcase

```c
void qsort(void *base, size_t count, size_t size,
           int (*compar)(const void *, const void *));
```

`qsort` sorts *any* array: it only knows the start address, the element count, and the element size in bytes. To order two elements it calls your comparator with pointers to them, typed as `const void *` because it doesn't know their type. Your comparator casts back and returns negative, zero or positive, like `IComparer<T>.Compare`.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int cmp_int(const void *pa, const void *pb) {
    int a = *(const int *)pa, b = *(const int *)pb;
    return (a > b) - (a < b);          // -1, 0 or 1, never overflows
}

typedef struct { char name[16]; int age; } Person;

int cmp_person(const void *pa, const void *pb) {
    const Person *a = pa, *b = pb;     // void * converts implicitly in C (not in C++)
    if (a->age != b->age) return (a->age > b->age) - (a->age < b->age);
    return strcmp(a->name, b->name);   // tie-break: then by name
}

// Array of char *: each ELEMENT is a char *, so qsort hands us char **.
int cmp_str(const void *pa, const void *pb) {
    const char *a = *(const char *const *)pa;
    const char *b = *(const char *const *)pb;
    return strcmp(a, b);
}

int main(void) {
    int xs[] = {5, -2, 9, 0, -2};
    qsort(xs, 5, sizeof xs[0], cmp_int);
    for (int i = 0; i < 5; i++) printf("%d ", xs[i]);
    printf("\n");

    Person ps[] = {{"cy", 30}, {"al", 25}, {"bo", 30}};
    qsort(ps, 3, sizeof ps[0], cmp_person);
    for (int i = 0; i < 3; i++) printf("%s:%d ", ps[i].name, ps[i].age);
    printf("\n");

    const char *words[] = {"pear", "apple", "fig"};
    qsort(words, 3, sizeof words[0], cmp_str);
    for (int i = 0; i < 3; i++) printf("%s ", words[i]);
    printf("\n");
    return 0;
}
```

Three classic bugs:

1. **`return a - b;`** It's in a thousand tutorials and it's wrong. If `a = INT_MIN` and `b = 1`, the subtraction overflows `int`: undefined behavior, and in practice it wraps to `INT_MAX`, a *positive* answer for a < b. The sort silently comes out wrong for inputs near the extremes. Use `(a > b) - (a < b)`: each comparison is 0 or 1, so the result is -1, 0 or 1.
2. **Sorting `char *` with `strcmp` directly.** For an array of strings the elements are `char *`, so the comparator receives `char **` disguised as `const void *`. Passing those straight to `strcmp` compares the bytes of the pointers themselves. Dereference once first, as `cmp_str` does. (For `char names[10][32]`, the elements *are* the char arrays, so there you pass the pointers straight to `strcmp`.)
3. **Casting a comparator for doubles to `int`.** `return (int)(a - b);` makes 0.3 and 0.1 "equal". Use the comparison idiom again.

`qsort` is not guaranteed stable (equal elements may be reordered); `List<T>.Sort` isn't either, but LINQ's `OrderBy` is. If you need stability, tie-break on a secondary key or the original index.

In a game, the classic `qsort` job is **draw order**: sort sprites by layer, then by y (things lower on screen drawn later, so they overlap correctly), then by id so the order is deterministic and sprites with equal keys don't flicker between frames.

> **Performance:** `qsort` calls your comparator through a pointer O(n log n) times, and the compiler can't inline it, so it's maybe 2-3x slower than a hand-specialized sort. That's fine for thousands of sprites per frame. What's not fine: sorting with an O(n²) algorithm (bubble/insertion sort "because it's short"), or comparing expensive things (re-hashing strings, recomputing distances) inside the comparator. Precompute a sort key per element once, then sort on the key. If the data is nearly sorted from the last frame, insertion sort *is* fast, but measure first.

## bsearch

```c
void *bsearch(const void *key, const void *base, size_t count, size_t size,
              int (*compar)(const void *key, const void *elem));
```

Binary search over a sorted array. It returns a pointer to *a* matching element (not necessarily the first of several equal ones) or `NULL`. The comparator's first argument is always the key you passed, which need not have the element type: look up a struct by its name by passing the name as the key.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct { const char *sym; int number; } Element;

// key is a const char *, element is an Element
int cmp_key_elem(const void *key, const void *elem) {
    return strcmp(key, ((const Element *)elem)->sym);
}

int main(void) {
    static const Element table[] = {      // must be sorted by the same order
        {"C", 6}, {"Fe", 26}, {"H", 1}, {"He", 2}, {"O", 8}, {"U", 92},
    };
    size_t n = sizeof table / sizeof table[0];
    const char *queries[] = {"Fe", "U", "Xx"};
    for (int i = 0; i < 3; i++) {
        const Element *e = bsearch(queries[i], table, n, sizeof table[0], cmp_key_elem);
        if (e) printf("%s = %d (index %td)\n", e->sym, e->number, e - table);
        else   printf("%s not found\n", queries[i]);
    }
    return 0;
}
```

`e - table` is pointer subtraction: the index. Its type is `ptrdiff_t`, printed with `%td`.

## void * generics

`qsort` shows the pattern for generic code in C: pass `void *` plus an element size, move bytes with `memcpy`, and let a callback interpret them. Here is a type-agnostic swap and a generic "find the max" that works for any element type:

```c
#include <stdio.h>
#include <string.h>

void swap_bytes(void *a, void *b, size_t size) {
    unsigned char tmp[64];                    // fine for small elements
    memcpy(tmp, a, size);
    memcpy(a, b, size);
    memcpy(b, tmp, size);
}

const void *max_elem(const void *base, size_t n, size_t size,
                     int (*cmp)(const void *, const void *)) {
    const unsigned char *p = base, *best = n ? p : NULL;   // char * so we can step by bytes
    for (size_t i = 1; i < n; i++)
        if (cmp(p + i * size, best) > 0) best = p + i * size;
    return best;
}

int cmp_double(const void *a, const void *b) {
    double x = *(const double *)a, y = *(const double *)b;
    return (x > y) - (x < y);
}

int main(void) {
    double ds[] = {2.5, 9.75, -1.0};
    const double *m = max_elem(ds, 3, sizeof ds[0], cmp_double);
    printf("max %.2f\n", *m);
    swap_bytes(&ds[0], &ds[2], sizeof ds[0]);
    printf("%.1f %.1f\n", ds[0], ds[2]);
    return 0;
}
```

You can't do arithmetic on `void *` in standard C (gcc allows it as an extension); convert to `unsigned char *` and multiply indices by the element size. What you lose compared to C# generics is type checking: nothing stops you passing an `int` array with a double comparator. `List<T>` knows `T`; your `Vec` only knows "8 bytes".

## map, filter, reduce

LINQ's `Select`, `Where` and `Aggregate` are three loops with a callback. In C they take the output buffer from the caller, since there's no GC to hand back a new sequence:

```c
#include <stdio.h>

typedef int  (*MapFn)(int);
typedef int  (*PredFn)(int);
typedef long (*ReduceFn)(long acc, int x);

void map(int *a, size_t n, MapFn f)             { for (size_t i = 0; i < n; i++) a[i] = f(a[i]); }

size_t filter(const int *in, size_t n, int *out, PredFn keep) {
    size_t k = 0;
    for (size_t i = 0; i < n; i++) if (keep(in[i])) out[k++] = in[i];
    return k;                                    // how many were kept
}

long reduce(const int *a, size_t n, long init, ReduceFn f) {
    for (size_t i = 0; i < n; i++) init = f(init, a[i]);
    return init;
}

int square(int x)        { return x * x; }
int is_odd(int x)        { return x % 2 != 0; }
long sum(long acc, int x) { return acc + x; }

int main(void) {
    int xs[] = {1, 2, 3, 4, 5, 6};
    int odd[6];
    size_t k = filter(xs, 6, odd, is_odd);       // 1 3 5
    map(odd, k, square);                         // 1 9 25
    printf("%ld\n", reduce(odd, k, 0, sum));     // 35
    return 0;
}
```

## Closures don't exist: pass a context pointer

In C# you'd write `xs.Where(x => x > threshold)`. The lambda *captures* `threshold`: the compiler generates a hidden class holding it, and the delegate stores both a method pointer and a reference to that object. C function pointers are just the method pointer, so there's nowhere to put `threshold`.

The C idiom does what the C# compiler does by hand: the callback takes an extra `void *ctx` argument, and whoever registers the callback passes a pointer to whatever state it needs. The library just carries the pointer through without looking at it.

```c
#include <stdio.h>

typedef int (*Pred)(int x, void *ctx);

size_t count_if(const int *a, size_t n, Pred p, void *ctx) {
    size_t c = 0;
    for (size_t i = 0; i < n; i++) if (p(a[i], ctx)) c++;
    return c;
}

int greater_than(int x, void *ctx) {
    int threshold = *(int *)ctx;
    return x > threshold;
}

typedef struct { int lo, hi; long calls; } Range;   // several captured values: use a struct

int in_range(int x, void *ctx) {
    Range *r = ctx;
    r->calls++;                    // the callback can also mutate captured state
    return x >= r->lo && x <= r->hi;
}

int main(void) {
    int xs[] = {4, 8, 15, 16, 23, 42};
    int t = 15;
    printf("%zu\n", count_if(xs, 6, greater_than, &t));         // 3
    Range r = {5, 20, 0};
    size_t n = count_if(xs, 6, in_range, &r);   // call first: argument order is unspecified
    printf("%zu (calls=%ld)\n", n, r.calls);    // 3 (calls=6)
    return 0;
}
```

> **Performance:** A C# lambda that captures variables allocates a closure object (and often a delegate) on the heap; doing that inside `Update()` creates garbage every frame. The C pattern allocates nothing: the context is usually a pointer to a struct that already exists on the stack or in your game state.

Every serious C callback API has this parameter: `pthread_create`'s `void *arg`, GLib's `gpointer user_data`, the `void *` in event libraries. `qsort` notably lacks it, which is why sorting by a runtime-chosen key forces a global variable (or the non-portable `qsort_r`). When you design an API that takes a callback, always add the `void *ctx`.

Watch the lifetime: `ctx` usually points at a local. That's fine while the call is running, but if the callback is *stored* and called later (an event handler), the local may be gone. C# closures keep captured variables alive; C doesn't.

## Dispatch tables

A `switch` on a command name becomes a table of `{name, function}` pairs. Adding a command is adding a row:

```c
#include <stdio.h>
#include <string.h>

typedef double (*UnaryFn)(double);

static double twice(double x)  { return 2 * x; }
static double halve(double x)  { return x / 2; }
static double negate(double x) { return -x; }

static const struct { const char *name; UnaryFn fn; } COMMANDS[] = {
    {"twice", twice}, {"halve", halve}, {"negate", negate},
};

static UnaryFn lookup(const char *name) {
    for (size_t i = 0; i < sizeof COMMANDS / sizeof COMMANDS[0]; i++)
        if (strcmp(COMMANDS[i].name, name) == 0) return COMMANDS[i].fn;
    return NULL;
}

int main(void) {
    const char *prog[] = {"twice", "twice", "negate", "halve", "explode"};
    double x = 5;
    for (int i = 0; i < 5; i++) {
        UnaryFn f = lookup(prog[i]);
        if (!f) { printf("unknown: %s\n", prog[i]); continue; }
        x = f(x);
        printf("%s -> %g\n", prog[i], x);
    }
    return 0;
}
```

When the keys are small integers (opcodes, enum values, states in a state machine) skip the search and index directly: `handlers[opcode](vm)`. That's the core loop of many interpreters and emulators, and of game state machines: `states[game.state].update(&game, dt)` with one row per state (title, playing, paused, game over), each holding `enter`, `update`, `render` and `exit` pointers.

> **Performance:** Look commands up by name *once* (when a key binding or script is loaded) and store the function pointer or index. `strcmp` through a table on every keypress is harmless; doing it per entity per frame is not.

The same pattern with a list of handlers per event type gives you an **event bus**: systems subscribe a `(function, ctx)` pair to "enemy died" or "player damaged", and the code that detects the event calls every subscriber without knowing who they are. An exercise below builds one with fixed-size arrays so emitting never allocates.

## Interfaces and virtual methods: the vtable

A C# interface call `shape.Area()` works like this under the hood: each object starts with a pointer to its type's method table, and the call loads the function pointer from that table. You can build exactly that:

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct Shape Shape;

typedef struct {                                 // the "interface": one per type, shared
    const char *name;
    double (*area)(const Shape *self);
    void (*destroy)(Shape *self);
} ShapeVtbl;

struct Shape { const ShapeVtbl *vt; };           // the "base class": just the vtable pointer

typedef struct { Shape base; double r; } Circle;     // base FIRST, so Circle * -> Shape * is valid
typedef struct { Shape base; double w, h; } Rect;

static double circle_area(const Shape *s) {
    const Circle *c = (const Circle *)s;         // the "downcast"
    return 3.14159265358979 * c->r * c->r;
}
static double rect_area(const Shape *s) {
    const Rect *r = (const Rect *)s;
    return r->w * r->h;
}
static void shape_free(Shape *s) { free(s); }

static const ShapeVtbl CIRCLE_VT = {"circle", circle_area, shape_free};
static const ShapeVtbl RECT_VT   = {"rect",   rect_area,   shape_free};

Shape *circle_new(double r) {
    Circle *c = malloc(sizeof *c);
    c->base.vt = &CIRCLE_VT;
    c->r = r;
    return &c->base;
}

Shape *rect_new(double w, double h) {
    Rect *r = malloc(sizeof *r);
    r->base.vt = &RECT_VT;
    r->w = w;
    r->h = h;
    return &r->base;
}

int main(void) {
    Shape *shapes[] = {circle_new(1), rect_new(2, 3), circle_new(0.5)};
    for (int i = 0; i < 3; i++) {
        Shape *s = shapes[i];
        printf("%-6s %.3f\n", s->vt->name, s->vt->area(s));   // virtual call
        s->vt->destroy(s);
    }
    return 0;
}
```

Key points:

- The vtable is `static const`, one per type, shared by all instances (like the CLR's method table). Each object pays one pointer.
- Putting `Shape base` as the **first member** means a `Circle *` and its `&c->base` have the same address, so converting between them with a cast is valid C. That's single inheritance.
- `self` is explicit. C#'s `this` is the same hidden first argument.
- `destroy` in the vtable is the virtual destructor: callers free shapes without knowing their concrete type.
- The Linux kernel (`struct file_operations`), SQLite (`sqlite3_vfs`) and COM all use this pattern.

> **Performance:** Vtables are the right tool for things you have a few of and call occasionally: game states, asset loaders, audio backends, UI widgets. They're the wrong tool for the hot loop over 10,000 entities. An array of `Shape *`, each separately `malloc`'d and updated through a virtual call, costs a cache miss to reach each object, another to reach its vtable, and an unpredictable indirect branch, and it blocks inlining and vectorization. The data-oriented alternative: keep one plain array per type (`Circle circles[N]; Rect rects[M];`) and run one tight loop per array. Same behavior, no indirection, often several times faster. This is the core idea behind ECS engines.

=== exercise comparators
title: Comparators that don't overflow
--- prompt
Write three `qsort` comparators for `int` arrays:

- `int cmp_int_asc(const void *a, const void *b)`: ascending.
- `int cmp_int_desc(const void *a, const void *b)`: descending.
- `int cmp_abs(const void *a, const void *b)`: by absolute value ascending; when the absolute values are equal, the negative number first. Note that `abs(INT_MIN)` overflows.

They must work for the full `int` range, including `INT_MIN` and `INT_MAX`. The starter uses the subtraction trick, which doesn't.
--- starter
#include <stdlib.h>
#include <limits.h>

int cmp_int_asc(const void *a, const void *b) {
    return *(const int *)a - *(const int *)b;
}

int cmp_int_desc(const void *a, const void *b) {
    return *(const int *)b - *(const int *)a;
}

int cmp_abs(const void *a, const void *b) {
    return abs(*(const int *)a) - abs(*(const int *)b);
}
--- solution
#include <stdlib.h>
#include <limits.h>

int cmp_int_asc(const void *a, const void *b) {
    int x = *(const int *)a, y = *(const int *)b;
    return (x > y) - (x < y);
}

int cmp_int_desc(const void *a, const void *b) {
    return cmp_int_asc(b, a);
}

int cmp_abs(const void *a, const void *b) {
    long long x = *(const int *)a, y = *(const int *)b;
    long long ax = x < 0 ? -x : x, ay = y < 0 ? -y : y;
    if (ax != ay) return (ax > ay) - (ax < ay);
    return (x > y) - (x < y);
}
--- hint
`(x > y) - (x < y)` is -1, 0 or 1 and can't overflow.
--- hint
Descending is ascending with the arguments swapped.
--- hint
For `cmp_abs`, widen to `long long` before negating so `-INT_MIN` is representable.
--- harness
#include <limits.h>
static int t_is(const int *a, const int *b, size_t n) {
    for (size_t i = 0; i < n; i++) if (a[i] != b[i]) return 0;
    return 1;
}
static int t_sign(int x) { return (x > 0) - (x < 0); }

int main(void) {
    int one = 1, mn = INT_MIN, mx = INT_MAX, neg = -1, z = 0;
    CHECK_INT(t_sign(cmp_int_asc(&mn, &one)), -1);
    CHECK_INT(t_sign(cmp_int_asc(&mx, &neg)), 1);
    CHECK_INT(t_sign(cmp_int_asc(&z, &z)), 0);
    CHECK_INT(t_sign(cmp_int_desc(&mn, &mx)), 1);
    CHECK_INT(t_sign(cmp_int_desc(&one, &z)), -1);

    int a[] = {3, INT_MIN, 0, INT_MAX, -7, 3, -1, INT_MAX - 1, INT_MIN + 1};
    int asc[] = {INT_MIN, INT_MIN + 1, -7, -1, 0, 3, 3, INT_MAX - 1, INT_MAX};
    int desc[] = {INT_MAX, INT_MAX - 1, 3, 3, 0, -1, -7, INT_MIN + 1, INT_MIN};
    qsort(a, 9, sizeof a[0], cmp_int_asc);
    CHECK(t_is(a, asc, 9));
    qsort(a, 9, sizeof a[0], cmp_int_desc);
    CHECK(t_is(a, desc, 9));

    int b[] = {5, -3, 3, INT_MIN, -5, 0, INT_MAX, 1, -INT_MAX};
    int babs[] = {0, 1, -3, 3, -5, 5, -INT_MAX, INT_MAX, INT_MIN};
    qsort(b, 9, sizeof b[0], cmp_abs);
    CHECK(t_is(b, babs, 9));
    CHECK_INT(t_sign(cmp_abs(&mn, &mx)), 1);
    CHECK_INT(t_sign(cmp_abs(&neg, &one)), -1);
    CHECK_INT(t_sign(cmp_abs(&one, &one)), 0);
    return TEST_END();
}

title: Sorting records and strings
--- prompt
Use `qsort` with your own comparators to write:

- `void sort_people(Person *p, size_t n)`: by `age` ascending, then by `name` ascending (`strcmp` order) for equal ages.

--- solution
#include <stdlib.h>
#include <string.h>

typedef struct {
    char name[32];
    int age;
    double score;
} Person;

static int cmp_age_name(const void *pa, const void *pb) {
    const Person *a = pa, *b = pb;
    if (a->age != b->age) return (a->age > b->age) - (a->age < b->age);
    return strcmp(a->name, b->name);
}

static int cmp_score_desc(const void *pa, const void *pb) {
    const Person *a = pa, *b = pb;
    return (a->score < b->score) - (a->score > b->score);
}

static int cmp_word(const void *pa, const void *pb) {
    return strcmp(*(const char *const *)pa, *(const char *const *)pb);
}

void sort_people(Person *p, size_t n) {
    qsort(p, n, sizeof *p, cmp_age_name);
}

void sort_by_score_desc(Person *p, size_t n) {
    qsort(p, n, sizeof *p, cmp_score_desc);
}

void sort_words(const char **words, size_t n) {
    qsort(words, n, sizeof *words, cmp_word);
}
--- hint
Inside a `Person` comparator, `const Person *a = pa;` converts from `const void *` without a cast.
--- hint
For the words, each element is a `const char *`, so the comparator gets a pointer to one: `*(const char *const *)pa` is the string.
--- harness

typedef struct { int layer; float y; int id; } Sprite;

static int cmp_sprite(const void *pa, const void *pb) {
    const Sprite *a = pa, *b = pb;
    if (a->layer != b->layer) return (a->layer > b->layer) - (a->layer < b->layer);
    if (a->y != b->y) return (a->y > b->y) - (a->y < b->y);

}

    qsort(s, n, sizeof *s, cmp_sprite);
}

    for (size_t i = 0; i < n; i++) c += s[i].y >= top && s[i].y <= bottom;
    return c;
}

title: An event bus without allocation
--- prompt
Write a publish/subscribe event bus for a game, the C version of C# `event`s. Systems subscribe a handler function plus a context pointer to an event type; emitting an event calls that type's handlers in subscription order. Everything lives in fixed-size arrays inside `Bus`, so subscribing and emitting never allocate.

```c
typedef struct { int type; int a, b; } Event;   // e.g. DAMAGE: a = target, b = amount
typedef void (*Handler)(const Event *e, void *ctx);
```

- `void bus_init(Bus *b)`: no subscribers.
- `int bus_subscribe(Bus *b, int type, Handler fn, void *ctx)`: 0 on success; -1 if `type` is outside `0..MAX_TYPES-1` or that type already has `MAX_HANDLERS` subscribers.
- `int bus_unsubscribe(Bus *b, int type, Handler fn, void *ctx)`: remove the first subscription with exactly this `fn` **and** `ctx`, keeping the others in order; return 1 if one was removed, else 0.
- `int bus_emit(const Bus *b, const Event *e)`: call each handler subscribed to `e->type` as `fn(e, ctx)`, in order; return how many were called (0 for an out-of-range type).

--- solution
#include <stddef.h>

#define MAX_TYPES 16
#define MAX_HANDLERS 8

typedef struct { int type; int a, b; } Event;
typedef void (*Handler)(const Event *e, void *ctx);

typedef struct { Handler fn; void *ctx; } Sub;
typedef struct {
    Sub subs[MAX_TYPES][MAX_HANDLERS];
    int count[MAX_TYPES];
} Bus;

void bus_init(Bus *b) {
    for (int t = 0; t < MAX_TYPES; t++) b->count[t] = 0;
}

int bus_subscribe(Bus *b, int type, Handler fn, void *ctx) {
    if (type < 0 || type >= MAX_TYPES || b->count[type] == MAX_HANDLERS) return -1;
    b->subs[type][b->count[type]++] = (Sub){fn, ctx};
    return 0;
}

int bus_unsubscribe(Bus *b, int type, Handler fn, void *ctx) {
    if (type < 0 || type >= MAX_TYPES) return 0;
    Sub *s = b->subs[type];
    for (int i = 0; i < b->count[type]; i++) {
        if (s[i].fn == fn && s[i].ctx == ctx) {
            for (int j = i + 1; j < b->count[type]; j++) s[j - 1] = s[j];
            b->count[type]--;
            return 1;
        }
    }
    return 0;
}

int bus_emit(const Bus *b, const Event *e) {
    if (e->type < 0 || e->type >= MAX_TYPES) return 0;
    int n = b->count[e->type];
    for (int i = 0; i < n; i++) b->subs[e->type][i].fn(e, b->subs[e->type][i].ctx);
    return n;
}
--- hint
Each event type has its own small array of `{fn, ctx}` pairs and a count. Subscribing appends; emitting loops.
--- hint
Function pointers can be compared with `==`. Unsubscribing shifts the later entries down by one to keep the order (the arrays are tiny, so that's fine here).

typedef int  (*MapFn)(int x, void *ctx);
typedef int  (*PredFn)(int x, void *ctx);
typedef long (*FoldFn)(long acc, int x, void *ctx);

void map_ints(int *a, size_t n, MapFn f, void *ctx) {
    for (size_t i = 0; i < n; i++) a[i] = f(a[i], ctx);
}

size_t filter_ints(const int *in, size_t n, int *out, PredFn keep, void *ctx) {
    size_t k = 0;
    for (size_t i = 0; i < n; i++)
        if (keep(in[i], ctx)) out[k++] = in[i];
    return k;
}

    for (size_t i = 0; i < n; i++) init = f(init, a[i], ctx);
    return init;
}

    for (size_t i = 0; i < n; i++)

#include <stdlib.h>
#include <string.h>

typedef struct {
    unsigned char *data;
    size_t elem_size, len, cap;
} Vec;

void vec_init(Vec *v, size_t elem_size) {
    v->data = NULL;
    v->elem_size = elem_size;
    v->len = v->cap = 0;
}

void *vec_push(Vec *v, const void *elem) {
    if (v->len == v->cap) {
        size_t ncap = v->cap ? v->cap * 2 : 4;
        unsigned char *p = realloc(v->data, ncap * v->elem_size);
        if (!p) return NULL;
        v->data = p;
        v->cap = ncap;
    }
    unsigned char *slot = v->data + v->len * v->elem_size;
    memcpy(slot, elem, v->elem_size);
    v->len++;
    return slot;
}

void *vec_at(const Vec *v, size_t i) {
    return i < v->len ? v->data + i * v->elem_size : NULL;
}

void vec_remove(Vec *v, size_t i) {
    if (i >= v->len) return;
    unsigned char *p = v->data + i * v->elem_size;
    memmove(p, p + v->elem_size, (v->len - i - 1) * v->elem_size);
    v->len--;
}

void *vec_find(const Vec *v, const void *key, int (*eq)(const void *key, const void *elem)) {
    for (size_t i = 0; i < v->len; i++) {
        unsigned char *p = v->data + i * v->elem_size;
        if (eq(key, p)) return p;
    }
    return NULL;
}

void vec_free(Vec *v) {
    free(v->data);
    v->data = NULL;
    v->len = v->cap = 0;
}
--- hint

=== exercise dispatch
title: Command dispatch table
--- prompt
Write a calculator that reads commands from stdin, one per line, and prints one result line per command. Implement it with a **table** of `{name, arity, function}` entries, not a chain of `if`/`strcmp`.

| Command | Result |
|---|---|
| `add a b` | a + b |
| `sub a b` | a - b |
| `mul a b` | a * b |
| `div a b` | a / b (C division) |
| `mod a b` | a % b |
| `neg a` | -a |
| `sq a` | a * a |

All numbers are integers that fit in `long`, and results fit too.

- Blank lines produce no output.
- An unknown command prints `error: unknown command NAME`.
- A wrong number of arguments prints `error: NAME takes N argument(s)` with `N` the expected count, e.g. `error: neg takes 1 argument(s)`.
- `div` or `mod` by zero prints `error: division by zero`.

A clean way: each function has the signature `int fn(const long *args, long *result)` and returns 0 on success or nonzero for an error.
--- starter
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    char line[256];
    while (fgets(line, sizeof line, stdin)) {
        // split into a name and up to a few numbers, look the name up, call it
    }
    return 0;
}
--- solution
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef int (*CmdFn)(const long *args, long *result);

static int c_add(const long *a, long *r) { *r = a[0] + a[1]; return 0; }
static int c_sub(const long *a, long *r) { *r = a[0] - a[1]; return 0; }
static int c_mul(const long *a, long *r) { *r = a[0] * a[1]; return 0; }
static int c_div(const long *a, long *r) { if (a[1] == 0) return 1; *r = a[0] / a[1]; return 0; }
static int c_mod(const long *a, long *r) { if (a[1] == 0) return 1; *r = a[0] % a[1]; return 0; }
static int c_neg(const long *a, long *r) { *r = -a[0]; return 0; }
static int c_sq(const long *a, long *r)  { *r = a[0] * a[0]; return 0; }

static const struct { const char *name; int arity; CmdFn fn; } CMDS[] = {
    {"add", 2, c_add}, {"sub", 2, c_sub}, {"mul", 2, c_mul}, {"div", 2, c_div},
    {"mod", 2, c_mod}, {"neg", 1, c_neg}, {"sq", 1, c_sq},
};

int main(void) {
    char line[256];
    while (fgets(line, sizeof line, stdin)) {
        char name[32];
        int used;
        if (sscanf(line, "%31s%n", name, &used) != 1) continue;
        long args[8];
        int nargs = 0;
        char *p = line + used, *end;
        for (;;) {
            long v = strtol(p, &end, 10);
            if (end == p) break;
            if (nargs < 8) args[nargs] = v;
            nargs++;
            p = end;
        }
        int found = 0;
        for (size_t i = 0; i < sizeof CMDS / sizeof CMDS[0]; i++) {
            if (strcmp(CMDS[i].name, name) != 0) continue;
            found = 1;
            long r;
            if (nargs != CMDS[i].arity)
                printf("error: %s takes %d argument(s)\n", name, CMDS[i].arity);
            else if (CMDS[i].fn(args, &r) != 0)
                printf("error: division by zero\n");
            else
                printf("%ld\n", r);
            break;
        }
        if (!found) printf("error: unknown command %s\n", name);
    }
    return 0;
}
--- hint
`sscanf(line, "%31s%n", name, &used)` reads the name and stores in `used` how many characters were consumed, so the numbers start at `line + used`. A blank line makes `sscanf` return `EOF` (or 0).
--- hint
Count the numbers with a `strtol` loop: when `end == p`, there was no number left.
--- hint
The table can be `static const struct { const char *name; int arity; CmdFn fn; } CMDS[] = {...};` and a loop over `sizeof CMDS / sizeof CMDS[0]` entries.

#include <stdlib.h>
#include <math.h>

typedef struct Shape Shape;

typedef struct {
    const char *name;
    double (*area)(const Shape *self);
    double (*perimeter)(const Shape *self);
    void (*scale)(Shape *self, double k);
    void (*destroy)(Shape *self);
} ShapeVtbl;

struct Shape { const ShapeVtbl *vt; };

typedef struct { Shape base; double r; } Circle;
typedef struct { Shape base; double w, h; } Rect;

static const double PI = 3.14159265358979323846;

static double circle_area(const Shape *s) { const Circle *c = (const Circle *)s; return PI * c->r * c->r; }
static double circle_perim(const Shape *s) { const Circle *c = (const Circle *)s; return 2 * PI * c->r; }
static void circle_scale(Shape *s, double k) { ((Circle *)s)->r *= k; }

static double rect_area(const Shape *s) { const Rect *r = (const Rect *)s; return r->w * r->h; }
static double rect_perim(const Shape *s) { const Rect *r = (const Rect *)s; return 2 * (r->w + r->h); }
static void rect_scale(Shape *s, double k) { Rect *r = (Rect *)s; r->w *= k; r->h *= k; }

static void shape_destroy(Shape *s) { free(s); }

static const ShapeVtbl CIRCLE_VT = {"circle", circle_area, circle_perim, circle_scale, shape_destroy};
static const ShapeVtbl RECT_VT = {"rect", rect_area, rect_perim, rect_scale, shape_destroy};

Shape *circle_new(double r) {
    Circle *c = malloc(sizeof *c);
    if (!c) return NULL;
    c->base.vt = &CIRCLE_VT;
    c->r = r;
    return &c->base;
}

Shape *rect_new(double w, double h) {
    Rect *r = malloc(sizeof *r);
    if (!r) return NULL;
    r->base.vt = &RECT_VT;
    r->w = w;
    r->h = h;
    return &r->base;
}

double total_area(Shape *const *shapes, size_t n) {
    double sum = 0;
    for (size_t i = 0; i < n; i++) sum += shapes[i]->vt->area(shapes[i]);
    return sum;
}

Shape *largest(Shape *const *shapes, size_t n) {
    Shape *best = NULL;
    double best_area = 0;
    for (size_t i = 0; i < n; i++) {
        double a = shapes[i]->vt->area(shapes[i]);
        if (!best || a > best_area) { best = shapes[i]; best_area = a; }
    }
    return best;
}
--- hint
Because `base` is the first member, `(Circle *)s` is valid inside the circle's functions, and `&c->base` (or `(Shape *)c`) is what the constructor returns.
--- hint
Declare the vtables as `static const ShapeVtbl CIRCLE_VT = {"circle", circle_area, ...};` after the functions they point to, and point every new object's `base.vt` at it.

--- solution
#include <stdlib.h>
#include <string.h>

typedef struct { char code[4]; const char *name; } Country;

void *lower_bound(const void *key, const void *base, size_t n, size_t size,
                  int (*cmp)(const void *key, const void *elem)) {
    const unsigned char *p = base;
    size_t lo = 0, hi = n;                 // answer is in [lo, hi]
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (cmp(key, p + mid * size) > 0) lo = mid + 1;
        else hi = mid;
    }
    return (void *)(p + lo * size);
}

static int cmp_country(const void *a, const void *b) {
    return strcmp(((const Country *)a)->code, ((const Country *)b)->code);
}

static int cmp_code_key(const void *key, const void *elem) {
    return strcmp(key, ((const Country *)elem)->code);
}

void sort_codes(Country *c, size_t n) {
    qsort(c, n, sizeof *c, cmp_country);
}

const Country *find_code(const Country *c, size_t n, const char *code) {
    return bsearch(code, c, n, sizeof *c, cmp_code_key);
}
--- hint
Keep a half-open range `[lo, hi)` of candidate indices. If the middle element is less than the key (`cmp(key, mid) > 0`), the answer is after it: `lo = mid + 1`. Otherwise it's at `mid` or before: `hi = mid`. Stop when `lo == hi`.
--- hint
Compute `mid` as `lo + (hi - lo) / 2`, and address elements as `(const unsigned char *)base + mid * size`.
--- hint
For `find_code`, the `bsearch` comparator's first argument is the key you passed (a `const char *`), the second is a `Country`. They are different types.
